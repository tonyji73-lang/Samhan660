# 흉년 선택 이벤트 v1

기반 브랜치: `feature/event-choice-framework-v1`, 기준 HEAD `310f8e1`.
전달 ZIP의 `VSCODE_HANDOFF_KO.md`와 `domestic_crop_failure_event_v1.json`을
기준으로 구현했다. 이벤트는 기존 단일 카탈로그에 통합했고 WebP만 설치했다.
PNG 원본, 추가 Scene/Autoload, 테스트 자원 지급 버튼은 추가하지 않았다.

## 판정과 정산

- `crop_failure.gd`: 9월 플레이어 영지만 판정한다. 확률은
  `clamp(12% - 농업 × 0.04%p - 치안 × 0.04%p, 4%, 12%)`.
- SHA256 입력은 `crop_failure:v1|시작시나리오ID|연도|영지ID`.
  앞 8자리 16진수를 10000으로 나눈 나머지와 basis-point 확률을 비교한다.
  `Korea35Data.PROVINCE_IDS` 순서의 첫 성공 영지만 발생한다.
- 기존 수확(징수율 45%, 9월 70%, 10월 30%) 및 풍년 판정을 그대로 수행하고,
  그 해 풍년 영지를 제외한 뒤 해당 영지 9월 수확의 30%를 반올림해 차감한다.
  이후 기존 병력 소비·저장 손실·생산·치안 회복·AI·계절 정산 순서를 유지한다.
- 턴 정산을 끝낸 뒤 기존 풍년 연출 다음에 흉년 연출을 예약한다.
  피해와 선택 결과는 각각 캠페인에서 동기적으로 한 번 확정한다.
- 구휼: 도시 군량 -800 / 치안 +8, 재고 800 이상 필요.
  세금 유지: 군량 변화 없음 / 치안 -6.
  강제 징발: 군량 +500 / 치안 -12.
  군량 하한 0, 치안 범위 0~100. 결과에는 상한/하한을 적용한 실제 변화량을 표시한다.
- 9월 AI 정산 중 대상 도시가 점령되면 정책 선택만 취소 기록한다.
  이미 확정한 수확 피해는 유지하고 새 소유자의 자원을 변경하지 않는다.

## 공통 선택 UI와 저장

`EventPresentation.play_choice()`는 카탈로그의 `requires_choice` 및 `choice`
단계를 사용한다. 화면은 `campaign.get_event_choice_reason()`으로 조건을 조회하고
`campaign.resolve_event_choice()`에 선택을 전달한다. 신규 이벤트 추가 시 공통
UI는 재사용하고 캠페인에 해당 이벤트의 판정/해결기만 연결한다.

선택 전 자동 진행·건너뛰기를 막는다. 다음은 도입부에서 선택 화면까지 진행할 수
있지만 선택 화면을 넘길 수 없다. 연출 최소 설정도 선택은 생략하지 않는다.
Esc 메뉴와 선택 대기 중 저장 버튼을 제공한다. 표시 결과의 템플릿은 해결기가
반환한 실제 수치로 선택 이후에 치환한다. 기존 배경/Portrait 위치는 유지한다.

저장 버전 4를 유지하고 선택 필드 `crop_failure_events`를 추가한다.

- `years`: 성공/실패를 포함한 연도별 판정 및 피해 영수증.
- `pending`: `event_id`, `occurrence_id`, `province_id`, `payload`.
- `resolved`: occurrence ID별 확정 선택·실제 변화량 또는 소유권 변경 취소.

불러오기는 자원 복원 후 미결 선택 화면만 연다. 다른 연출 뒤에 대기하던 선택도
복원한다. 도입부·피해·지난 달·이미 확정된 결과는 재실행하지 않는다.
이전 저장에 필드가 없으면 빈 상태로 시작하며, 9월 이후 저장은 그 해를 정산 완료로
기록해 소급 피해를 막는다. 기존 저장 파일에 자원/기술을 지급하지 않는다.

기존 표시 전용 `cutscene_preview.tscn` 목록에서는 자원 결정을 요구하는 이벤트를
제외했다. 흉년은 실제 캠페인 또는 별도 자동 검증에서 확인한다.

## 자동 검증

Godot 4.7.2 console 실행 파일을 `godot` 명령으로 사용할 수 있는 환경에서,
저장소 루트에서 실행한다. 로그/스크린샷/테스트 저장은 커밋하지 않는다.

```text
godot --headless --path . --script res://tests/crop_failure_test.gd
godot --headless --path . --script res://tests/bountiful_harvest_test.gd
godot --headless --path . --script res://tests/cutscene_test.gd
godot --headless --path . --script res://tests/production_test.gd
godot --headless --path . --script res://tests/geumgwan_ownership_test.gd
git diff --check
```

흉년 검증은 확률·SHA 기준값·대상 순서·풍년 제외·연간 한도·피해·세 가지 선택·
재고 경계·치안 상하한·중복 신호·구형 저장·연출 설정·대기열 저장 복원·입력 잠금을
확인한다. 생산 테스트의 기존 수확 공식 전용 fixture에서는 그 해 흉년 판정만
완료 상태로 고정한다. 본게임 자원을 바꾸는 설정은 없다.

최종 결과: 흉년 90/90, 풍년 47/47, 컷씬 83/83, 생산 193/193,
소유권 181/181. 컷씬 수는 새 WebP 경로 검증 3개로 80에서 83으로 늘었다.
기존 Windows 인증서 저장소 접근 오류는 환경 오류로 분리한다.
헤드리스 편집기 import 종료 시 사용자 editor_settings 저장 권한 오류도 있었으나,
리소스 import와 게임 스크립트 파싱은 성공했다.

## 실제 화면 확인 (2026-09-07)

1280×720 그래픽 실행, 정상 UI 명령과 턴 진행을 사용했다. 금·재고·기술·시설·날짜를
런타임으로 주입하지 않았다. 저장 검증은 정상 저장/불러오기 함수에 `.godot/` 내
별도 파일 경로를 전달하여 사용자의 기본 저장을 덮어쓰지 않았다.

1. 새 게임 → 632년 → 신라 → 게임 시작.
2. 다른 명령 없이 턴 종료 8회 → 9월.
3. 국원 풍년 연출 종료 → 금관가야 흉년(확정 군량 손실 576).
4. 다음 → 세 가지 정책 중 선택 → 결과 → 다음/건너뛰기/자동 진행으로 지도 복귀.
5. 선택 전에 저장했다가 불러오면 금관가야·피해 576을 표시하는 선택 화면으로 복귀.

동일한 선택 대기 저장을 각각 불러와 확인한 결과:

| 선택 | 도시 군량 전 → 후 | 치안 전 → 후 |
|---|---:|---:|
| 구휼 | 4,830 → 4,030 | 100 → 100 (실제 +0) |
| 세금 유지 | 4,830 → 4,830 | 100 → 94 |
| 강제 징발 | 4,830 → 5,330 | 100 → 88 |

군량 4,830은 이미 9월 수확·흉년 피해·기존 월 경제를 정산한 뒤의 도시 재고다.
구휼은 실제 포인터 클릭으로 확인했다. 다른 선택·자동 진행은 UI 신호를 사용했다.
실제 Esc 키로 메뉴 진입, 최소 연출 설정에서 저장 복귀, 선택 후 턴 잠금 해제를
확인했다. 재고 부족 및 치안 경계의 인위적 조건은 헤드리스 전용 fixture에서 확인했다.
