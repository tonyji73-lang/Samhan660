## 철 조달 제한과 수정

기존 차단은 (1) 632/642 금관의 지역 허용 데이터, (2) 제철시설 건설에도 적용되던 같은 지역 검사, (3) basic_smelting의 researchable=false였다. 지역 공급 데이터·고증 자료·기존 산출량·금6은 보존했다.

| 경로 | 조건 | 100 작업량당 비용/산출 |
|---|---|---|
| 기존 `iron_supply` | 기존 지역/시나리오 허용 + 기본 제련1 + 제철시설1 | 금6 → 철2 |
| 신규 `iron_procurement` | 기본 제련1 + 제철시설1 | 금18 → 철2 |
| 기존 `iron_sword` | 도검 제작1 + 군기감1 | 금10 + 철2 → 무기1묶음 |

공통 조달은 **소규모 원료 확보와 정련을 합친 게임용 공급 과정**이다. 특정 도시의 광산이나 역사적 생산량을 새로 지정하지 않는다. 직접 비용은 같은 산출량의 지역 공급 금6의 3배인18이다. 철은 기존 city_inventory.iron, 무기는 sword만 사용한다. 부대 환산은 이전과 같은 무기1묶음=100명분이며 레시피·재고 숫자를 증식하지 않았다.

기본 제련의 신규 연구 가격은 **금200, 기존 계절1회=기준3개월/작업량300**으로 정했다. 도검 연구와 같은 초기 검증값이다. 국가·연도 제한 없이 공통 담당자 연구로 수행한다. 기존 시나리오가 이미 보유한 기본 제련 단계는 그대로이며 재결제하지 않는다. 제철시설 금240/기준6개월, 군기감 금320/기준6개월, 도검 연구 금200/기준3개월은 유지한다.

지역/공통 조달은 같은 smelter 작업량을 쓴다. 두 명령이 켜지면 유효한 저렴한 지역 공급이 먼저 선택되고 남은 시설 배치 한도만 쓴다. 생산 담당자 없음100, 담당자 있음100+round(E/2), 100 미만 잔여 진척, 재료·금 부족, 중지/재개, 점령 종료, 국가/시설 월 처리 기록은 기존 API를 사용한다. 구형 비산업 경로에도 동일 시설 한도와 공급→제작 순서를 적용했다. 같은 달 경로 전환으로 추가 생산되지 않는다.

## 민간 인구·동원 한도·저장

`provinces[city].population`을 **민간 인구의 유일한 원본**으로 정의했다. 기존 시나리오 인구를 소급 보정하거나 현재 병력만큼 빼지 않는다. 신규 모집 성공 시에만 N명을 민간에서 빼고 기존 부대 원장에 N명을 등록한다. 일반 모집 100명당 금15/해당 도시 군량20은 유지한다. 인구·출신 한도·권한·금·군량을 먼저 검증한 뒤 동기식 거래로 차감/생성하며 실패 시 이 자원과 병력은 그대로다. 실패 진단 이력은 남길 수 있다.

- C = 현재 도시 민간 인구.
- S = 위치/국가와 관계없이 현재 복무 중인 부대의 해당 도시 출신 인원 합계.
- 추가 동원 = `max(0, floor((C+S)×0.25)−S)`, 민간 인구 한도와 100명 단위 내림 적용.
- 25%는 `Mobilization.RATE`의 조정 가능한 게임용 값이다.
- S는 기존 `unit_rosters[id].origins`를 조회한다. 두 번째 출신/병력 장부를 만들지 않는다. 이동 중·타 도시 주둔도 포함한다.
- 기존 편성·보충 합류·분할·이동·훈련은 인구를 다시 차감하지 않는다. 모집 출신별 인원은 분할/합류/손실 후 실제 부대 병력 합계와 같아야 한다.
- 전사자는 민간으로 돌아오지 않는다. 현재 캠페인에는 별도 부상자/포로 병력 원장이나 모집 예약·생성 전 취소 경로가 없다. 그런 자료를 민간 인구로 간주하는 규칙을 추가하지 않았다.
- 시나리오/구형 병력은 `scenario_or_legacy_no_retroactive_charge`, 일반 모집은 `recruitment`, 분할은 `split`, 내부 외부 지원 생성은 `external_support`로 구분한다. 실제 사건의 무료 지원 병력을 새로 추가하지 않았다.

해산은 실제 아군 도시에 주둔한 자기 부대만 가능하다. 선택한 N명은 **현재 도시** 민간으로 돌아오고 출신지의 현역 부담은 줄어든다. 출신지로 인구를 순간 이동시키지 않는다. 이동 중 해산을 거절한다. 부분 해산은 남은 훈련도/장비/출신과 업무를 보존하고 다음 월 비용은 남은 인원으로 계산한다. 전원 해산은 훈련 업무와 담당자 duties를 해제한다. 비용·군량·장비 환불은0이며, 제거한 장비는 소비 이력이다.

저장 버전11은 원래 인구·병력·장비·훈련·국고와 진행 업무/수송/생산/사건을 그대로 저장한다. 기존 origins를 우선한다. 없는 구형 주둔 자료는 당시 위치, 구형 이동은 기존 source_id 기준의 추정이고, 위치도 식별되지 않으면 unknown으로 보존한다. 실제 추정은 migration/origin_basis에 기록한다. 구형 출신 합계가 실제 병력과 상충하면 원본을 보관하고 당시 주둔 도시 추정을 명시한다. 이미 한도를 초과한 저장도 병력을 삭제하거나 인구를 소급 차감하지 않으며 추가 모집만 막는다. 반복 로드 자체는 인구·철·장비·비용을 지급/차감하지 않는다.

## 경제 계산과 월 순서

기존 세입과 수확은 이미 민간 인구에 선형 비례했다. 기준 인구나 별도의 감소 계수를 추가하지 않았다.

- 기본 월 세입 = round((C/1000) × 상업/100 × 치안효율 × 2).
- 기본 연간 수확 = round((C/1000) × 농업/100 × 치안효율 × 100).
- 치안효율 = 0.5 + clamp(치안,0,100)/200.
- 기존 유효 태수 배율은 위 기본 결과에 한 번만 적용한다.
- 기존 국가 수취율45%, 9월70%/10월30%, 풍흉년·주둔 소비·창고 손실은 유지한다.
- granary_capacity는 기존 저장 값을 사용한다. 모집으로 다시 계산하거나 보유 군량을 용량에 맞춰 삭제하지 않는다.
- 실제 코드에는 별도의 자연 인구 증가나 기존 사건의 민간 인구 증감 처리가 없었다. 모집 부족을 상쇄하는 자연 증가/임의 인구 지급을 추가하지 않았다.

도시 견적은 기존 계산 함수에 모집 후 민간 인구를 넣은 임시 사본으로 계산한다. 실제 인구를 바꿨다가 되돌리는 방식이 아니다. 연간 수확과 다음 9/10월 국가 수취 예상량을 구분하고, 미래 치안/태수/사건 변화까지 보장하지 않는다고 표시한다.

월 순서는 기존 내정 완료 → 건설/연구 완료 → 화물 도착 → 세입/수확 → 주둔 소비/창고 손실 → 훈련 → 시설 생산 → 기존 병력/장수 이동 → AI 수송·조달/장비·훈련/모집·공격 → 계절/사건이다. 완성 시설·기술 및 도착한 철을 그달 생산에 사용한다. 모집은 해당 월 결산 이후 실행되므로 변경된 인구는 다음 결산에 반영된다.

별도 실제 결산 검증: 632년 금성1,000명 모집 시 민간120,000→119,000, 월 세입155→154, 연간 수확9,452→9,373. 다음 월 실제 세입은 **기본129+태수25=154**였다. 9월 실제 수취는 **기본2,469+태수484=2,953**으로 견적과 같았다. 풍흉년 증감은 별도 사건 경로이며 세입/수확 재호출은 중복 정산하지 않았다.

## AI 정책과 실제 비교

AI도 공통 연구/건설/생산/수송/모집/지급/훈련 함수를 호출한다. 자산을 채워 실행하지 않는다.

- 군수 준비는 국가별 한 거점을 우선 완성한다. 현재 아군 도시/가용 인물로 결정하며 상실 시 다시 고른다. 여러 미완성 제철시설에 예산을 분산하던 개발 중 판단을 수정했다.
- 현지 주둔군3개월 군량, 금 예비300과 실제 계획 모집 비용을 남길 수 있어야 군수 지출을 선택한다. 시설/연구 접수는 국가당 월 최대 하나다.
- `target_bundles=10`, 생산 원료 목표4배치, 도착 지연 평가값 월당6을 정책값으로 둔다. 이는 실제 추가 운송비가 아니라 선택 점수다.
- 현지 유효한 지역 공급 금6/철2, 공통 조달 금18/철2, 아군 실제 여유 철 재고의 운송비/경로/도착을 비교한다. 기존 재고의 과거 매입비는 재청구하지 않는다. 생산 기간은 기본 배치 기준으로 평가하고 실제 생산은 담당자/시설 작업량을 적용한다.
- 현재 조달 비교는 가동 가능한 현지 생산과 실제 아군 여유 재고가 대상이다. 아직 없는 원격 광산/시설을 가정한 공급망 최적화는 하지 않는다.
- 선행 긴급 군량 수송과 도착 예정 유효 철을 반영한다. 같은 국가의 월 신규 수송 최대1개를 지키고, 같은 부족분을 다시 보낼 수 없다.
- 모집은 공통 인구/국고/군량 상한 내100명 단위다. 모집 후3개월 유지 군량과 현재 견적의 세입/수확95% 이상을 보존할 수 있는 수량으로 줄인다. 유지 조건 실패 시 모집하지 않는다. 이동/소속 변경으로 출신 한도를 우회하지 않는다.
- 같은 월 재호출을 막고, 실행 불가 판단이 같으면 진단을 매월 그대로 추가하지 않는다. 조건을 재평가하지만 실패 명령을 비용/결과 없이 반복 접수하지 않는다.

별도 AI 규칙 검증은 기반시설·국고·철을 명시적으로 설정한 **통제 fixture**다. 정상 플레이 재고로 주장하지 않는다. 실제 `run_enemy_ai_turns()`가 명령을 선택하고 다음 실제 월에 처리했다.

## 다음 연결 함수와 남은 과제

- `Mobilization.view/serving`: 현재 민간 인구·출신 현역·100명 단위 동원 여력.
- `Recruitment.quote/affordable/execute`: 같은 자원/권한/인구 검사와 실제 유료 모집.
- `campaign.get_recruitment_quote`: 공통 모집 견적 + 기존 경제 함수의 모집 후 세입/다음 수확 예상.
- `Mobilization.disband_quote/disband`: 현지 인구 복귀, 장비 소모, 부분/전체 훈련 업무 처리.
- `Mobilization.initialize`: 소급 차감 없는 구형 출신/사유 보완과 진단.
- `Army.divide/merge/casualties`: 기존 부대 원장의 출신/장비/훈련 합계 보존.
- `Production.facility_quote/city_quote/process_all`: 공유 제철시설 진척, 실제 국가 비용/도시 재고.
- `IronAI.run`, `Mobilization.ai_amount`, `Supply.ai`: 실제 월 조달·인구/유지 판단·도착 예정 재고 비교.

남은 과제는 초기 시설 준비 기간과 모집 대비 무기 생산 능력의 밸런스, 원격 생산 거점까지 포함한 장기 조달 최적화, 인구 성장/징집 연령 구성, 별도 부상자·포로·복귀 제도다. 이번에 이를 임의 인구/장비 생성으로 대체하지 않았다. 기존 이동 중 별도 군량 행렬, 특수병 모집/전술·전투 개편도 추가하지 않았다. 현재 통합본에서 후속 밸런스와 경제 정책 작업을 계속할 수 있다.
