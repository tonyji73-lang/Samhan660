## 저장 변환

저장 버전은 5. 정적 명부는 데이터 파일에, 실제 상태는 `strategy_state.officer_registry`에 저장한다. 이름별 도시 목록과 emergent_officers, officer_metadata, dynasty.people의 중복 저장을 제거했다. 기존 저장의 생성 능력치·생몰 게임 연도·관계·태수·이동·부모·자녀·교육 담당을 ID로 연결한다. 진행 중 소속·위치는 저장을 우선하며 초기 명단과 다르거나 도시 소유자와 맞지 않는 경우 진단만 남긴다.

기존 외교의 월별 행동 기록은 원래 **세력→마지막 행동 월** 구조여서 인물 이름 키를 갖지 않는다. 이 구조와 외교 관계·통상 조약을 그대로 보존하고, 사절 입력과 검증은 ID로 전환했다. 난수 식별 문자열은 인물 표시 변경으로 재추첨되지 않도록 보존한다.

미식별 인물은 안정된 legacy ID로 유지하고 원본 능력치·명단·관계·이동·태수 자료를 `legacy_archive`에 보관한다. 중복 배치·충돌 태수는 한 인물의 실제 위치를 중복 생성하지 않고 보류 원본과 진단을 남긴다. 이름만으로 복원할 수 없는 역사 소속은 빈 ID와 legacy_faction으로 보존하며 잘못된 도시에서 행동 가능 인물로 취급하지 않는다. 과거 저장 자체가 같은 이름의 두 사람을 구분하지 않았다면 자동으로 신원을 단정하지 않는다.

실제 직전 통합 세이브를 변환한 뒤 생산 재고·건설·군량·외교 행동 월·사건 완료 기록이 보존되는 것을 검사했다. 생성 사절·이동 대기·도착·성장·동명이인·변환 후 세이브마다 세 번 반복 불러오기를 실행했다. 저장 중복본을 제거했는지도 파일에서 직접 확인했다.

## 남은 기존 문제와 다음 작업

- 기존 전투 `unit_rosters` 캐시는 로드 시 도시 병력에 다시 맞춰진다. 직전 통합부터 있던 문제로 유지했다. 비교에서는 캐시만 제외하고 도시 병력·군량·다른 실제 상태는 검사하며 원본 전후 자료를 보관한다.
- 기존 캠페인은 44개 도시를 만든다. 탐라는 준비된 시나리오 세력 목록에 없고, 632/642의 9개 초원 도시는 옛 부족 소유 템플릿과 해당 시나리오의 설연타 등 세력 목록이 어긋난다. 이번에 도시 소유권·세력 선택 정책을 개편하지 않았다. 아래 표에 ‘시나리오 미등록’ 소유자와 공석을 별도 표시한다. 이 도시에 인물을 임의 생성해 문제를 숨기지 않았다.
