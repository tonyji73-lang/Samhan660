## 직책과 업무

- 태수는 명부의 `posts["governor:<city>"]`로 유지되는 직책이다. `set_post`가 동일 인물의 다른 태수 자리를 해제하고 이력을 남긴다. 실제 임명은 기존 캠페인의 소속·도시·생존·이동 검사를 거친다.
- 군주는 `ruler:<faction>`의 별도 직책이다. **새 게임에서는 군주에게 태수를 자동 부여하지 않는다.** 명시적 초기 배치 순서에서 해당 도시에 근무 가능한 첫 비군주 인물을 태수로 선택한다. 그런 인물이 없으면 공석이다. 군주도 사용자가 같은 도시 태수로 임명할 수 있다.
- 기존 저장에 있는 군주 겸임 태수와 기존 임명은 그대로 유지한다. 새 게임의 태수 선택 규칙을 로드 시 다시 적용하지 않는다. 기존 OFFICER 보고서의 공석 숫자는 변경 전 스냅샷이다.
- 개발은 `strategy_state.domestic.jobs[job_id]`의 기간 업무다. 도시당 농업/상업 합쳐 pending 업무 하나, 인물당 pending 내정 업무 하나다. 담당자는 같은 도시·소속의 활동 중인 생존 인물이며 이동 중이어서는 안 된다.
- 인물의 `duties`에는 이름이 아닌 업무 ID와 도시 ID의 연결만 둔다. 완료/취소/중단 시 해당 연결만 제거하여 다른 종류의 업무 정보를 지우지 않는다.
- 태수는 자기 도시의 개발 업무 하나를 겸할 수 있다. 태수 교체·해임은 개발을 취소하지 않는다. 현지에서 일할 수 있다면 개발 담당 역할은 계속된다.
- 업무가 있는 인물은 이동·사절·공격 지휘관 선택에서 제외된다. `Registry.action_available`을 명령 검증과 실제 지휘관 선택이 함께 사용한다. 다른 가용 장수가 있으면 그 사람이 지휘하고, 모두 내정 중이면 출정을 막고 업무 정리를 안내한다. 애초 배치 장수가 없는 도시의 기존 수비대장 fallback은 유지했다.
- **방어와 태수 역할은 내정 업무를 겸해도 가능하다.** 공격 지휘관은 `get_best_commander(city,"attack")`, 수비는 `"defense"` 경로다. 전투 계산식·병력 성장은 바꾸지 않았다.
- 실제 사절/출정을 수행한 인물은 `external_action_month`를 기록하고 그달 새 내정 업무를 맡을 수 없다. 그달 태수 운영 견적도 근무 불가로 계산하며 다음 달에는 이 활동 제한이 풀린다. 사절 이동 기간 등 새로운 여행 규칙은 추가하지 않았다.

## 계산식과 월 처리 순서

상수는 `domestic_assignment.gd`의 COST=100, MONTHS=1, POLITICS_WEIGHT=0.8, INTELLIGENCE_WEIGHT=0.2, BASE_GAIN=1, GAIN_RANGE=4, EFFICIENCY_SCALE=100, MIN_GAIN=1, MAX_GAIN=5, MAX_DEVELOPMENT=100, GOVERNOR_DIVISOR=500에 모았다.

`E = 정치 × 0.8 + 지력 × 0.2`

`예정 상승 = clamp(round(1 + 4 × E / 100), 1, 5)`

견적에서는 남은 상한 여력으로 실제 상승량을 제한한다. 이미 100이면 명령을 거절하고 금을 차감하지 않는다. 담당자·비용·정치/지력·효율·예정 상승량·완료 월을 접수 시 기록한다. 이후 능력치가 달라져도 예정 성과를 재추첨하거나 덮어쓰지 않는다. 완료 시 상한 여력을 다시 확인하여 100을 넘기지 않는다.

`태수 운영 계수 = 1 + clamp(정치, 0, 100) / 500`

기존 기본 세입과 기본 연간 수확을 먼저 계산하고, 각각에 위 계수를 **한 번만** 곱해 반올림한다. 국가 군량 수취 45%, 9월 70%·10월 30% 수확 배분, 치안 효율, 병력 소비와 창고 손실은 기존 순서와 계산을 유지한다. 태수 계수를 개발 상승량에 곱하지 않는다. authority는 기존 인물 능력치 그대로다.

월 진행 순서:

1. 달력 진행, 직책 이력용 현재 월 갱신.
2. 담당자/도시 자격 검사와 만기 개발 완료. 실패하면 성과 없이 중단.
3. 도시 상업세, 계절 수확과 기존 풍년/흉년, 병력 군량 소비, 창고 손실.
4. 기존 군수 생산, 치안, 이동 도착, 기존 AI 행동.
5. 기존 계절 전략 처리(건설·연구·교역·연간 인물 처리), 화면 갱신과 사건 제시.

완료된 개발 수치는 같은 월 결산에 사용된다. 결산 이후 치안 변화 때문에 그다음 화면의 **새 견적**과 직전 실제 결산이 다를 수 있어 둘을 나눠 표시한다.

플레이어와 AI 모두 같은 `city_operation_quote`와 `Domestic.governor`를 사용한다. 활성 AI 도시의 세입도 같은 계수로 계산해 도시 결산 기록에 남기며, 수확 군량은 플레이어/AI 도시 모두 실제 재고에 가산한다. 기존 게임에는 AI의 독립 상업세 지출 예산이 없으므로 새로운 AI 국고나 지출 AI를 만들지 않았다. 금 가산은 기존대로 플레이어 소유 도시 합계다.

`domestic.settlements[city]`에는 세입/수확의 처리 월, 기본값, 태수 추가분, 결과와 계산 당시 개발/치안 수치를 저장한다. 같은 월 같은 결산을 재호출하면 중복 지급하지 않는다. 이는 풍년/흉년 효과를 대체하지 않으며 수확 기록은 해당 추가 사건 적용 전 정상 수확이다.

## 취소·중단·이력

정상 취소는 완료 예정 월 전, 여전히 소유한 도시와 자격 있는 담당자의 pending 업무만 가능하다. 접수한 금 100을 한 번 환불하고 `cancelled`, `refund`, 처리 월을 기록한다. 완료/취소/중단된 업무는 다시 취소하거나 환불할 수 없다.

도시 상실 또는 담당자 사망·이동·소속 불일치 등으로 자격을 잃으면 `interrupted`와 이유를 남기고 성과를 적용하지 않는다. 도시 상실에는 환불하지 않는다. 이번 초기 규칙에서는 담당자 자격 상실에 의한 강제 중단도 환불하지 않으며, 자격이 정상일 때 사용자가 취소하는 경로에서만 환불한다. 도시 탈취 처리와 월 결산 전 검사가 이 중단을 반영한다.

직책 변경은 `officer_registry.post_history`에 `officer_id`, `city_id`, `post`, `previous_id`, `new_id`, `month`, `reason`을 남긴다. `month`는 기존 게임과 같은 `year * 12 + month` 절대 월이다. 새 게임 초기 태수, 수동 임명/해임, 이동·소속·생존 변경에 의한 해제를 구분한다. 변경이 없는 재임명은 이력을 중복 생성하지 않는다. 기존 저장의 과거 이력을 임의로 만들어 넣지 않는다.

## 실제 비교와 자원 변화

신라 금성·백제 사비·고구려 평양의 같은 통제 조건에서 각각 실행했다. 능력치를 바꾼 인물은 검사 fixture이며 게임 기본 인물 데이터는 변경하지 않았다. 상세 수치는 [comparisons.json](../.godot/domestic-results/comparisons.json)에 있다.

| 담당자 정치/지력 | 접수 전 금 | 접수 후 금 | 농업 시작 | 완료 농업 | 상승 |
|---|---:|---:|---:|---:|---:|
| 90 / 90 | 1,000 | 900 | 40 | 45 | +5 |
| 30 / 30 | 1,000 | 900 | 40 | 42 | +2 |

두 조건을 삼국 모두 검사했다. 접수 후 담당자 능력을 1/1로 바꿔도 접수된 +5/+2가 그대로 완료되는 것도 확인했다. 상업 99에서는 +1만 견적·적용되고, 100에서는 실행과 차감이 차단된다.

인구 100,000, 농업·상업 50, 치안 100의 동일 도시 비교:

| 태수 상태 | 월 세입 | 연간 수확 | 기본 대비 |
|---|---:|---:|---:|
| 공석 / 태수 이동 후 | 100 | 5,000 | 기본값 |
| 정치 80 | 116 | 5,800 | +16% |
| 정치 30 인물로 교체 | 106 | 5,300 | +6% |
| 정치 100 | 120 | 6,000 | +20% |

정치 100 태수의 9월 실제 도시 군량 가산은 `6,000 × 45% × 70% = 1,890`. 같은 월 재처리는 0 추가였다. 이것은 병력 소비·창고 손실 전 수확 가산이다.

| 632년 통제 fixture | 대상 도시 세입 | 해당 실행의 플레이어 전체 세입 | 대상 도시 9월 수확 가산 |
|---|---:|---:|---:|
| 신라 / 금성 | 120 | 1,507 | 1,890 |
| 백제 / 사비 | 120 | 725 | 1,890 |
| 고구려 / 평양 | 120 | 1,044 | 1,890 |

전체 세입이 다른 것은 나머지 도시 수·상태가 다르기 때문이다. 같은 대상 도시 계산은 같다.

**수정하지 않은 632년 신라 실제 화면 플레이:** 선덕여왕(정치 93·지력 91)의 농업 견적 +5를 접수했다. 금 `1,000 → 900 → 취소 1,000 → 재접수 900`. 저장·불러오기 후 2월에 금성 농업 `74 → 79`, 금 `2,442`, 총 군량 `72,270 → 69,861`을 확인했다. 2월은 수확 월이 아니므로 농업 개발 자체로 즉시 군량을 지급하지 않으며, 군량은 기존 월 소비·손실을 거친 값이다. 금성의 직전 실제 세입은 기본 130 + 태수 25 = 155로 표시되었다. 결산 후 치안 변화가 반영된 새 견적은 160으로 별도 표시된다.

## 저장 호환

저장 버전 6. 기존 `strategy_state` 아래에 domestic 업무·결산을 추가하고, 명부 안에 직책 이력·업무 ID·당월 외부 활동 기록을 저장한다. `Domestic.ensure`는 업무 정보가 없는 기존 저장에 빈 구조만 보완한다. 새 게임의 태수 선임 규칙이나 새로운 업무를 로드 중 실행하지 않는다.

pending 저장을 세 번 반복 불러온 뒤 실제 월 진행으로 완료했고, 완료 저장과 취소 저장도 각각 세 번 반복 로드했다. 금·담당자·예정 성과·직책 이력·처리 상태·기존 생산·외교·사건·도시 군량을 함께 비교했다. 이후 월 진행에서도 개발이 반복되지 않고 완료/취소 후 재환불이 거부되었다. 내정 데이터 없는 저장은 빈 업무로 복원되고 기존 금·재고·외교가 보존되었다.

직전부터 있던 `unit_rosters` 병력 캐시 재동기화만 기존 방식대로 비교에서 제외했다. 실제 도시 병력·군량과 다른 상태는 비교했다. 이 전투 캐시 문제를 이번 내정 변경에 섞지 않았다.

업무 중복, 이동·사절·공격 충돌, 수비 참여, 태수 겸직·교체·공석·이동, 금 부족, 개발 상한, 정상 취소/중복 환불 거절, 도시 상실, 사망 자격 상실, 접수된 능력치 스냅샷, 실제 월 처리 순서와 반복 로드를 검사했다. 기존 장수 검증에서는 생성 인물의 임명·이동·사절·성장·저장 경로도 다시 실행했다.

기존 테스트 기대 변경은 생산 테스트 한 곳이다. 기본 수확식 검사 fixture에 이제 실제 태수 효과가 붙어 첫 실행에서 9/10월 기대값 두 개가 실패했다. 기본 공식 검사 동안만 태수를 비우고 즉시 복원하여 종전 `2,520 + 1,080 = 3,600`과 수취율·수확 시기 검증을 유지했다. 새 태수 효과는 별도 삼국 실제 수확 검증에서 검사한다. 새 내정 검사 작성 중에는 직접 fixture 이동 후 표시를 동기화하지 않은 비교, 결산 후 치안으로 새로 계산한 견적을 직전 결산과 비교한 항목을 바로잡았다. 게임의 결산/치안 순서를 바꾸어 테스트를 맞추지 않았다.

환경 때문에 생략한 요청 검증은 없다. 실행 시 시스템 인증서 저장소 경고는 있었으나 게임 로직·렌더링 검사는 진행되었고, 최종 로그의 스크립트 오류나 검사 실패는 없다.

재실행: 프로젝트 경로에서 `Godot --headless --path . --script res://tests/domestic_assignment_test.gd --log-file <절대 로그 경로>`. 실제 화면은 `--headless`를 빼고 `res://tests/domestic_assignment_gui_test.gd`를 실행한다. 기존 검사들은 위 표의 해당 `_test.gd`로 실행한다.

## 다음 건설·연구·군수 생산 연결 지점

| 공통 함수/구조 | 사용 방법 |
|---|---|
| `Registry.resolve/view/eligible` | 인물 ID·실제 상태·현지 소속/생존/이동 자격 조회 |
| `Registry.action_available(registry,id,provinces,action,city)` | 인물 가용성의 한 진입점. 새 업무 종류를 추가할 때 여기서 충돌 정책을 확장할 것 |
| `Registry.set_post/set_location/set_faction/set_alive` | 직책 중복과 해제 이력을 보존하는 실제 상태 변경 |
| `Registry.post_history` | 귀족/충성 등 후속 기능이 조회할 임명·해임의 인물/도시/전후 ID/날짜/이유 |
| `Domestic.quote/start/cancel/process` | 동일 검증으로 견적→접수→월 처리→종결을 구현하는 구조. 현재 지원 업무는 agriculture/commerce뿐 |
| `Domestic.efficiency/increase/governor` | 개발 성과와 태수 운영 계수 분리. 건설/연구에 개발식을 무조건 재사용하지 않을 것 |
| `Domestic.active_job/invalid_reason/release/ensure` | 도시 업무 조회, 자격 상실, 담당 연결 해제, 저장 기본값 보완 |
| `campaign.get_domestic_quote/start_domestic/cancel_domestic` | UI와 실제 금 차감을 묶는 명령 경로 |
| `campaign.city_operation_quote/get_city_operation_text` | 도시 세입·수확의 기본/태수 추가분과 표시 |
| `campaign.validate_attack_staff/get_best_commander` | 출정과 방어를 구분한 인력 가용성 연결 |

업무/비용/성과/상태 기록은 진행 중 세이브와 함께 유지해야 하며, 새 종류도 완료/취소/중단을 구분해 반복 적용을 막아야 한다. 이번에는 건설·연구·군수 생산 담당자, 중앙 관직, 충성·반란·혼인 효과, 신규 업무 AI를 추가하지 않았다.
