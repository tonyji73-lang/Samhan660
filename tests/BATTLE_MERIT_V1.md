# 전투 공훈·선택 포상 v1

## 구현과 보존

현재 main의 `7c0662e`를 기준으로 구현했다. 기존 미추적 파일
`tests/main_host_save_test.gd.uid`는 그대로 두고 이번 커밋에서 제외한다.
기존 회귀 보고서 및 642 정치 확장 보고서를 변경하지 않았다.
상위 경로 포함 적용할 AGENTS.md는 없었다.

- `army_readiness.gd`: 기존 전투 직전 부대 스냅샷과 기존 승패 결과에 공훈 메타데이터를 추가한다.
- `battle_merit.gd`: 신규 전투 ID, 참전 기록, 포상 견적/실행, 인물 이력을 담당한다.
- `battle_merit_overlay.gd`: 전투 결과·후보·비용/효과·처리 상태와 선택 포상 화면.
- `campaign_main.gd`: 기존 플레이어 전투 결과 경로 뒤에 공훈 화면 연결, 메뉴 재진입, 입력 잠금/복원.
- `noble_politics_overlay.gd`: 현재/과거 아군 인물을 선택해 참전·포상 이력을 열람한다.
- `tests/battle_merit_{playtest,test,restart}.gd`: 정상 플레이·GUI, 통제 경계, 별도 프로세스 복원.

실제 전투에 사용된 전투 지휘자와 참전 부대에 배정된 지휘관을 기록한다.
전투 당시 생존·활동·소속·위치가 유효한 인물만 포함하며 동일 지휘관의 여러 부대는 한 후보로 묶는다.
당시 소속·정치 집단·공격/방어·승패·참전 부대 ID·직접 지휘 부대 ID·전투 지휘 여부를 보존한다.
전투 후 이동·점령·지휘관 교체로 현재 부대가 달라져도 과거 기록은 바뀌지 않는다.
UI에는 원장에 있는 참전 부대 종류/당시 인원만 표시한다. 양측 전체 손실을 개인 처치·피해량으로 분배하지 않는다.

새 전투마다 Crypto의 16바이트 무작위 ID를 생성해 기존 `army.battles` 원장에 저장한다.
게임 전투 RNG나 승패·손실·점령·훈련·생산 공식을 바꾸지 않는다.
전투 ID와 참전/포상 자료는 기존 strategy_state 저장 경로로 그대로 직렬화된다.

## 포상과 화면

632·642년 신라 정치 캠페인에서 승리한 아군 참전 지휘관이 대상이다.
공격 승리와 방어 승리 모두 지원하며 현재 생존·활동·신라 소속이어야 한다.
국고 금100, 충성+5, 현재 집단 협력+6은 기존 정치 포상 상수를 사용한다.
기존 100 상한을 적용하고, 무소속이면 집단 효과는 없다고 견적에 표시한다.

선택 버튼에는 금100과 충성/협력 전후 값이 표시된다. 자동 포상은 없다.
`Economy.validate_national`과 `Economy.post`, `Politics.change` 공통 함수를 사용한다.
실행 직전에 국고·대상·승패·현재 소속·생존/활동·중복·시나리오/플레이어·캠페인 종료를 재검증한다.
전투/인물별 포상 영수증과 국고의 고유 거래 토큰으로 중복 지급을 차단한다.
결제→정치 효과→영수증은 await 없는 동기 작업이며 화면 갱신에는 효과가 없다.
같은 인물도 다른 승리 전투에서는 별도로 한 번 포상할 수 있다.

기존 플레이어 전투 결과/특수 전투 연출이 끝나면 결과·공훈 화면이 열린다.
`Menu → 전투 결과·공훈 포상`에서 다시 열 수 있으며 방어전 결과도 이 목록에서 선택할 수 있다.
적 침공 경보의 기존 자동 재생 흐름은 유지한다.
인사 화면의 인물 선택 목록은 전투 당시 아군이었다가 소속이 바뀐 인물의 기록도 조회할 수 있다.
닫기/Esc는 포상을 실행하지 않고 지도 입력을 복구하며, 결과 화면 중 월 명령은 차단한다.

정치 자료 없는 구저장에는 정치 상태를 추가하지 않는다. 공훈 필드 없는 과거 전투에는
후보·포상 자격·영수증을 소급 생성하지 않는다. 기존 전투 원장은 그대로 보존한다.
포상 전 저장을 불러오면 그 저장 시점의 미포상 상태로 돌아오며, 포상 완료 저장의 재진입/복원은
추가 비용·효과를 만들지 않는다. 별도 저장 분기를 강제로 묶는 외부 전역 포상 기록은 만들지 않는다.

## 실제 정상 플레이 및 GUI

Godot 4.7.2 stable Windows, D3D12 Forward+ / RTX 4060 Laptop GPU.
642년 7월 신라·역사·보통, seed 64220260917로 시작했다.
기존 병력을 정상 이동 명령으로 집결하고 한 달 진행 후, 642년 8월 국원소경에서 웅진성을 공격했다.
전투 전 알천을 정상 지휘관 임명 명령으로 배정했다.
자원·능력·시설·연구·병력 수·날짜·승패를 직접 수정하지 않았으며 AI 월 처리도 유지했다.

전투는 승리했고, 공격/방어 전체 손실은 11275 / 20500이었다.
알천은 참전 지휘 후보 한 명으로 표시됐고 GUI 버튼을 클릭해 다음을 확인했다.

- 국고 2333→2233, 충성58→63, 문치 집단 협력50→56.
- 전투 결과에 포상 완료 표시 및 버튼 비활성화.
- 반복 실행·재진입에 자금/정치 원장 변화 없음.
- 인사 화면에서 알천의 국원소경→웅진성 참전·승리·부대·포상 이력 확인.
- 결과 화면 중 월 명령 차단, 닫기/Esc 후 지도 잠금 해제, 이후 정상 월 진행 성공.

GUI 입력은 Godot viewport의 버튼 좌표로 마우스 입력을 보내 수행했다.
이동/월 명령은 실제 게임 API를 사용했으며 사람이 수동 플레이한 결과라고 표현하지 않는다.
