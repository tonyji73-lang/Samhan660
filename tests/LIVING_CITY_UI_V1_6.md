## 화면과 수치의 근거

### 군수

왼쪽에 **현지 사용 가능 재고 / 진행 중 생산 / 도착 예정 수송 / 부족 물자 수송**, 오른쪽에 **생산 품목 / 상세 / 실행 정보**를 배치했다. 오른쪽 실행 정보와 확정/중지 버튼은 상세 스크롤 밖에 두었다.

군량은 기존 `provinces[city].food_stock`, 철·무기는 기존 도시 inventory를 조회하는 `get_production_view_model()`의 값이다. 국가 금은 공용 국고로 별도 표기하며 국가 전체 물자 합계를 현지 재고에 더하지 않는다. 이동 중 화물도 도착 전에는 현지 재고에 포함하지 않는다.

도착 예정은 기존 수송 주문의 목적지/상태/경로/현재 구간과 `remaining_reason()`을 사용한다. 날짜 표시는 기존 수송 창과 같은 남은 구간 기준이다. 경로가 막히면 도착 보류 사유를 표시한다. 새 수송 규칙이나 배송 속도는 추가하지 않았다.

출발 도시 선택 → 수송 버튼은 기존 수송 화면을 열고 목적지를 현재 도시로 선택한다. 화물량이나 운송비를 자동 확정하지 않는다. 부대 준비에서 진입했다면 닫기/Esc로 원래 도시·부대·담당자로 돌아온다.

생산은 기존 규칙상 선행 조건 미달이어도 **가동 예약**이 가능하다. 이를 실제 생산 가능으로 잘못 안내하지 않도록 확정 버튼은 “매월 생산 예약 확정”, 가까운 설명에는 실제 `model.reason`의 **생산 보류 사유**를 표시한다.

### 편성·장비 지급

주둔 부대를 왼쪽 목록에서 선택하면 중앙에 병력·장비 충족률·숙련도와 편성 명령, 오른쪽에 지급 수량과 창고/부대 변화가 나온다. 지휘관 초상과 이름은 왼쪽 아래에 유지한다.

`Army.equip_quote()`가 허용한 `bundles`·`persons`만 사용해 창고 차감과 부대 장비 증가를 표시한다. 현재 지급 가능량도 현지 재고와 부족 장비 범위를 구한 뒤 기존 quote로 재확인한다. 지급 불가이면 변화 예측을 숨기고 원래 사유를 보여준다. 선택/수량 입력만으로 재고·병력을 변경하지 않으며 **장비 지급 확정**에서만 기존 `Army.equip()`을 호출한다.

분리·합류·현지 해산·이동·출정은 원래 명령 함수와 검증 순서를 유지했다. UI에 전투력·인원 보정 공식을 새로 넣지 않았다.

### 훈련

후보 카드는 기존 일반/금색 선택 테두리와 초상을 사용한다. 이름·통솔/무력·현재 업무·배정 가능 또는 불가 사유를 표시한다. 선택은 견적 갱신이며 지휘관 임명/훈련 확정과 분리돼 있다. 후보 선택 취소는 게임 상태를 바꾸지 않는다.

현재 숙련도·진행 상태·현재 담당·실제 누적 납부를 표시한다. 월 비용·다음 숙련도는 기존 `Army.training_quote()`, 남은 기간/비용 안내는 기존 `military_preparation_guide.gd`의 모델 문구를 그대로 사용한다. UI에서 별도 훈련 공식을 만들지 않았다. 비용/기간은 **현재 조건이 유지될 때의 기존 견적**이지 무조건 보장되는 완료일이 아니다.

### 정상 캠페인에서 확인한 내용

632년 신라 정상 시작 → 실제 장수 이동 → 금관가야 제련소·군기감 건설/도검 제작 연구 → 실제 월 생산 10묶음 → 금성 수송 → 정상 모집으로 장비 없는 1,000명 부대 생성 순서다. 금·재고·인물·날짜를 검증용 수치로 덮어쓰지 않았다.

- 도착 예정 무기 10묶음이 군수 화면에 표시될 때 현지 재고는 여전히 0이었다. 다음 월 실제 수송 도착 후 현지 재고가 증가했다.
- 720p·1080p에서 지급 전 **창고 10→0묶음, 부대 장비 0→1000명분, 병력 1000명 유지**를 확인했다. 미리보기 동안 상태가 바뀌지 않았다.
- Space 키로 지급 확정 → 창고 10묶음 차감과 장비 1000명분 지급을 확인했다.
- 후보 선택/취소는 게임 상태 스냅샷과 동일했다. Space로 지휘관 임명·훈련 접수를 확인했다.
- 실제 견적은 월 금50, 다음 숙련도 50→61이었다. 실제 다음 달 버튼으로 2개월 진행해 숙련도 70에 도달했다. 화면이 훈련 완료로 갱신되고 추가 훈련 버튼이 비활성화됐다. 정상 흐름 완료 시점은 634년 4월이다.
- 이 정상 명령 흐름의 자원 준비는 720p에서 진행했다. 지급 전/훈련 견적/훈련 완료 화면은 양쪽 해상도로 확인했고 지급·훈련 키보드 확정과 마지막 월 진행은 1080p에서 수행했다. 전체 장기 흐름을 해상도마다 처음부터 2회 실행했다고 주장하지 않는다.

### 입력과 V1.5.1 미검증 보완

- 군수 및 군사 두 탭에서 Tab으로 활성 컨트롤 전체를 순회해 대화창 내부 순환을 확인했다. Shift+Tab 역순 이동, 부대 선택 후 포커스 유지도 검사했다.
- 생산 예약/중지를 Space로 실행했고 연구 접수/첫 진행 전 취소 환불도 두 해상도에서 키보드로 확인했다. 연구 Tab·Shift+Tab·Esc도 확인했다.
- 군수·군사·연구·수송의 Esc 닫기와 현재 도시 화면 입력 복구, 군사→생산→수송→원래 부대/담당자 복귀를 확인했다.
- 후보가 많은 경우와 긴 설명은 **UI에만 추가한 경계 fixture**다. 실제 인물/게임 규칙을 바꾸지 않았다. 내부 스크롤·가로 넘침 방지·빈 후보의 훈련 비활성을 확인하고 목록을 재구축했다.
- 이번 보완은 Godot의 두 해상도 입력 검증이다. V1.5.1의 **다른 PC 또는 Windows 125%·150% 전체 키보드 조합**을 새로 검증한 것은 아니다.

### 중간 실패와 조치

첫 화면 실행에서 내정 창이 아직 열리지 않은 경우 후보 초상을 얻는 의존 경로가 초기화되지 않아 비었다. 캠페인의 기존 초상 조회를 직접 사용하는 표현 헬퍼로 고쳤다. 편성 버튼의 수평 확장 폭도 수정했다. 중간 포커스 헬퍼의 중복 함수 선언을 제거하고 구문·화면을 재검증했다. 최종 로그에 스크립트 오류는 없다.

오래된 정상 흐름 검사의 지도 잠금 플래그는 현재 도시 오버레이가 표시된 상태에서도 잠겨 있으므로, “Esc/저장 복원 후 입력 복구” 검사 7개가 구형 기준으로 실패했다. 게임 잠금 규칙을 바꾸지 않고 **새 검증 사본에서 `settlement_overlay.busy()`를 사용**하도록 수정했다. 접수·비용·월 완료·재고 조건은 그대로 유지했다. 초기 실패 로그도 작업 폴더에 보존했다.

## 재현

원본 캐시/저장을 보존하려면 검수 사본에 현재 파일과 `tests/*.gd`, `tests/living_city_v1_6_review/production_regression.gd`를 복사한다. Godot 버전은 위와 일치시킨다. GUI 검사는 `--headless`를 사용하지 않는다.

```powershell
& $godot --path $qaProject --script res://tests/living_city_ui_v1_6_play.gd --log-file $visualLog -- --after
& $godot --path $qaProject --script res://tests/living_city_ui_v1_6_flow.gd --log-file $flowLog
& $godot --headless --path $qaProject --script res://tests/army_readiness_test.gd --log-file $armyLog
& $godot --headless --path $qaProject --script res://tests/living_city_v1_6_review/production_regression.gd --log-file $productionLog
```

실제 실행 시 생산 회귀 사본은 검수 프로젝트의 `tests/v1_6_production_regression.gd`에 복사해 실행했다. 위 경로의 사본 내용과 같다. 수정 전 캡처 재현에는 `before-source/` 사본과 `--after` 없는 캡처 모드를 사용하며 현재 작업 파일에 덮어쓰지 않는다.

## 미검증과 다음 작업

- **별도 Windows PC 검증: 수행하지 못함.** 다른 PC의 설치/저장 복원은 계속 미검증이다.
- V1.6 Windows export·배포 ZIP·실제 OS 125%/150% 재검수는 수행하지 않았다. 기존 V1.5 실행본에는 이번 UI가 아직 들어 있지 않다.
- 모든 도시·시나리오의 수동 UI, 게임패드, 초광폭/세로 화면은 미검증이다. 기존 모델 회귀의 시나리오 범위와 GUI 수동 범위를 혼동하지 않는다.
- 생산·수송 명령의 경제/전투 규칙은 보존했으며, 국가 전체 물자 대시보드나 새로운 물자 부족 예측은 추가하지 않았다.
