## 12조합의 조건표

**U35**: 아래 고정 도시 35개를 플레이어 국가가 **직접 점유**하면 승리. 동맹 점유는 제외한다. 소유국 변경으로 목표 목록을 재생성하지 않는다.

**D**: 플레이어의 최종 작전 거점 상실 + 현재 구현상 실행 가능한 수복·세력 전환 없음. 공격은 아군 출발 도시가 필요하며, 기존 이동은 아군 목적지 도착 또는 아군 출발지 복귀만 한다. 따라서 무도시 상태의 주둔/이동 중/미배치 병력 기록만으로 패배를 유예하지 않는다. 실제 무거점 수복 명령은 현재 없다. 자원 부족이나 역사적 멸망 연도, 군주의 사망 연도를 패배로 사용하지 않는다.

**M**: 무기 제작, 신규 보병 1,000명 장비·훈련 준비, 개별 전투 승리는 중간 목표다. 최종 승리로 취급하지 않는다.

## 판정·확정·화면 연결

- `Ending.evaluate(state, provinces)`: 읽기 전용 판정. 초기화, 자원 차감, 이동, 결과 확정을 하지 않는다.
- `Ending.confirm(...)`: 유효한 승리/패배만 한 번 확정. `campaign_ending.status`는 `ongoing/victory/defeat`. 조건 정의·버전·판정 사유·종료 월·경과 개월·도시/병력/국고/현지 재고 스냅샷을 저장한다.
- `campaign_main.evaluate_campaign_ending`: 복원/월 정산 중 `ending_busy` 및 진행 중 연출·필수 선택을 확인한다. 소유권을 잃은 흉년 선택은 기존 취소 처리를 거친다. 유효한 선택 효과와 결과 표시가 끝난 후 확정한다.
- 전투: 실제 `resolve_army_battle`의 손실, 점령, 수송 피탈, 생산 중단, 인물 이동, 훈련 정리 후 검사 예약. 플레이어의 기존 지연 전투 연출보다 뒤에 검사하도록 `_queue_ending_check`를 거친다. 월 중 AI 전투는 동기 월 정산이 끝난 뒤 검사한다.
- 월: 기존 내정→산업→수송→세입/수확/소비/손실→훈련/생산→부대 이동→AI→계절 처리→필수 사건 순서를 유지한 뒤 판정한다.
- 불러오기: 모든 원장·인물·부대·월 기록·선택 상태를 복원한 뒤 평가한다. UI 숨기기나 일부 도시 복원만으로 판정하지 않는다.
- `player_controls_all_provinces()`도 공통 순수 평가를 참조하도록 바꿨다. 기존 목표 메뉴에 실제 종료 규칙을 안내한다.

종료 후 지도 명령과 월 버튼을 잠그고, 실제 공통 모집·장비·훈련·부대 분할/이동/전투·업무 접수/취소·생산·수송·인사·외교·AI·계절 처리의 진입점도 `Ending.finished`로 차단한다. 국고의 `validate_national/post` 및 직접 세입/수확 처리도 차단하여 화면을 우회해 자원이나 예약 작업이 진행되지 않게 했다. 내부 저장 정규화/조회 함수는 복원을 위해 유지한다.

결과창은 기존 AcceptDialog/FileDialog를 사용한다. 승패 사유, 시나리오·국가, 종료 날짜/기간, 목표 점유, 도시·잔존 병력·군량·국고, **기록이 존재하는 범위**의 모집·전투 손실·정치 지출을 표시한다. 미기록 과거를 0으로 추정하지 않는다. 새 보상과 점수는 없다. 닫은 결과는 Menu의 ‘캠페인 결과’에서 다시 연다.

## 저장 호환과 오류 처리

저장 버전13. 기존 전체 전략 저장 안에 `campaign_ending`을 포함한다. 다른 원장의 수량·지출·완료 기록은 소급 수정하지 않는다.

- 새 캠페인 ID는 난수128비트다. 결과 ID는 캠페인 ID + 종료 월/판정/스냅샷의 해시다. 같은 종료 전 저장에서 **서로 다른 결말**로 갈라져도 결과 파일이 충돌하지 않는다. 이미 확정한 결과는 다시 만들지 않는다.
- 기본 전용 경로: `user://campaign_endings/<결과ID의 콜론을 하이픈으로 바꾼 값>.json`. 기존 수동 저장 경로 또는 다른 결과 ID를 가진 파일은 덮어쓰지 않는다. 종료 후 기존 상단 저장 버튼도 전용 종료 저장으로 연결한다.
- 임시 파일에 쓰고 flush 성공 후 rename하여 공개한다. 실패하면 성공 표시나 화면 이동 없이 결과를 유지한다. 재시도와 다른 위치 저장을 제공한다. 실패한 임시 파일이 생길 수 있으나 기존 정상 저장을 대체하지 않는다.
- 종료 저장은 결과를 복원하며 진행을 재개하지 않는다. 종료 전 저장은 그 저장의 진행 상태와 원장으로 돌아간다. 파일 선택을 취소하면 결과 화면으로 돌아온다.
- 종료 정보가 없는 구저장은 완전 복원 후 기본 조건을 한 번 추가한다. 파일 원문의 해시로 이관 캠페인 ID를 정해 반복 복원에도 동일하다. 당시 정확한 시작월은 없으므로 시나리오 1월 기준 경과를 **추정치로 표시**한다. 새 게임은 실제 선택한 시작월을 기록한다.
- 같은 실행 안에서 기존 선택 화면을 거쳐 새 캠페인을 생성하면 이전 결과·입력 잠금·예약 인사 확인창이 남지 않는다. 메인 화면 이동은 패배 판정 동작이 아니다.

기본 호스트 AppData는 이 실행의 파일 권한 제한으로 첫 쓰기에 실패했다. 실패 표시를 확인한 뒤 **검증 프로세스에만 APPDATA를 `<worktree>/.godot/ending-runtime`으로 지정**하여 실제 `user://` 전용 저장과 재시도를 실행했다. project.godot나 사용자 수동 저장 위치를 변경하지 않았다. 정상 사용자 AppData에 성공적으로 저장했다고 주장하지 않는다. 실제 생성한 독립 사용자 프로필은 [ending-runtime](../.godot/ending-runtime/)에 남겼다.

## 실제 실행 결과와 경계 실험 구분

**정상 상태 검증:** 실제 선택 12조합이 초기 승패 오판정 없이 진입하고 목표 그래프에 연결됨. 기존 정상 [패전 후 1,000명 준비 저장](../.godot/playability-results/defeat-replacement-ready.json)을 반복 복원해 인구·부대·장비·훈련·재정 보존 및 중간 목표가 최종 승리가 아님을 확인했다. 이번 [정상 시작 저장](../.godot/ending-results/1789375078-929/normal-before.json)을 불러온 뒤 월 진행, 결과→기존 선택 화면→새 캠페인→632년2월 진행을 실제 UI로 수행했다.

승리 분기의 기록된 신라 전투 손실9,455명은 첫 두 패전3,960+2,178과 마지막 공격3,317의 합이다. 패배 분기의8,800명은 같은 두 패전 후 북한산 잔존2,662명의 전멸을 포함한다. 도시를 테스트에서 넘겨도 다른 곳에 남은 인물/병력 기록이 자동으로 수복 명령을 얻지는 않는다. 실제 무거점 출발 공격의 소유권 검증 거절과 이동 중1,000명이 적 목적지를 수복할 수 없음을 별도로 실행했다.

필수 사건 경계에서는 목표 점유 상태와 실제 흉년 선택 대기를 구성했다. 저장/복원 뒤 실제 `force_requisition` 선택으로 금성 군량5,292→5,792(+500)가 한 번 적용되고 사건 결과 표시가 끝난 후 승리했다. 종료 저장 반복 복원·같은 선택·월 호출에서 +500이 재적용되지 않았다. 종료 후 직접9월 수확/세입/소비/손실 함수를 호출해도 자원 변화가 없었다.

GUI의 전투 연출 순서 검사는 기존 특정 인물 전투 컷신이 이 경계 전투에도 표시되도록 **테스트 메모리의 연출 트리거만** 연결했다. 실제 전투 판정에는 관여하지 않는다. 전투 연출이 활성인 동안 종료 확정·결과창이 보류되고, 닫은 뒤 승리창이 나오는 것을 확인했다. 이 컷신을 정상632년 역사 사건 발생으로 보고하지 않는다.

## 이번에 발견하고 수정한 회귀

1. 구저장 ID를 정규화 후 변한 자료에서 계산하면 반복 불러오기마다 ID가 달라짐 → 원본 저장 문자열 해시로 고정. 자원은 바꾸지 않음.
2. 종료 전 저장을 불러왔을 때 이전 지도 잠금이 남음 → 전체 복원 후 입력 잠금 재계산.
3. 결과창과 파일 선택창을 함께 독점 팝업으로 열 때 Godot 충돌 → 결과창을 숨기고 선택창을 열며 취소 시 결과 복귀.
4. 결과 버튼의 입력 처리 중 즉시 장면 교체 시 제거된 Window 입력 오류 → 기존 화면 이동을 지연 호출.
5. 캠페인 ID 하나에 단일 `final` ID만 붙이면 승리/패배 분기가 같은 파일을 사용함 → 결말 스냅샷 기반 결과 ID와 독립 파일. 이전 승리 파일이 패배 분기 후에도 남는지 확인.
6. 월 버튼만 막아서는 직접 수확/세입 콜백이 자원을 바꿀 수 있음 → 공통 처리 진입점도 차단.

입력 시험 초기에 결과창 내부 좌표를 루트 Viewport에 보낸 시험 코드도 수정했다. 결과창 버튼은 실제 키보드 포커스+Enter 입력, 기존 화면의 월/시작 버튼은 마우스 입력으로 검증했다. 파일 경로 선택은 FileDialog의 실제 `file_selected` 연결에 검증 경로를 전달했다. 물리 마우스로 파일 탐색기를 탐색한 검증과 구분한다.

## 미검증과 후속 사항

12조합의 정상 장기 **완주**는 하지 않았다. 마지막 목표/최종 거점의 경계와 실제 전투·사건·저장·새 판 연결을 검증한 것이다. 실제 무거점 수복·망명·부흥 전환, 역사적 군주 사망/자동 계승, 별도 기간형 생존 목표는 미구현이며 작동하는 기능으로 계산하지 않았다. 이번 기능을 위해 새 정치 제약이나 전투 규칙을 추가하지 않았다.

직전 검수의 AI 군수 계획 문제(모집 규모에 비해 무기 공급/훈련 완료가 뒤처짐)와 권력 집중의 실제 제약 부족, 값싼 포상으로 요구를 처리하는 문제는 그대로 후속 과제다. 가격을 바꿔 종료 구현에 섞지 않았다. 다음 우선 작업은 AI가 기존군 방어·모집·조달/수송·담당자·훈련을 하나의 준비 계획으로 연결하고, 동일 정상 조건에서 신규1,000명 완성 또는 구체적인 병목/대안을 기록하는 것이다. 정치 v2는 실제 불이익·명령권·회복 행동을 먼저 명세한 뒤 진행해야 한다.
