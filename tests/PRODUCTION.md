# 생산 기반 검증

현재 배치: 632·642년 시작 시나리오의 금관(`geumgwan`)에만 지역 제철 공급을
시범 적용합니다. 신라 기본 제련 기술은 새 게임에서만 설정하며 무료 시설·재고는 없습니다.
실제 캠페인의 월별 기록과 저장 호환 결과는 [IRON_PILOT.md](IRON_PILOT.md)를 참조하세요.

Godot 4.7.2에서 프로젝트 루트를 기준으로 실행합니다.

```text
godot --headless --path . --script res://tests/production_test.gd
```

테스트는 별도 프로세스의 캠페인 인스턴스에만 철·금·기술·시설을 설정합니다.
저장/불러오기 테스트는 OS 임시 디렉터리에 프로세스별 파일을 만들고 삭제합니다.
기존 `user://campaign_save_35_regions_v1.json`은 사용하지 않습니다.

생산 사례: 금 100, 철 10, 칼 0, 도검 제작 1, 군기감 1에서 한 달 처리하면
금 90, 철 8, 칼 1입니다. 이 수치는 생산 처리만 분리한 검증이며, 실제 턴 종료에서는
기존 월 상업 수입도 합산됩니다. 동일 월 재처리와 저장 복원은 추가 생산하지 않습니다.

임시 밸런스는 `production_data.gd`에서 관리합니다.
- 철 2 + 운영비 금 10 → 칼 1 / 월
- 도검 제작 연구: 금 200, 계절 정산 1회, 최대 1단계
- 필요 시설: 기존 군기감 1단계. 기존 비용 금 320와 계절 정산 2회는 변경하지 않음

국가 연구는 기존 `faction_research`, 시설은 `province_buildings`, 새 도시 재고는
`city_inventory`, 도시별 생산 설정은 `city_production`에 저장합니다.
`production_last_month`는 연도와 월을 합친 월 정산 식별자로 저장합니다.

게임 접근: 아군 도시 클릭 → 도시 카드 두 번째 줄 오른쪽 **생산** →
도검 제작 연구/군기감 건설 → 매월 생산 시작. 닫기 또는 Esc로 지도로 돌아옵니다.
연구·건설은 1·4·7·10월 진입 시 진행하고, 완료된 조건은 다음 월 생산부터 적용됩니다.
여러 도시의 운영비가 부족하면 도시 ID 순으로 조건을 확인하여 가능한 배치만 처리합니다.

새 게임·구형 저장의 철과 칼 기본 재고는 0입니다. 생산 시작은 예약이며,
재료 부족 시 차감 없이 보류합니다. 본게임 지역 제철 공급은 위 두 시작 시나리오의
금관에만 시범 적용했습니다. 국제 무역 및 전체 지역 특산품 배치는 미구현입니다.

## 품목 마스터 확장

`Samhan660_Trade_Production_Plan_v01.xlsx`의 품목목록 A5:L22, 지역고증 A5:I23,
출처 A5:G18을 데이터 정의로 옮겼습니다. 출처의 원문을 이번에 재검증한 것은 아니며,
품목의 존재/사용 근거와 지역 생산 후보 근거를 분리했습니다. 모든 신규 지역 배치는
`regional_placement_confirmed=false`입니다. 문서의 지시문·후속 단계는 자동 실행하지 않습니다.

기본 화면은 보유품과 현재 레시피 투입/산출품을 표시합니다. **전체 품목 보기**를
켜면 기본 품목의 경제·군사 역할과 비활성 확장 후보를 볼 수 있습니다. 다시 끄면
기존 연구·건설·가동/중지 화면으로 돌아옵니다. 역할 설명은 효과 구현이 아닙니다.

저장 버전 4와 기존 iron/sword ID를 유지합니다. 조회 별칭 weapons는 sword로만
해석하며, 새로운 weapons 장부를 만들지 않습니다. 비정상/외부 입력에 별칭만 있으면
sword로 옮기고, 둘 다 있으면 기존 sword 값만 우선합니다(합산하지 않음).
grain은 food_stock이 유일한 원장입니다. 잘못 들어온 city_inventory.grain은
합산 없이 제거하며 food_stock은 변경하지 않습니다. 신규 기본 품목은 0으로
보정하고 확장 품목의 기본 재고는 만들지 않습니다. 조회용 inventory 사전은
저장 원장과 분리되어 있습니다.

엑셀 `생산연결!F14:G14` 및 `밸런스실험!B23:G23`의 무기 제안은
철 1 + 목재 1 + 금 3 → 무기 1입니다. 이를 적용하지 않고 기존
철 2 + 금 10 → 칼 1을 유지합니다. 도검 제작/군기감 비용과 기간도 유지합니다.
품목 마스터 확장 당시에는 새로운 공급·레시피·자원 배치·군대 효과를 추가하지 않았습니다.

## 철 공급 공정 (금관 시범 배치)

`iron_supply_data.gd`의 `CANDIDATES`는 출처 URL, 편년, 근거 종류, 확인 사실,
추정·불확실성, 채굴 확인, 배치 확정을 분리합니다. 김해 우계리는 geumgwan의
검토 후보이며 광산 또는 632~670년 가동 확정 자료로 취급하지 않습니다.
실행 허용표 `SCENARIOS`는 별도이며 632·642년 시작 시나리오의 금관만 허용합니다. 스키마는
`scenario_id -> city_id -> {allowed, placement_confirmed, candidate_id}`입니다.
두 허용 플래그가 모두 true인 정확한 시나리오·도시 조합만 공급할 수 있습니다.
후보 존재, 국가 기술, 시설 완공만으로는 이 조건을 우회할 수 없습니다.
허용표는 세이브에서 읽거나 쓰지 않고 현재 코드 데이터로 판단합니다.

- 공정 `iron_supply`: 국가 기술 `basic_smelting` 1 + `smelter` 1 + 지역 허용.
- 임시 밸런스: 금 6 → 기존 `iron` 2, 도시당 월 최대 1배치.
- `smelter`: 건설 금 240, 기존 계절 정산 2회, 최대 1단계. 기존 건설 큐 재사용.
- `basic_smelting`: 632·642년 새 캠페인의 신라만 시작 시 1, 나머지는 0.
  연구 시작 불가. 역사적 능력의 부정이 아닌 모델 설계이며 제련 효율 개선 연구는 미구현.
- 채취·원료 조달, 선광·배소, 연료 조달, 제련·정련을 추상화합니다.
  철광석·숯 품목, 별도 철 장부, 군대 능력치 효과는 없습니다.
- 기존 `iron_sword`, `swordsmithing`, `forge`와 비용·산출은 그대로 유지합니다.

월 처리 순서는 **도시 ID 오름차순 → 해당 도시 철 공급 → 해당 도시 칼 제작**입니다.
예를 들어 A 공급 → A 제조 → B 공급 → B 제조이며 모든 도시의 공급부터 하는
순서가 아닙니다. 국가 금은 성공한 각 배치만큼 순서대로 차감합니다.
공정마다 모든 조건을 먼저 검증하고 일괄 반영하므로 공급 성공 후 제조만 보류되면
공급된 철은 남습니다. 기존 월 상업·수확·병력 군량·손실 → 생산 → 치안·이동·AI →
계절 전략 처리의 호출 순서를 변경하지 않았습니다. 계절 처리에서 끝난 연구·시설은
다음 월 생산부터 적용됩니다.

공급과 제조 모두 기존 `production_last_month`를 공유합니다. 월 시도 전에 기록하며
성공·보류·중지 모두 재시도하지 않습니다. 같은 월에 돈을 추가하거나 시작/중지하거나
저장 후 불러와도 추가 처리되지 않습니다. 건너뛴 월의 생산을 몰아서 실행하지 않습니다.
현재 월 처리 API는 기존과 같이 플레이어 국가 금을 받아 한 번 실행하며 AI 생산 자동화는
추가하지 않았습니다.

저장 버전은 4를 유지합니다. `city_production[city_id]`에 기존 `iron_sword` 주문과
새 `iron_supply` 주문이 각각 `{enabled, owner, status, reason}`으로 저장됩니다.
이전 저장에 공급 주문이 없으면 중지 상태로 추가하며 철·칼·기존 주문 소유자·월 기록은
유지합니다. 불러오기/정규화는 재고 지급·생산·밀린 월 정산을 실행하지 않습니다.
소유권이 일치하지 않는 활성 주문은 정규화 시에도 중지합니다.
플레이어/AI 점령 경로는 즉시 두 주문을 중지하여 같은 달 재점령도 자동 재개되지
않습니다. 시설·재고는 도시, 연구는 원래 국가에 남으며 새 소유자가 다시 명령해야 합니다.

화면 접근: 아군 도시 → 도시 카드 **생산** → 상단 선택 **철 공급 / 칼 제작**.
선택 변경은 표시만 바꾸며 다른 주문을 취소하지 않습니다. 모든 기술·시설 조건별
표시/명령 버튼을 만들며, 전체 품목 보기·닫기·Esc는 유지합니다.
미적용 도시/시나리오에서는 철 공급 시작과 제철시설 건설이 비활성인 것이 정상입니다.

`production_test.gd`는 기존 84개 검증과 `iron_supply_test.gd`의 추가 검증을 함께
실행합니다. 기존 기대값 중 공정 수(1→2), 공급 미구현 안내(배치 미적용으로 변경),
소유권 변경(보류→중지)만 새 요구사항에 맞췄습니다. 허용표·기술·시설·금은 별도
테스트 프로세스에만 주입하며 본게임 지급 버튼은 없습니다.

| 생산 직전 금 / 철 / 칼 | 생산 직후 금 / 철 / 칼 |
|---|---|
| 100 / 0 / 0 | 84 / 0 / 1 |
| 15 / 0 / 0 | 9 / 2 / 0 (칼 제작 보류) |
| 5 / 0 / 0 | 5 / 0 / 0 (두 공정 보류) |

검증: 지역 허용·배치 확정·시나리오·기술·시설·소유권 차단, 독립 시작/중지,
월 재호출·재시작·JSON/실제 저장 복원, 구형 v4 주문 보존, 도시별 공유 금 순서,
건설 비용·중복 명령·완공·최대 단계, 실제 플레이어/AI 점령 경로, 본게임 5개
시나리오 전체 도시 비활성, 기존 품목/군량/계절 처리/UI 회귀를 포함합니다.
