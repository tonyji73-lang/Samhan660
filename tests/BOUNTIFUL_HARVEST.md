# 9월 풍년 이벤트 연동 v1

기반 `feature/cutscene-framework-v1` / `6b426ec`.
작업 브랜치 `feature/cutscene-event-integration-v1`. commit/push/merge 없음.

## 확정 규칙과 구현 선택

- 9월 정상 수확 직후, 플레이어의 활성 영지 중 실제 수확량이 양수인 곳만 판정한다.
- 확률 = **4% + 농업 × 0.04%p + 치안 × 0.04%p**, 최대 **12%**.
  농업·치안은 0~100으로 제한한다. 세부 증가 기울기는 이번 구현의 밸런스 선택이다.
  `bountiful_harvest.gd`의 상수로 관리한다.
- 고정 난수: 문자열 `bountiful_harvest:v1|시작시나리오ID|연도|영지ID`의 SHA-256,
  앞 8자리 16진수를 정수로 변환한 뒤 `% 10000`으로 0~9999 값을 얻는다.
  확률을 basis point(4%=400, 12%=1200)로 비교한다. 전역 RNG·현재 시각·저장 횟수와 무관하다.
- 영지 ID 오름차순으로 검사해 첫 통과 영지 **한 곳**만 보상한다. 여러 영지가 통과해도
  한 해 최대 한 곳이다. 이 순서에 따른 우선권은 의도적인 결정 규칙이며 균등 추첨은 아니다.
- 풍년 실패도 연간 기록을 남긴다. 판정 뒤 점령·능력치 변화로 같은 해를 재판정하지 않는다.
- 보너스 군량 = 기존 공식으로 이미 계산한 **해당 영지의 9월 수확량 × 25%, 정수 반올림**.
  치안은 +3, 최대 100. 실제 증가량 1~3은 그대로 표시하고 0이면 **치안 100 · 최대치**로 표시한다.
  이 문구 치환은 결과 화면만 처리하며 실제 증가량과 저장 기록은 0을 유지한다.

기존 45% 징수 → 9월 70% / 10월 30% 공식과 반올림 순서를 변경하지 않았다.
기존 군량 소비·저장손실·치안 회복·생산·연구·건설·교역·AI 순서를 유지한다.
풍년 치안 증가에 따른 이후 경제 효율 변화와 보너스 군량의 정상 저장손실도 기존 공식대로다.
풍년 군량은 `food_stock`에만 더하며 생산 재고에는 별도 장부를 만들지 않는다.

## 게임과 UI 연결

`_on_end_turn_button_pressed()` → `process_seasonal_harvest()`에서 기본 수확 계산
→ `BountifulHarvest.apply_september()`에서 연간 기록과 보상 동시 확정
→ 나머지 기존 월 정산 완료 → `_present_harvest_event()` → 기존 `EventPresentation.play()`.

동적 지역명·추가 군량·실제 치안 증가량을 기존 JSON/기존 WebP에 전달한다.
occurrence ID는 `bountiful_harvest:v1:시나리오ID:연도:영지ID`다.
건너뛰기·자동 진행·전체/중요/최소 설정은 연출만 제어하며 보상 함수를 호출하지 않는다.
침공 경보와 김유신–계백 전투 연결, 지도·세력 데이터, 생산/철 공급 소스는 수정하지 않았다.

## 저장 호환

기존 저장 버전 4와 기존 필드를 유지하고 선택 필드 `harvest_events`만 추가한다.
`version: 1`, `years: {연도: 판정/적용 기록}` 구조이며 연도 키는 문자열이다.
성공 기록에는 영지 ID/이름, 기본 수확량, 실제 추가 군량/치안, 판정값/확률과 occurrence ID를 보관한다.
실패 기록도 보관하며 화면 완료 기록과 보상 적용 기록을 구분한다.

- 불러오기는 기록만 복원한다. 풍년 판정·보상·컷씬을 실행하지 않는다.
- 8월 이전 구형 저장에 필드가 없으면 빈 기록으로 시작하여 미래 9월에 정상 판정한다.
- 9월 이후 저장에 현재 연도 기록이 없으면 이미 정산한 해로 표시한다.
  9월에 들어가는 턴에서 수확을 정산하는 기존 구조에 맞춰 소급 보상을 차단한다.
- 8월 저장을 반복해서 불러와도 동일 시나리오·연도·영지·상태에서는 같은 결과다.
  9월 전의 정상 내정 명령으로 농업·치안을 바꾸면 확률은 달라질 수 있으나 고정 판정값은 바뀌지 않는다.

이 기능의 연간 중복 방지는 **풍년 추가 보상**에 적용한다.
기존 기본 수확 함수는 정상 월 진행에서 한 번 호출하는 계약을 유지하며 별도의 기본 수확 재정산 기능을 추가하지 않았다.

## 직접 확인한 본게임 순서

1. 새 캠페인 → **632년 → 신라 → 역사적 게임플레이 / 보통 → 시작**.
2. 다른 명령 없이 **턴 종료 7회** → 632년 8월. 필요하면 여기서 저장한다.
3. 턴 종료 1회 → **632년 9월, 국원소경 풍년**.
4. 다음 → **군량 +512 / 치안 100 · 최대치**. 치안은 정상 월 회복으로 이미 100에 도달해 있다.
5. 건너뛰기 후 군량 확인. 8월 저장을 다시 불러오거나 메뉴의 연출 수준을 최소로 바꿔
   같은 턴을 진행해도 동일 결과다. 9월 저장 재개는 보상·연출을 다시 실행하지 않는다.

본게임 검증은 정상 새 게임, 턴 종료, 저장/불러오기, 메뉴 명령만 사용했다.
