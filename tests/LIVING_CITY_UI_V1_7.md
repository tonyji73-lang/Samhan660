## 실제 데이터와 표시 원칙

- `noble_politics.gd`의 시나리오 정의에는 신라 632년·642년 집단이 있다. 집단 이름·회원 수·인물은 이 데이터를 그대로 사용한다. 역사적으로 확정된 파벌이라는 표현을 사용하지 않는다.
- 백제·고구려는 집단 정의가 없으므로 **집단 설정 없음**과 실제 해당 국가 소속 인물을 표시한다. 신라 집단을 차용하거나 새 집단을 만들지 않는다. 기존 인사 기능은 작동한다.
- 개인 충성·집단 협력은 각각 0~100 상태값이다. 영향력은 기존 `Core.influence()`의 **지휘 병력 비중×60 + 태수 민간 인구 비중×40**인 점수이며 확률이 아니다. 관직·도시·지휘 병력·업무와 분모를 함께 설명한다. 업무 자체의 영향력 가산을 만들지 않는다.
- 군주 초상과 실제 국고·전체 병력·기존 `Army.attack_units()`로 조회한 출정 후보 병력을 표시한다. 후보 병력은 실제 출정 확정 가능량이라는 보장이 아니며 군량 등 명령 조건은 별도 확인한다. 독립 왕권 점수를 만들지 않는다.
- 협력·충성 변화는 기존 이력의 날짜·이유·전후 값만 표시한다. 기록 없는 불만 원인은 추정하지 않는다. 인물의 위치·활동 상태·관직·지휘 병력·업무도 기존 레지스트리에서 읽는다.
- 요구 수락/포상/거절 및 권력 보상/기한 보장/강제 회수/철회/후임 재지정이 연결되어 있다. 선택은 조회이며 빨간 확정 버튼에서만 실제 함수를 실행한다.
- 즉시 결과는 `Personnel.resolve()`, `Power.resolve()/retarget()`를 격리 복사본에 실행한 결과다. 관계 변화·국고 차이·제약 상태를 읽으며 별도 비용 수식을 만들지 않는다. 확정 시 원본 처리 함수가 현재 자격과 자원을 다시 검사한다.
- 기한 보장은 현재 즉시 적용되는 변화와 인계 예정 날짜를 표시한다. 미래 인계 반응은 기존 설명을 안내하며 그때의 후임 자격·상태를 다시 검사한다고 명시한다. 미래 상태가 보장된 예측처럼 표시하지 않는다.
- 강제 회수 시 영향 인물·부대, 진행 훈련, 해당 도시 진행 업무와 가동 예약을 표시한다. 저장에 진척 수치가 없으면 임의의 0을 만들지 않고 기록 없음으로 표시한다. 제약 기간·도시 작업량 배율은 실제 결과 상태를 사용한다.

## 환경 및 재현

Windows 11, NVIDIA GeForce RTX 4060 Laptop GPU, Godot `4.7.2.stable.official.ed1daf0bf`, D3D12 Forward+. GUI는 실제 Godot 렌더링 창에서 입력 이벤트와 버튼 클릭을 실행했다. 1280×720과 1920×1080은 실제 렌더링 캡처 크기다. Windows DPI 변경 검사가 아니다.

원본 캐시와 저장을 보호하기 위해 검수 사본을 사용했다:

```text
%LOCALAPPDATA%/Temp/Samhan660_V1_7_20260930/source
%LOCALAPPDATA%/Temp/Samhan660_V1_6_1_20260930/tools/Godot.exe
```

검수 사본에는 현재 코드와 자산, 필요한 기존 테스트를 복사했다. 사본에만 이전 Windows export QA autoload를 제외했다. 원본 `project.godot`는 변경하지 않았다. 재현 시 `normal-concentrated.json`은 기존 `.godot/noble-power-results/normal-concentrated.json`을 사본의 아래 결과 폴더로 복사한다. GUI 테스트는 기존 데이터를 덮어쓰지 않도록 사본에서 실행한다.

```powershell
$runtime = Join-Path $env:LOCALAPPDATA 'Temp/Samhan660_V1_7_20260930/source'
$engine = Join-Path $env:LOCALAPPDATA 'Temp/Samhan660_V1_6_1_20260930/tools/Godot.exe'
& $engine --path $runtime --script res://tests/living_city_ui_v1_7_play.gd --log-file "$runtime/tests/living_city_v1_7_review/run.log"
# 위 프로세스가 종료되어 테스트 저장 생성이 끝난 뒤 실행
& $engine --path $runtime --script res://tests/living_city_ui_v1_7_edges.gd --log-file "$runtime/tests/living_city_v1_7_review/edges.log"
& $engine --headless --path $runtime --script res://tests/noble_politics_test.gd
& $engine --headless --path $runtime --script res://tests/noble_power_constraints_test.gd
```

## 발견·수정 및 검사상의 구분

- 저장 전환 후 화면을 다시 열 때 이전 현안 ID를 잠시 조회하는 오류가 추가 검사에서 발생했다. 화면 진입 시 현안/대응 목록과 미리보기 모델을 초기화하여 수정하고 동일 전환 검사로 재확인했다. 정치 저장 구조는 변경하지 않았다.
- 초기 GUI 검사 자체의 스크롤 부모 경로·레이아웃 대기 오류를 수정했다. 정상 요구 생성에 사용할 수 없던 636년 상태 대신 정상 642년 임명 흐름을 사용했다. 초기 실패 결과를 최종 성공 수에 가산하지 않았다.
- 최종 GUI 로그 및 두 회귀 로그에서 SCRIPT ERROR/ERROR/FAIL을 확인했다. `git diff --check`도 확인했다. 기존 파일의 CRLF 안내는 Git 설정 안내이며 코드 오류가 아니다.

1. V1.7 Windows 실행본 갱신 후 실제 종료·재실행을 포함한 요구/인계 저장 복원과 패키지 자산 포함 여부 확인. 이번은 프로젝트 GUI 검증이며 새 배포 EXE를 만들지 않았다.
2. 다른 Windows PC와 실제 DPI 125%·150%의 텍스트/클릭/키보드 검수. 이번에는 수행하지 않았다. 모든 OS 키보드 조합·팝업 목록 방향키·접근성 도구까지 검증한 것은 아니다.
3. 백제·고구려 정치 집단은 미연결이 아니라 원래 데이터 미정의 상태다. 별도의 시나리오 설계 승인 없이 집단·정치 규칙을 추가하지 않는다. 기존 실제 인사 연결만 제공한다.
4. 진행 중 건설·생산·훈련이 동시에 존재하는 모든 조합의 정치 대응 GUI는 전수 검사하지 않았다. 기존 권력 회귀 검사를 실행했지만 이를 모든 업무 조합의 시각 검증으로 확대 해석하지 않는다. 부족한 국고 등 기존 계산의 거부 사유를 UI에 연결했으나 모든 거부 분기의 새 화면을 각각 캡처하지 않았다.
