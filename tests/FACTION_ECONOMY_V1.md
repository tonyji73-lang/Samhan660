## 원장과 초기값

`strategy_state.faction_economy.accounts[faction_id]`가 금의 유일한 원장이다. 각 계정의 opening/balance/income/expense와 entries의 개별 금 증감, receipts의 중복 방지 키를 저장한다. income/expense는 입출금 집계이며 현재 금의 별도 원장이 아니다. `factions`는 표시 이름을 기존 인터페이스와 연결하는 ID→이름 표다. 단순 조회는 계정을 만들거나 초기 금을 지급하지 않는다.

`campaign.gold`는 플레이어 계정의 조회·호환 쓰기 속성이다. 호환 쓰기는 차액을 `compatibility` 거래로 남긴다. `_legacy_start_gold`는 초기화/구형 저장 읽기용 임시값이며 캠페인 원장이 있으면 조회하지 않는다. 저장 최상위 gold도 호환용 투영값이고, 원장이 있는 저장은 원장을 우선한다.

현재 시나리오에 국가별 금 설정은 없었다. 이후 `starting_gold`, 그다음 `gold` 설정을 지원하며, 없는 AI는 **새 게임 또는 원장 없는 구형 저장의 변환 시 1,000**으로 초기화한다. 이는 검증용 게임 값이며 과거 AI의 누적 재산을 복원한 값이 아니다. 플레이어는 기존 쉬움 1,500 / 보통 1,000 / 어려움 800을 유지하고 구형 저장은 저장된 플레이어 금을 정확히 승계한다. 월 진행·점령·조회에서는 재초기화하지 않는다.

기존 경제 범위인 `Korea35Data.PROVINCE_IDS` 중 등록 국가가 소유하는 도시를 공통으로 조회한다. 태수 효과·월 세입·수확·소비·창고·AI·생산·모집에서 같은 범위를 사용한다. 실제 월 경제는 기존 비활성 국가 제외 규칙도 유지한다. 당·왜·초원 국고는 같은 구조로 존재하지만 미구현 본토/유목 경제와 새로운 생산 AI를 추가하지 않았다.

군량은 각 `provinces[city_id].food_stock`만 변경한다. `campaign.food`와 국가별 군량 합계는 조회용이다. `food_entries`는 모집·출정 등 명령이 실제 지불한 지역 군량의 전후 기록이며 재고 원장이 아니다.

## 처리 순서와 기능별 비용

1. 사건/모달이 열려 있으면 월 진행을 막는다. 정상 월 진행은 달력을 한 달 전진한다.
2. 기존 내정 업무를 완료·중단하고, 도시 세입을 결산 시점 소유 국가에 지급한다.
3. 기존 9월 70% / 10월 30% 수확, 국가 수취율 45%, 태수 계수, 주둔군 소비와 창고 손실을 적용한다.
4. `Production.process_all`이 국가마다 유효 생산 명령을 처리한다. 국가 안에서는 도시 ID 순서, 원료 생산→제조 순서다.
5. 기존 치안·이동 처리를 거친 뒤 AI가 공통 모집 명령과 기존 공격 판단을 실행한다.
6. 계절 전환이면 건설·연구·통상을 처리하고, 통상 결과의 모든 대상 국가에 금을 정산한다. 기존 봄 인물 성장 처리는 유지한다.
7. 화면 갱신과 기존 사건 표시/선택 대기로 연결한다.

세입은 기존 도시 tax_month와 거래 키, 수확은 harvest_month를 사용한다. 소비·창고·AI·계절 처리는 `phase_months`로 같은 월 재호출을 막는다. 생산은 `production_months[faction_id]`를 사용한다. 옛 `production_last_month`는 호환 정보로만 유지하며 다른 국가 실행을 차단하지 않는다. 구형 전역 생산 기록은 그 저장의 플레이어 처리 이력으로 승계하고, 다른 국가의 과거 처리를 했다고 추정하지 않는다. 월을 건너뛰어도 누락된 과거 생산을 소급 지급하지 않는다.

내정은 접수 시 금 100을 실제 부담 국가에 한 번 청구하고 job.payer_faction_id를 저장한다. 정상 취소만 그 국가에 100을 한 번 돌려준다. 도시 상실/자격 상실 중단은 기존처럼 환불하지 않는다. 건설·연구는 기존 견적/권한 검증 후 원장에 지불하고 큐에 payer_faction_id/cost_paid를 남긴다. 생산은 기술·시설·지역·재료·소유권·잔액을 검증한 뒤 한 배치를 함께 반영한다. 점령 시 기존 생산 중단 규칙을 유지한다.

외교는 기존 사절 ID·가용성·행동 제한과 원장 잔액을 검증하고 실제 실행 결과의 gold_cost를 부담 국가에 청구한다. 현재 풍년/흉년 및 사건 선택은 금을 증감하지 않고 도시 군량·치안·사건 기록을 변경하므로 그 동작을 보존했다. 사절·이동·출정과 내정의 장수 충돌 규칙도 유지한다.

## 모집과 출정

모집 100명 = 금 15 + **해당 도시** 군량 20. 기본 수량 1,000명은 금 150 / 군량 200이다. 최소 100, 100명 단위만 허용하며 플레이어 화면의 견적과 확정은 같은 검증 함수를 호출한다. 기존 기본 모집에는 별도의 장수 선임 조건이 없으므로 새로운 조건을 추가하지 않았다. 기존 별도 병종 실험용 백엔드/전투 체계는 변경하지 않았다.

AI의 기존 난이도별 충원량은 목표/상한으로 사용한다. 금·군량으로 가능한 100명 단위 수량까지 줄여 모집하고, 최소 단위도 불가능하면 비용과 병력 변화 없이 실패 이유를 기록한다. 목표 0도 최소 100명으로 올리지 않는다. 도시별 recruitment 기록에 요청량·실제 인원·금·군량·전후 병력·실패 이유를 저장한다. 공격을 시도한 도시도 충원 합계에 포함한다. AI에 월별 국고 보충은 없다.

플레이어/AI 공격 모두 기존 출정 군량 500을 실제 출발 도시에서 지불한다. 499이면 전투 및 장수 활동 기록을 바꾸기 전에 거절한다. 지휘관의 공통 action_available/validate_attack_staff 제한과 방어 규칙은 유지한다. 거리별 보급비나 새 전투 공식을 추가하지 않았다.

비용을 낸 모집 병력이 병종 캐시와 어긋나지 않도록 모집 성공 직후 기존 `strategy.reconcile_unit_roster`를 호출한다. 삼국에서 모집→저장→3회 복원 후 도시 병력과 병종 합계가 일치함을 검증했다. 다른 기존 전투/손실 경로 전체의 캐시 개편은 별도 과제로 유지한다.

## 저장 호환과 남은 범위

구형 저장의 없는 AI 자산·거래 이력은 추측하지 않는다. 원장 변환 시점의 플레이어 저장 금과 AI 검증용 시작 금이 opening이며, 그 뒤의 입출금부터 기록한다. 같은 구형 파일을 다시 읽는 것은 그 저장 시점으로 복원하는 것이며 현재 원장에 초기 금을 더하는 처리가 아니다. 원장이 포함된 새 저장에서는 초기화가 즉시 반환되어 잔액과 완료 기록을 그대로 유지한다. 기존 name 기반 인물/장수 상태는 앞선 OfficerRegistry 변환 경로를 그대로 사용한다.

진행 중 내정 업무의 비용 부담 국가 ID·지불액·refund·status, 생산의 국가별 월 처리 기록, 소비/창고/AI/계절 처리 기록과 금 거래 영수증을 함께 저장한다. 저장을 읽는 함수 자체는 세입·생산·모집을 실행하지 않는다. 사건 선택 대기 중 저장도 이후 선택 및 월 진행에서 이미 처리한 월 경제를 다시 적용하지 않는다.

기존 문제와 이번 수정 범위를 구분한다. 공용 금·무료 AI 충원·전역 생산 처리 누락은 이번에 해결했다. 모집 후 병종 캐시는 이번 비용·저장 기능에 필요한 범위에서 동기화했다. 다른 전투 경로 전체의 캐시 일원화, 별도 병종 모집 백엔드 개편, 본토·유목 경제, 신규 생산/모집 AI 전략, 수송/거리 보급은 구현하지 않았다. 이번 검증에서 미해결된 새 회귀는 발견되지 않았다. 다음 생산·수송 연결 작업을 시작할 수 있다.

## 다음 작업의 공통 연결 지점

| 조회/명령 | 용도 |
|---|---|
| `Economy.resolve(state, reference)` | 기존 국가 표시 이름 또는 ID를 원장 faction_id로 연결 |
| `Economy.balance(state, faction_id)` / `campaign.get_faction_gold(id)` | 초기 지급 없이 현재 국고 조회 |
| `Economy.city_ids(state, provinces)` | 현재 경제 대상 도시 범위 |
| `Economy.validate_national(state, actor, payer, gold_cost)` | 명령 국가·부담 국가·국고 가용성 검사 |
| `Economy.validate(state, provinces, actor, payer, city, gold_cost, food_cost)` | 위 검사와 경제 범위·현재 소유권·그 도시 군량 검사 |
| `Economy.post(state, id, delta, reason, month, city, token)` | 승인된 결과의 금 수입/지출 및 중복 방지 키 기록 |
| `Economy.spend(...)` | 공통 검증 뒤 금·지역 군량을 함께 차감. 실패 시 둘 다 불변 |
| `Recruitment.quote(...)` / `affordable(...)` / `execute(...)` | 동일 수량 비용·가용 100명 단위 상한·실제 모집과 기록 |
| `campaign.get_recruitment_quote(city, amount)` / `request_recruitment(city, amount)` | 플레이어 UI용 권한 제한 명령 |
| `campaign.recruit_for_faction(id, city, amount)` | 캠페인 내부 AI용 공통 모집 + 기존 병종 캐시 동기화 |
| `Production.process_all(...)` | 전 국가 유효 생산 명령 월 처리 |
| `Domestic.quote/start/cancel/process` | 기존 공통 인물 ID 업무 + payer_faction_id 원장 지불/환불 |
| `campaign.claim_economy_phase(phase)` | 전체 국가를 한 번에 처리하는 경제 단계의 월 중복 방지 |

`post`와 내부 AI 함수는 신뢰된 시뮬레이션 경로용이다. 새 UI나 AI 기능은 actor/payer·도시 소유권 검증 없이 호출하지 말고 validate/spend 또는 해당 명령 래퍼를 이용한다. 새 수송도 국가 군량 합계에서 빼지 말고 명시한 출발 도시의 food_stock만 변경해야 한다. 반복 실행될 명령에는 안정적인 명령 ID 기반 token을 사용한다.

## 파일과 실행 산출물 구분

직접 수정한 소스·테스트·문서는 위 변경 표에 한정된다. `.godot/economy-baseline-20260910-162533`은 에이전트가 만든 시작 사본이다. `.godot/economy-results`의 JSON 저장, evidence.json, PNG 캡처와 economy 로그는 테스트/실행 산출물이다. 이들은 Godot가 자동으로 수정한 소스 파일이 아니다. Godot의 가져오기·셰이더·캐시 파일은 `.godot` 아래의 자동 생성물로 구분한다. 이번 작업으로 신규 소스 `.uid`는 추가되지 않았다. 보호 파일에 대한 Git diff와 시작 해시 비교, `git diff --check`를 확인했다.
