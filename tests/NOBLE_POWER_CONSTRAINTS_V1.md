## 적용 범위와 거래

기존 정치 설정이 있는 **632년 신라**에만 적용한다. 이미 정의된 왕실·군사 귀족·문치 귀족 집단을 사용하고, 새 가문이나 역사 소속을 만들지 않는다. 비왕실 집단의 영향력 `I >= 40`이고 실제 지휘 병력 또는 태수 관할 민간 인구가 감소하는 왕명 인사에 적용한다. 단순 명칭 변경, 같은 실권을 유지하는 분할·이동, 전사·점령 같은 비자발적 상실은 구별한다. 다른 연도/국가는 기존 공통 인사 경로를 유지한다.

`Power.quote()`는 복제한 공통 명부·부대 원장에서 전후 영향력과 실제 회수 기반을 계산한다. `intercept()`는 비용이나 인사 효과를 적용하지 않고 고유 `handover:N` 협의를 만든다. 최초 견적의 영향력·감소량·충성·야망·세입·대상 부대를 저장한다. `resolve()`는 최신 소유권·생존·소속·현지 가용성과 국고를 다시 검사한 뒤 공통 인사/부대 명령을 실행한다. 거래 실패 시 협상비를 차감하지 않는다.

| 선택 | 실제 비용·인계 | 퇴임 충성/집단 협력 | 추가 차질 |
|---|---|---|---|
| 보상 | 금 `ceil10(max(100, M*D/100*(1+I/100)*F))`, 즉시 | -4 / -2 | 없음 |
| 기한 보장 | 금 0, 기한까지 기존 담당 유지 | 인계 시 -4 / -2 | 없음 |
| 강제 회수 | 금 0, 즉시 | -20 / -12 | 도시 2회 결산 또는 부대 1회 월 처리 |

`F=clamp(1+(야망-충성)/200,0.75,1.25)`. M은 최근 최대 3개 완료 월의 원장상 도시 세입과 양의 통상 세입이다. 일회성·환불·약탈은 제외한다. 기록이 없으면 공통 도시 세입 견적을 사용하며 근거를 견적에 남긴다. 기한은 I 40~59에서 2개월, 60 이상에서 3개월, 충성 80 이상 -1, 야망 80 이상 +1, 최종 1~4개월이다. 여러 집단이 실제로 권한을 잃는 거래는 집단별 금액을 합산하고 가장 긴 기한을 사용한다.

신임자 효과는 기존 임명 규칙·보상 간격을 유지하여 한 번만 적용한다. 기존 자동 퇴임 효과를 억제한 뒤 선택에 따른 퇴임 효과를 한 번 기록한다. 비용 원장 사유는 `politics:power_compensation`이므로 기존 종료 결과의 정치 지출 집계에도 포함된다.

## 월 처리·차질·우회 방지

1. 기존 월 진입/수송 단계 이후, 내정 결산 전에 `Power.begin_month()`가 기한 만료와 대상 유효성을 처리한다.
2. 내정 → 건설/연구 → 도시 세입·수확·주둔 소비 → 훈련·생산 등 기존 월 순서를 유지한다. 태수 차질은 기본 세입/수확을 지우지 않고 태수 배율만 1로 한다. 건설 및 시설 생산 작업량에 0.8을 한 번 적용한다. 연구·개발 상승량에는 곱하지 않는다.
3. 실제 배치가 생산된 경우에만 기존 원료·금 비용을 낸다. 남은 진척과 시설별 능력 공유는 기존 생산 원장을 사용한다.
4. AI 월 행동과 해당 월 효과 적용 뒤 `Power.finish_month()`가 잔여 횟수를 줄인다. 생성 월에는 줄이지 않고 효과별 마지막 처리 월로 재호출을 막는다.

부대 차질은 공격 참여 원본 목록과 훈련 견적에 연결했다. 해당 부대는 방어 전투력·군량 유지에서 빠지지 않는다. 훈련 중에도 차질 기간에는 금/훈련도를 적용하지 않고 이후 월에 재개한다. 강제 회수 뒤 아군 거점 이동은 허용한다. 분할 자식과 합류 결과가 차질을 이어받는다.

협의 중 대상 부대의 편성을 바꾸는 조작은 이유를 표시하고 제한한다. 같은 지휘권을 유지하는 일반 분할은 지휘관 ID도 보존한다. 지휘 병력의 일부를 지원하려면 먼저 분할한 뒤 해당 부대를 선택한다. 전체 병력을 넘기는 견적을 부분 인계에 잘못 적용하지 않기 위한 명시적 제한이다. 지휘관 없이 병력을 지원하거나 집중 군권 병력을 해산하는 명령도 먼저 인계 협의를 거친다. 장수 이동과 태수 해임도 공통 명령에서 막는다.

기한 중 후임이 부적격이면 `successor_needed`로 남긴다. 후임 재지정은 기다린 기한을 유지한다. 철회에는 인사 보상·불이익이 없다. 점령·전사·소속 상실은 유효성을 정리하며 비용을 환불하거나 새 소유국에 청구하지 않는다. 이미 이동한 지휘 부대는 최초 거점이 아니라 현재 위치와 실제 소속을 검사한다.

## AI·저장·회귀 실행

AI는 실제 `run_enemy_ai_turns()`에서 공통 명령을 사용한다. 현재 태수보다 정치가 10 이상 높은 현지 후보를 검토하며, 진행 중 협의가 있으면 새 협의를 만들지 않는다. 새 검토 간격은 6개월, 같은 월 재호출은 차단한다. 능력 개선이 없으면 철회, 협상비 지출 후 금300 여유가 있으면 보상, 그렇지 않으면 기한 보장을 우선한다. 비전선의 큰 통솔 개선은 강제를 허용하되 전선 공격 지연을 피한다. 기존 귀족 요구로 생성된 지휘관 협의도 같은 선택 경로를 사용한다. 군수 계획의 위협 계산은 공격 가능한 실제 부대를 사용하고 건설 전망은 임시 차질의 종료를 반영한다.

정상 집중 저장의 **플레이어만 백제로 전환한 경계 상태**에서 신라 AI 월 경로를 실행했다. 평시 금성의 김춘추를 후임으로 선택하고 보상130을 실제 지출했다. 같은 달 재호출은 추가 인사·지출이 없었다. 이 상태를 정상 신라 AI가 독자적으로 권력을 집중한 장기 캠페인이라고 표현하지 않는다. 증거: `boundary-ai-selected.json`, lifecycle 로그의 `AI POWER EVIDENCE`.

새 상태는 공통 명부의 `politics.power_transfers` version1 아래 협의·고유번호·납부내역·결과·도시/부대 차질·AI 판단 시점을 저장한다. 기존 저장에는 빈 상태를 보완하며 과거 인사를 재정산하지 않는다. 정상 명부/부대/국고의 기존 저장 구조는 유지한다. 기한/처리 상태는 반복 불러오기로 실행되지 않는다. 종료 상태에서는 resolve/retarget/월 처리/AI가 차단되고, 새 캠페인은 새 명부와 UI를 만든다.

## 실제 화면과 재현

Godot **4.7.2 stable**을 사용했다. 독립 프로필은 `.godot/ending-runtime`이고 로그·캡처는 `.godot/noble-power-results`에 있다. 호스트 기본 AppData의 사용자 저장 경로를 확인했다고 주장하지 않는다.

정상 저장을 실제 캠페인에 불러와 인사 명령 → 공통 인계 선택창 → 각 선택 버튼 → 닫기/입력 복구 → 실제 월 버튼 → 필수 귀족 요구 정산 → 인계 현황을 확인했다. 선택 전 견적과 인계 완료/남은 차질을 분리해서 표시한다. 이미 끝난 협의의 선택 버튼은 비활성화한다. 기존 사건이 열려 있으면 인계창을 겹치지 않고 사건 종료 뒤 표시한다.

## 남은 범위

- 반란·처형·혼인·집단별 법적 인사 거부·왕 사망 시 새로운 협상 규칙은 구현하지 않았다. 현재 왕실 직할/귀족 영향력과 실제 인사·생산·출정 비용 범위만 평가한다.
- 단일 군수 허브·한 훈련 묶음 정책과 조달 속도는 기존 AI 보고서의 제한 그대로다. 90개월 감사 실행 길이는 신규 전력 최초 복구 시간이 아니며, 이전 실제 복귀 기록(500명18개월, 1,000명25개월 등)을 이번 변경으로 재측정했다고 쓰지 않는다.
- 정상 통일 완주와 호스트 기본 사용자 저장 경로 확인은 **미수행** 상태다. 기존 종료 경계·독립 프로필 검증을 재사용했다.
- 정상 비교에서는 정기 수확이 발생하지 않아 실제 수확량 감소를 수치로 추가 주장하지 않는다. 세입·시설 생산·훈련비는 실제 지출/산출로 검증했다.
- 협상 공식은 세입과 회수 규모를 반영하지만, 오래 축적한 큰 국고에는 작은 도시의 인계가 여전히 저렴하다. 군사·경제 가격을 임의로 변경하지 않았다. 추후 여러 거점/대규모 군권 회수의 정상 전쟁 비교가 필요하다.
### 출정 직전의 별도 정상 비교

금성에는 실제 적 인접 도시가 없었으므로, 그 상태를 '출정 직전'이라고 가정한 초기 검증을 폐기했다. 대신 정상 집중 저장에서 금130으로 김유신 태수직을 정리하고 생산 업무를 중단한 뒤, 기존 김유신 지휘 병력과 김유신·선덕여왕을 기존 지원 이동 명령으로 **금성→달구벌**에 보냈다. 실제 한 달 진행 후 저장한 `normal-front-concentrated.json`이 공통 기준이다. 달구벌에서 김유신에게 생산 관리 업무를 다시 지정하고, 선덕여왕에게 군권을 인계해 출정하는 선택을 비교했다. 재고·병력·능력치를 주입하지 않았다.

군권 견적 I=42.4531, D=31.3623, M=1397.6667, F=1.01 → **금640**. 세 방식의 공통 사전 준비에 들어간 태수 인계비130과 이번 군권 협상비640은 별개이다.

| 군권 선택 | 해당 부대 출정 대기 | 실제 출정 시점 | 참여 병력 | 적 병력 | 아군 손실 | 결과 |
|---|---:|---|---:|---:|---:|---|
| 보상 | 0개월 | 636.12 | 117,800 | 3,604 | 1,982 | 대가야 점령 |
| 기한 보장 | 2개월 | 637.2 | 117,800 | 4,104 | 2,257 | 대가야 점령 |
| 강제 | 1개월 | 637.1 | 117,800 | 4,104 | 2,257 | 대가야 점령 |

기존 군권 대상 외의 현지 부대도 실제 전투에 참여했다. 강제 차질은 대상 부대만 제한하므로 다른 정상 부대의 공격까지 금지하지 않는다. 실제 공통 전투 진입점을 사용했고 아군 실효 전투력은 207,328, 적은 즉시 출정 시5795.674, 지연 후6681.978이었다. 전투 승리를 보장하는 수정은 없었다. 기존 병력을 많이 집중한 사례라 세 방식 모두 승리했으며, 이를 일반적인 승률 우열로 확대하지 않는다.

기한 보장은 '기존 지휘관의 출정도 무조건 금지'가 아니다. 이 비교는 생산 업무 중인 김유신을 그대로 두고 새 지휘관으로 출정하려는 조건이다. 기존 담당자의 업무를 정리하고 그 지휘관에게 계속 맡기는 선택은 별개로 가능하다.

검수 중 자동 대체 지휘관 선택이 실제 군권 인계를 우회하는 경로를 발견했다. `Power.attack_reason()`으로 **출정비 차감 전** 인계를 요구하게 했다. 점령 부대에는 실제 출발하여 이동한 지휘관 ID를 연결한다. 남아 있는 담당자를 점령지 지휘관으로 잘못 저장하지 않으며, 승패·기본 전투 계수는 변경하지 않았다. 회귀 부대337/종료56 검증을 수정 후 다시 실행했다.

증거: `normal-front-actions.json`, `normal-command-comparison.json`, `normal-command-{compensate,wait,force}-battle.json`, `power-front.log`, `power-final2-noble_power_command.log`(15 확인, 실패0). 재현 순서는 `noble_power_normal_test.gd` → `noble_power_front_test.gd` → `noble_power_command_test.gd`이다.

### 정기 수확 경계 실행 및 추가 회귀

정상 4개월 비교에는 수확기가 없으므로, 저장의 수량을 유지하고 달력만 별도로 637.9→10으로 설정한 경계 검증을 추가했다. 기존 10월 수취율30%와 국가 수취율45%를 그대로 사용해 `process_seasonal_harvest()`를 실제 호출했다.

- 보상 후 유효 태수: 군량 8203→9625, 실제 수확 **1422**.
- 강제 차질 중: 군량 8203→9402, 실제 수확 **1199**.
- 같은 달 다시 호출해도 군량을 재지급하지 않는다. 이 숫자는 수확 단계만의 변화이며 이후 주둔 소비·창고 손실을 포함한 전체 월 순증이라고 표현하지 않는다.

증거 `boundary-harvest.json`, `power-harvest.log`(6 확인, 실패0). 정상 자연 진행 수확과 명확히 구분한다.

추가 기존 회귀 실행: 모집·인구417, 수송159, 내정131 확인 모두 실패0. 로그는 각각 `power-release-mobilization.log`, `power-release-supply_transport.log`, `power-release-domestic_assignment.log`. 실제 GUI는 최종 **27 확인, 실패0**(`power-release-noble_power_gui.log`)이며, 캡처를 직접 열어 인계창과 남은 차질이 보이는지 검사했다. 중간 GUI 검증에서 필수 귀족 요구 창을 인계 현황 캡처로 오인할 가능성을 발견해, 사건 정산 후 실제 인계창이 표시됐다는 검사를 추가하고 캡처를 다시 만들었다.
