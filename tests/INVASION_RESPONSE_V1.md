# 침공 예고·방어 대응 v1

검증일: 2026-09-17. 기준 main `f9f8f8e`. Godot 4.7.2 Windows. 기존 프로젝트 지침과 군권 인계·642 정치/군사 준비 검증을 보존했다.

## 적용 범위와 공통 규칙

기존 `run_enemy_ai_turns`의 목표 선택, 병력비·실효 전력 판단을 통과한 공격은 즉시 전투하지 않고 **다음 달 실행할 침공**을 선언한다. 기존 역사/가상 모드의 공격 대상 범위를 그대로 사용한다. 플레이어의 직접 공격 시점과 생산 비용·훈련·전투력·손실·점령 배분 공식은 변경하지 않았다.

새 `strategy_state.invasions`에는 캠페인 내 고유 ID, 출발지·목표와 당시 양측 소유 세력, 실제 부대 ID 목록, 총지휘관 및 부대별 지휘관, 예고 당시 병력, 접수/예정/처리 월, 상태·취소 사유·결과 전투 ID를 저장한다. 병력을 복제하거나 새로 만들지 않는다. 실제 부대 원장을 계속 사용하고 수비에는 예약 중인 부대도 참여할 수 있다.

예약된 부대는 다른 공격·지원 이동·분할·병합·해산·지휘관 교체·장비 지급·훈련에 중복 사용하지 못한다. 공통 부대 자격과 군권 협상 검증 양쪽에서 연결했다. 실행은 예약 ID만 공통 전투 함수에 전달하므로 나중에 공격 출발지에 온 미예약 병력이 몰래 합류하지 않는다. 방어 측에는 실행 당시 도시에 도착한 실제 부대 전부를 반영한다.

실행 직전에 출발지/목표 소유권, 경로, 실제 부대의 소속·생존 병력·주둔/이동 상태, 지휘관 생존·소속·위치·업무 자격, 훈련/군권 차질, 군량을 재검증한다. 무효면 구체적인 사유와 함께 취소하고 예약을 해제한다. **대응으로 전력비가 역전됐다는 이유로 취소하지 않는다.** 유효한 전투만 기존 공통 결제로 출발지 군량 500을 한 번 지불한다. 완료·취소 상태는 반복 월 처리나 복원 후 재실행되지 않는다. 패전도 완료 상태로 기록해 해당 예약을 정리한다.

## 월 처리 순서

1. 날짜 전진, 공통 상태 정리, 예정된 군권 인계 처리.
2. 기존 내정·건설/연구·화물·세입·수확·주둔 군량·보관 손실·훈련·생산·치안 처리.
3. 기존 1개월 병력/인물 지원 이동 도착 처리.
4. **전월에 예고한 침공**의 현재 자격 재검증 → 기존 전투 계산 → 점령/생산 중지 등 기존 후처리 → 방어 결과·공훈 연결.
5. 기존 AI 군수 계획과 공격 판단 → **다음 달의 새 침공 선언**.
6. 기존 계절 업무·사건, 군권 차질 종료, 캠페인 종료 판정. 사건이 표시 중이면 결과 화면은 사건 종료 후 표시한다.

따라서 예고를 받은 월에 접수한 인접 도시 지원은 다음 전투 전에 도착한다. 다구간 경로를 한 달에 순간이동시키지는 않는다. 한 달 안에 도착하지 않는 지원은 해당 전투에 참여하지 않는다. 기존 군량 결산이 이동 도착보다 먼저라는 순서도 유지했다.

여러 침공은 저장된 접수 순서로 독립 처리한다. 앞선 전투로 뒤 명령의 소유권 등이 바뀌면 뒤 명령은 사유를 남겨 취소된다. 전투 중 동기 처리만 실행 상태를 사용하며, 정상 저장은 대기 또는 완료/취소 상태를 보존한다.

## 정상 캠페인의 실제 비교

새 **642년 7월 신라·역사 모드·보통 난이도**로 시작했다. 날짜는 턴 종료로만 진행했고, AI를 유지했다. 자원·병력·영향력·승패를 주입하지 않았다. 재현을 위해 난수 시드만 고정했다(64220260921, 분기 이후 64220260922). 정상 월 사건은 기존 선택으로 처리했다. 첫 예고 전에는 병력·인사를 조작하지 않았다.

- 8개월 경과한 **643년 3월**, 실제 AI가 `invasion:1`, 백제 대가야→달구벌을 선언했다.
- 예고 병력 **32,800명**, 실제 기존 부대 10개, 총지휘관 없음(기존 기본 통솔 50), 예정 **643년 4월**.
- 이때의 동일 `pending` 시험 저장을 매번 불러와 전체 상태 일치를 검사한 뒤 무대응/지원 분기를 진행했다.
- 지원 분기는 GUI의 침공 목록에서 출발지를 골라 기존 지원 화면으로 이동했다. 금성 **27,000명 + 선덕여왕·김춘추·김유신**, 사벌 **19,000명 + 품일**, 추풍령 **13,200명**을 각각 달구벌로 보냈다. 각 출발지에 1,000명은 남겼고 태수 이동 확인도 처리했다.
- 지원 합계 **59,200명**, 1개월 후 도착. 실제 전투는 시작 후 9개월인 **643년 4월**에 발생했다. 기존 지원 명령에는 별도 금 지출이 없으며 월 주둔 군량은 기존대로 결산했다.

| 실제 정상 진행 분기 | 적 병력 / 아군 수비 | 적 실효 전력 / 아군 실효 전력 | 아군 방어 결과 | 아군 손실 | 적 손실 |
|---|---:|---:|---|---:|---:|
| 무대응 | 32,800 / 8,800 | 49,440 / 16,192 | 패배, 달구벌 상실 | 8,800 | 4,840 |
| 정상 지원 | 32,800 / 68,000 | 49,440 / 155,720 | 승리, 달구벌 유지 | 6,560 | 14,760 |

지원 효과에는 **병력 증가와 김유신 도착에 따른 방어 지휘 통솔 50→95가 함께 포함**됐다. 병력만의 통제 실험이 아니다. 이번 참가 보병은 기존 장비가 충분해 추가 장비 지급은 하지 않았다. 현재 장비·훈련 반영은 별도 통제 조건 검사와 기존 부대 회귀로 검증했다. 과거 군사 준비 기록의 전투와도 별개 실행이다. 이 한 사례를 캠페인 전체 밸런스의 결론으로 일반화하지 않는다.

방어 승리 후 실제 참전 총지휘관 **김유신**이 포상 후보로 표시됐다. GUI에서 금 **100**을 선택 지출해 충성 **50→55**, 군사 집단 협력 **50→56**을 확인했다. 전투 ID별 포상 완료 상태가 유지되고 새 프로세스에서 재포상을 거부했다. 이번 정상 AI 침공 방어 승리 포상은 검증 완료이며, 과거 문서의 당시 미검증 기록은 덮어쓰지 않았다.

## 화면과 저장 검증

상단 `침공 예고 N건`과 메뉴에서 여러 예고 및 지난 완료/취소 이력을 다시 확인한다. 위협 도시·예정 월·예고 당시 병력·지휘관을 표시하고 다음 경로를 제공한다.

- 위협 도시 보기.
- 해당 도시의 기존 부대 화면: 장비·훈련·지휘관 명령.
- 인접 아군 출발 도시 선택 → 기존 지원 화면. 목적지를 위협 도시로 자동 선택한다.
- 완료 후 해당 전투 결과·실제 공훈·선택 포상.

기존 침공 컷씬은 전투 이후 ‘이미 진입’ 안내에서 **선언 직후 ‘다음 달 공격 예정’**으로 수정했다. 컷씬 넘기기/닫기는 전투나 비용을 실행하지 않는다. 결과 화면은 아군 기준 `방어 승리/패배`를 명시한다. 새 안내·바로가기 열기는 비용을 쓰거나 업무를 배정하지 않는다. Esc/닫기 후 지도 입력이 복구되고 예고 창이 열린 동안 턴 종료가 차단된다.

GUI 자동 입력은 주 화면 버튼에 실제 마우스 이벤트, 태수 이동 확인 네이티브 창에 포커스/Enter를 사용했다. 목록·수량·인물은 위젯 값/선택을 설정한 뒤 실제 실행 버튼 입력으로 접수했다. 사람의 수동 플레이로 보고하지 않는다. 정상 예고·지원·방어 결과·포상과 통제 조건의 다중 예고·취소 사유 화면을 캡처하고 육안 확인했다.

## 통제 조건과 회귀 결과

정상 비교와 별도인 `invasion_response_test.gd`는 저장을 다시 불러와 소유권·군량·부대 소속/소멸/이동·지휘관 사망/이동/업무/교체·캠페인 종료를 의도적으로 바꾸고, 예정 월을 직접 맞춘 **통제 조건 검사**다. 무효 취소 사유·무지출·예약 해제, 유효 전투 군량 500 단 한 번, 완료/취소 API 재실행 거부를 확인했다. 같은 부대 중복 선언과 다른 명령 충돌도 검사했다.

다중 예고는 기존 정상 대기 저장에서 별도의 공통 선언 호출로 만든 통제 조건이다(두 번째는 고사성→추풍령, 14,000명). ID/부대 비중복, 저장 복원, 목록 선택/재확인, 예정 처리 종료를 확인했다. 실제 AI가 자연스럽게 동시에 두 침공을 생성한 정상 플레이 사례로 보고하지 않는다. 공격군의 현재 장비·훈련 변경과 선언 뒤 추가한 미예약 부대도 분리된 통제 조건이며 실제 전투 입력을 검사했다.

침공 필드가 없는 구저장 형태를 만들어 저장·복원한 뒤 과거 전투를 재생하지 않음을 확인했다. 실제 과거 원본 저장 재검증을 대신하는 것은 아니다.
