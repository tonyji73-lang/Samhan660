# 금관가야 새 게임 초기 소유권 검증

## 수정 범위와 근거

`korea_35_data.gd`의 기본 소유권은 가야였고, 기존 연도별 보정에는
670년에만 금관가야의 신라 소유가 지정되어 있었다.
632·642·660·663년은 정확한 연도에만 적용되는 원천 데이터 보정표로 신라를 지정했다.
670년의 기존 보정, 다른 도시, 대상 밖 연도의 가까운 연도 대체 동작은 유지한다.

근거: [국사편찬위원회 한국사데이터베이스, 금관국왕 김구해가 항복하다 (532년)](https://db.history.go.kr/id/sg_004r_0030_0150).

새 게임 경로는 `new_game_setup._on_start_pressed()` → 루트의
`new_game_settings` → 캠페인 `_ready()` → `_apply_new_game_settings()` →
`_apply_year_factions()` → `Korea35Data.get_factions_for_year()`이다.
이후 시나리오 군주 배치는 소유권을 다시 바꾸지 않는다.
새 게임 지도도 같은 연도 함수를 읽으며, 세계 지도/시나리오 보정에
금관가야의 소유권을 덮어쓰는 항목은 없다.

영토 팔레트·지도 표식·도시 카드·상세 패널·명령 권한·AI 컨트롤러·전략 시스템의
세력별 도시 묶음은 실제 `provinces[id].faction`을 사용한다.
세력 선택 화면의 `초기 영지` 설명은 대표 거점을 적은 정적 요약으로 기존 문구를 유지했다.
연도 없는 편집기 템플릿과 설정 없이 F6로 직접 실행한 캠페인은 이번 수정 대상이 아니다.
확인할 때는 **새 캠페인 → 대상 연도 → 신라 → 선택한 역사 시작 → 금관가야 클릭**으로 진입한다.

기존 `금관가야 수장` 태수 문구는 유지하며, 이 도시에 배치된 등록 장수는 없다.
태수 임명은 기존처럼 소속 장수를 선택해야 가능하다. 임의의 역사 인물을 추가하지 않았다.
대가야·소가야의 소유권과 가야 세력/장수 정의는 변경하지 않았다.

## 저장과 생산

불러오기는 저장된 `provinces` 사전을 복원하고 연도별 초기 소유권 함수를 호출하지 않는다.
저장 형식이나 이행 코드를 변경하지 않았다. 가야 소유인 이전 저장과 백제에 점령된 저장을
별도 파일로 만들어 실제 저장/불러오기 핸들러에서 검증한다.
도시 소유권·병력·군량·시설·철/칼 재고·생산 예약/주문 소유자·국가 연구·월 처리 기록을 보존한다.
불러오기 시 생산이나 밀린 월 처리는 없다. 기존의 주문 소유자 불일치 검사도 그대로 유지한다.

소유권 수정 당시 철 공급 허용표는 빈 상태였다. 이후 별도 승인된 시범 배치로
632·642년 시작 시나리오의 금관만 공급/건설이 허용되며, 신라의 기본 제련 기술만
새 게임에 설정한다. 나머지 지역/시나리오는 차단한다. 이 문서의 아래 결과는
소유권 수정 당시 기록이며, 최신 검증과 실제 플레이는 [IRON_PILOT.md](IRON_PILOT.md)를 참조한다.

## 재현 명령과 결과

Godot 4.7.2, 프로젝트 루트에서 실행:

```text
godot --headless --path . --script res://tests/production_test.gd
godot --headless --path . --script res://tests/geumgwan_ownership_test.gd
git diff --check
```

- 기존 생산/품목/철 공급 회귀: 수정 전후 모두 **155개 통과**.
- 새 소유권 검증: **181개 통과**. 다섯 연도 실제 캠페인 초기화, UI 신호/표시값,
  세력별 도시 묶음, 플레이어/AI 제어, 저장 복원, 철 공급 차단을 포함한다.
- 632·642·660년은 백제, 663년은 고구려 플레이어로 타 세력 명령 차단을 검증한다.
  670년은 본게임에서 신라만 선택 가능하므로 별도 프로세스의 당 플레이어 상태로만 검증한다.
- JSON 정수/실수 변환은 양쪽을 JSON 복원한 값으로 비교한다. 본게임 저장 파일은 사용하지 않는다.
- `git diff --check` 통과. 헤드리스 실행에는 Windows 인증서 저장소 읽기 오류가 출력되지만
  두 테스트의 종료 코드는 0이며 GDScript 오류는 없다.

실제 화면: 새 게임 설정의 시작 버튼 신호로 진입한 642년 신라 캠페인에서
금관가야의 신라 지도 표식, 도시 카드/상세 패널의 `세력: 신라`, 생산 버튼을 캡처 확인했다.
생산 화면의 철 공급 선택에서 시작/제철시설 건설 비활성 및 본게임 배치 미적용 안내도 확인했다.
이는 실행 중 UI 신호 조작과 화면 캡처 확인이며, 다섯 연도 전체의 화면 수동 클릭 검증은 아니다.
이후 스크롤 확인용 MCP 임시 스크립트에서 탭/공백 혼용 오류가 발생하여 검증 실행을 종료했다.
오류 스크립트는 프로젝트 파일에 저장되지 않았으며, 앞선 화면 확인과 헤드리스 결과와 구분한다.
