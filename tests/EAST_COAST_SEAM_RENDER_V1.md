## 실제 적용

다운로드의 `Samhan660_East_Coast_Seam_Render_v1.zip`에서 START_HERE_KO.md와 docs/INTEGRATION_KO.md를 읽고 다음 파일을 추가했다.

- `assets/map_render/east_coast_join_v1.gdshader`: ZIP 원본 코드와 바이트 동일. Godot가 생성한 `.gdshader.uid` 포함.
- `assets/map_render/east_coast_join_v1.tres`: ZIP 재질에 `shader_parameter/edge_width_uv = 0.04`를 명시했다. ZIP 기본 0.12보다 좁은 20.48 월드 단위 혼합 폭이다. 성 보호 사각형·외곽 guard·RGB/alpha 처리 수식은 변경하지 않았다.
- `settlement_map.gd`: 기존 동해 상세 전용 TextureRect인 `east_detail`에만 재질을 연결하고 use_parent_material=false를 명시했다. 기존 재질은 없었다. 바탕 terrain은 z=-9, 상세는 z=-8이며, 바탕의 상세 아래 영역을 잘라내지 않는다. UV는 전체 상세 PNG의 0~1, 반전/반복/아틀라스 UV가 아니다. 지형의 동일 세계 rect 변환과 그리기 순서를 유지했다.
- `settlement_overlay.gd`: 지원 경로 안내를 펼치면 720p 하단이 잘리는 기존 문제가 드러나 왼쪽 업무 버튼 높이 44·글자 18·버튼 사이 간격 2로 줄였다. 하단 버튼과 안내문 모두 화면 안에 들어온다. 명령 처리·지원 기간/비용은 변경하지 않았다.
- `tests/east_coast_seam_test.gd`: 동일 카메라 전후 캡처, 재질 범위, 성 주변 픽셀 보존, 선택·지원 경로·하단 검사.

성·표식·이름·클릭 버튼·도로/지원 경로·영토 마스크·상위 지도·UI에는 재질을 연결하지 않았다. 기존 성 비례 크기, 원거리 표식, 최소 32px 클릭 영역과 겹친 성 선택 처리를 유지했다. 원래 지도 기본 화면에도 이 재질을 연결하지 않았다.

두 지형 PNG 및 성 PNG는 ZIP registration의 SHA256과 현재 원본을 직접 대조해 일치했다. 신규 이미지 생성/교체는 하지 않았다.

## 관찰과 남은 문제

왼쪽·아래의 뚜렷한 직사각형 선은 완화됐고, 검사한 화면에서 새 검은 틈은 보이지 않았다. 바탕 지도는 투명해진 가장자리를 통해 실제로 보인다. 성·표식·지원 경로는 같은 위치에 유지됐다.

기본 혼합 폭 0.12에서 금성 남동쪽, 상세 UV 대략 x=0.40~0.55 / y=0.88~1.0 부근에 기존 해안·수목과 새 상세가 넓게 겹쳐 보였다. 재질 폭을 0.04로 줄여 혼합 띠를 61.44에서 20.48 월드 단위로 제한해 이 넓은 잔상을 완화했다. 성 보호 구역의 상세는 계속 불투명하다. 다만 아래쪽 해안 연결부와 왼쪽 숲/수계 경계의 형태·밀도 차이는 원본 불일치로 남아 있다. 폭을 줄인 것은 지리 정합의 해결이 아니며 아주 좁은 외곽 혼합 구간의 불일치까지 완전 제거했다고 판정하지 않는다.

정확한 해안·강 연결은 같은 지형으로 주변 아트를 맞추는 별도 작업이 필요하다. PNG 원본을 유지하는 이번 작업에서 선 완화를 위해 물길이나 성 좌표를 옮기지 않았다. 해안 정합, 세 성 바닥 전체, 35곳 정합, 미할당 마스크 9곳, 세계 지도 접합은 완료 판정하지 않았다. 사람의 수동 플레이, 과거 원본 저장 재검증 2건도 기존 미검증 상태다.

게임 규칙·ID·UV·경로·저장 형식은 유지했다. 사용자 저장의 확인 해시는 기존과 동일한 `3bca5c5286be3abb44ed60fbb9e1efe39815c29f6ff255d2ad825273aa5275d3`이다.
