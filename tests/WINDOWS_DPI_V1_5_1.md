## 실제 Windows 배율과 물리 크기

Windows 설정의 디스플레이 페이지에서 선택된 **디스플레이 1❘3**의 배율을 직접 변경했다. 복제/확장 구성과 모니터 해상도는 변경하지 않았다. 활성 화면의 해상도는 1920×1080이고, 추가 활성 화면도 1920×1080이다. 배율은 UI Automation으로 Windows 설정의 실제 선택값을 읽었다. 게임 viewport 설정은 바꾸지 않았다.

| Windows 배율 | 모니터 해상도 | 대표 캡처의 물리 클라이언트 크기 | 창 테두리 포함 크기 | 비고 |
| --- | --- | --- | --- | --- |
| 100% | 1920×1080 | 1280×720 | 1296×759 | 시작 및 최종 복원 창 크기 |
| 125% | 1920×1080 | 1600×900 | 1620×949 | 내정·후보·태수·생산·건설 |
| 125% 연구 | 1920×1080 | 1333×751 | 1354×800 | 150%에서 배율을 내린 직후의 크기. 동일 크기 비교로 오인하지 말 것 |
| 150% | 1920×1080 | 1600×901 | 1625×960 | 화면 안에 들어오도록 물리 창만 조정 |
| 150% 최초 전환 | 1920×1080 | 1893×1018 | 1917×1077 | OS 전환 직후 측정값, 전체 화면 검수에는 위 조정 창 사용 |

각 PNG 옆 `.png.json`이 해당 캡처 시점의 실제 크기·위치다. `environment-125.json`, `environment-150-initial.json`, `original-display.json`, `restored-display.json`, `window-awareness.json`도 함께 보존한다.

`GetDpiForWindow`는 모든 단계에서 96, 창의 DPI awareness는 1(system-aware)이었다. 따라서 이 API 값만으로 “Windows 배율이 그대로였다”고 판단하지 않는다. 실제 설정값과 물리 크기 변화가 별도로 확인되었다. 125%·150%에서는 100%보다 글자와 테두리가 부드럽게 확대되는 모습이 있다. 시스템 DPI 인식 창의 확대 경로와 일치하는 관찰이며, 다른 PC/다른 로그인 DPI에서의 선명도까지 승인한 것은 아니다. API의 반환값은 창의 DPI 인식 모드에 의존한다. [Microsoft GetDpiForWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getdpiforwindow).

## 재현과 전달물

1. 기존 V1.5 ZIP을 새로운 빈 폴더에 해제하고 포함된 `Samhan660.exe`를 실행한다.
2. 새 게임 632년 신라 → 금성을 선택한다. 기존 저장 슬롯을 사용하지 않는다.
3. `Start-Process 'ms-settings:display'`로 Windows 디스플레이 설정을 연다. 현재 모니터/배율을 먼저 기록하고 실제 배율을 변경한다.
4. 각 화면에 진입해 캡처한다. `desktop.ps1`의 `Get-GameMetrics`는 Win32 클라이언트/외곽 물리 크기를 기록한다. `Save-GameCapture`는 게임 클라이언트만 캡처한다. `Set-WindowsScale`은 열린 설정 창의 배율 컨트롤을 사용하므로 다른 환경에서 무조건 실행하지 말고 선택 모니터를 확인한다.
5. 배율을 원래 값으로 복원하고 저장/소스 해시를 비교한다.

작은 검토 ZIP은 보고서, 상대경로 `index.html`, 대표 18개 화면과 조작/군사 준비 증거, 환경 요약을 포함한다. 가벼운 JPEG 사본은 공유용이며 원본 PNG와 검증 JSON은 작업 폴더에 보존한다. EXE/PCK·원본 배경/초상·과거 캡처·대용량 로그·저장 파일은 포함하지 않는다.
