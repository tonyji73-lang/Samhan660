## 병력 원본과 저장 이관

기존 캠페인은 `provinces[city].troops`를 직접 증감하고 `unit_rosters[city][kind]`를 로드 때 다시 맞췄다. 이번에는 **`strategy_state.unit_rosters[unit_id]`가 실제 병력의 원본**이다. 기존 저장소를 확장했으며 별도의 army.units 병력 장부를 만들지 않았다. `army`에는 버전·ID 카운터·이관 진단·출납/전투/AI 이력만 둔다.

각 부대의 필드는 ID, faction_id, location/status, kind, troops, training_points, equipment(인원분), commander_id, origins(모집 출신 도시별 인원), power다. 출신 도시와 현재 소속·주둔지·지휘관은 별개다. 인물 ID는 공통 Registry.resolve를 통해 저장한다. 가문·정치집단은 공통 인물 명부에 이미 있는 참조만 조회할 수 있으며 부대에 근거 없는 귀족/가문 소속을 만들지 않았다.

도시 troops는 Army.sync가 만든 호환 표시 값이고 `Army.at_city/count/projection`에서 계산한다. 기본 병종/특수 병종 조회는 이 투영을 사용한다. 새 원장이 있는 저장은 도시 표시 숫자를 다시 부대에 적용하지 않는다. 이동 명령은 unit_ids로 같은 부대를 참조하고 troops는 호환 표시일 뿐 도착 때 다시 더하지 않는다. 이동 중/미배치 부대도 원장에 남는다.

저장 버전10의 이관 기준:

- 구형 저장은 실제 플레이가 사용하던 도시 병력 수를 우선한다. 저장된 병종 수가 일치하면 그대로 보존한다.
- 캐시가 어긋나면 비보병 병종의 기록을 도시 총병력 한도에서 먼저 보존하고 나머지를 보병으로 맞춘다. 원래 도시 값·부대 합계의 차이를 migration에 기록하고 원본 전체를 legacy_archive에 보관한다. 상충하는 두 합계를 모두 실병력으로 더하지 않는다. 이는 오래된 캐시 불일치 복구 정책이며, 원래 병종별 실제 수를 확정 복원했다고 주장하지 않는다.
- 훈련도가 있으면 유지한다. 실제 기존 일반 모집 경로는 기본 보병 training=50을 사용했으므로 **새 모집도 50**을 재사용한다. 미연결 별도 특수 모집 견적의 장수 보너스 공식을 일반 모집에 이식하지 않았다.
- 장비 필드가 있으면 유지한다. 없던 기존 병력은 **인원수만큼 이미 기본 장비를 지급받은 것으로 한 번 이관**한다. 도시 창고에 무기를 추가하지 않는다. 새 모집/보충에는 장비0이다.
- 이전 pending_transfer_orders의 병력은 도시 주둔병과 별도로 이동 중 부대에 한 번 등록한다. 목적지/출발지 모두 상실하면 기존 이동의 미배치 방식을 따라 원장에 보존한다.
- 이관 원본은 복구 이력이다. legacy_archive의 병력·장비 숫자는 모집/전투/집계에 사용하지 않는다.

## 편성·장비의 수량 보존

훈련도는 반올림한 평균을 저장하지 않고 정수 `training_points`를 보관한다. 표시/계산은 training_points/troops다. 분할할 때 병력 비율로 훈련도 합계와 장비를 배분하고 나머지는 원부대에 둔다. 합류는 정확히 더한다. 출신 도시 인원도 같은 방식으로 보존한다. 반복 분할·합류 30회에서 병력·장비·훈련도 합계가 그대로였다.

실제 단위 검증:

- 기존 1,001명, 훈련53, 장비1,050명분에 신규1,000명(훈련50·장비0)을 보충했다.
- 결과는2,001명, 훈련도 합계103,053, 장비1,050이다. 평균 훈련은103,053/2,001이며 장비 충족률은1,050/2,001이다.
- 무기10묶음을 지불하면 장비2,050명분이 되어 여분49를 보존하고 전투 충족률은100%로 제한한다.
- 이후501명 손실에는 장비 ceil(2,050×501/2,001)=514명분을 잃어1,536명분이 남는다. 부대는1,500명이다. 남는 장비도 부대에 남고 창고로 회수하지 않는다.

장비 지급은 `Army.equip_quote/equip`이 같은 도시·국가·주둔 상태·일반 보병·필요 묶음 수·창고 수량을 검증한 뒤 차감한다. **무기1묶음=100명분은 게임용 환산**이다. 제작 레시피나 이동 중 수량을100배로 바꾸지 않았다. 완전 충족 후 추가 지급은 막는다. 신규 모집, 분할, 합류, 로드로 무기를 생성하지 않는다.

손실은 실제 부대에 비례 배분한다. 장비 손실은 인원 손실 비율을 올림하여 줄이며, 전멸 때 남은 장비 전부를 손실 이력에 남긴다. 전멸 부대는 병력·훈련 합계·장비0, destroyed 상태다. 해산/교체/사망 장비를 창고로 반환하는 기능은 없다.

## 훈련과 월 처리

RULES에 최대1,000명, 목표70, 기본 증가5, 100명당 월 금5, 신규 훈련50, AI 예비금/방어 비율을 분리했다.

- 능률 E = round(통솔×0.7 + 무력×0.3), 0~100.
- 월 증가 = 5 + floor(E/10).
- 월 훈련비 = ceil(훈련 인원/100)×5.
- 접수 당월 비용/성과 없음. 다음 월부터 지불 성공한 경우만 증가하며70에서 완료한다. 기존70 초과 훈련도를 내리지 않는다.
- 실제 현재 소속·위치·생존·이동 여부는 Registry, 업무 충돌은 Registry.action_available와 Industry.staff_reason을 공유한다. 태수의 같은 도시 업무 겸직 규칙을 유지한다.
- 훈련 업무는 기존 `domestic.jobs`에 kind=training으로 기록한다. 담당자 duties는 job_id를 참조한다. 내정/건설/연구/생산 관리와 동시에 같은 인물을 쓰지 못한다.
- 국고 부족/해당 월 주둔군 군량 부족은 성과 없이 보류한다. 담당자·도시 자격을 상실하면 업무를 중지하고 실제 달성치를 남긴다. 담당자 교체 후 다음 월부터 새 능률을 적용한다.
- 부대 이동/공격은 훈련 중인 부대를 제외하고, 이동하려면 먼저 중지한다. 도시 방어는 훈련 중이어도 참여한다. 업무 중지/완료는 duties를 해제하며 수동 재시작에 과거 비용을 환불하거나 재부과하지 않는다.
- 업무별 last_month와 국가 거래 token으로 같은 달 비용·성과를 중복 적용하지 않는다.

월 순서는 기존 농업/상업 → 건설/연구 → 화물 도착 → 세입/수확 → **기존 주둔군 소비/창고 손실 → 훈련비·훈련 성과** → 생산 → 기존 이동 → AI 지원/장비·훈련 선택/모집·공격 → 기존 계절/사건이다. 훈련이 별도로 군량을 또 빼지 않는다. 이전 수송 보고서의 월 군량 수지는 당시 실행 기록으로 유지하며 새 AI 훈련비는 국가 금 원장에 추가된다.

## 실제 전투 연결

플레이어 `resolve_attack`과 AI `resolve_ai_attack`이 **`resolve_army_battle → Army.combat`**를 사용한다. 별도 시험용 전투 계산에만 붙이지 않았다. 실제 전장 연결/소유권·출정 군량과 인물 가용성을 검사하고, 준비된 공격 부대와 모든 실제 수비 부대를 합산한다. UI의 기존3,000명 출정 기준도 가용 병력을 사용한다.

일반 보병의 부대 기본 전투력:

`병력 × (기존 병종 power/50) × (0.8+0.2×장비충족률) × (0.8+0.4×훈련도/100)`.

기본 보병 power50, 훈련50, 장비100%에서는 병력수와 같다. 다른 기존 병종은 저장된 power 또는 기존 정의를 사용하고 보병용 장비/훈련 보정은 확장하지 않는다.

부대 합산 후 공격은 기존 `1+통솔/100`, 수비는 기존 `1+통솔/100+성곽/200`을 각각 한 번 적용한다. 명시한 유효 부대 지휘관을 우선하고, 없으면 기존 공통 가용성 기준으로 현지 장수를 선택한다. 지휘관을 unit power에 또 곱하지 않는다.

승리 시 공격 손실 기준은 기존 플레이어의 방어병력55%, 패배 시 공격병력45%를 공통으로 사용한다. AI만50%/35%였던 별도 손실 경로를 제거했다. 기존 손실 하한은 남기되 실제 참여 병력을 넘지 못하게 제한한다. 생존/점령 병력에 최소500·1,000을 더하지 않는다. 승리 생존자의35%를 출발지에 남기고 나머지만 점령지로 이동한다. 소규모 전투의 손실 곡선 자체는 후속 밸런스 대상이다.

동일 전장(국원→웅진), 공격1만/수비8천, 양측 통솔50·성곽0 통제 비교:

| 공격군만 변경 | 공격 실효 전투력 | 수비 실효 전투력 | 실제 판정 | 공격/수비 손실 |
|---|---:|---:|---|---:|
| 장비0%, 훈련0 | 9,600 | 12,000 | 공격 패배 | 4,500 / 2,000 |
| 장비100%, 훈련70 | 16,200 | 12,000 | 공격 승리 | 4,400 / 8,000 |

이는 통제 fixture의 비교다. 역사 배치·재고를 변경한 실제 플레이 결과로 주장하지 않는다. 실제 캠페인 진입점을 호출했고 저장/복원을 검사했다. 1·10·499·999명 패전과1명이 빈 성을 점령하는 경우도 병력 생성/음수 없이 처리했다. 부대별 전투 전 상태·장수 능력·성곽·실효 전투력·손실은 army.battles에 기록한다.

## AI 실제 월 행동

현재 AI 월 경로에서 같은 지급/훈련 함수를 호출한다. 창고 무기는 부족한 일반 보병에 필요한 수량만 지급한다. 훈련은 국가당 월 최대 한 부대를 새로 선택하며, 인원1,000 이하·가용 담당자·군량 유지·국고 조건을 적용한다. 현재 자원으로 가능한 계획 모집 비용과 예비금300, 다음 훈련비를 남길 수 있어야 한다. 수송비는 앞선 공통 지원 단계에서 이미 지불된다. 새 훈련 후에도 도시 병력의 최소50%를 훈련 외 상태로 남긴다. 방어에는 훈련 부대도 참여한다.

실제 AI 월 함수 검증에서는 백제 신규1,000명에 창고10묶음이 지급되어 장비1,000명분, 창고0이 됐다. 담당자 선택 업무가 생성되어 다음 월 금50을 지불하고 훈련50→63이 됐다. 이 고립 검증은 훈련 예비금 조건을 만들기 위해 백제 국고에 fixture1,000을 명시적으로 넣었으며, 기본 게임에 자동 지급 규칙을 추가하지 않았다. 같은 검사에서 예산이 부족한 고구려는 모집 뒤 훈련을 시작하지 않았다. 실제 GUI의 신라 캠페인에서는 AI를 그대로 실행했고 fixture 국고/무기를 추가하지 않았다.

현재 AI에는 새 시설/연구/생산 예약 전략이 여전히 없다. 재고가 없다면 장비를 생성하지 않는다. 이 제한 때문에 삼국의 기본 조달은 대칭적이지 않다.

## 실제 화면 실행

Godot `4.7.2.stable.official.ed1daf0bf`, Windows D3D12 Forward+ / RTX4060 Laptop GPU에서 실제 창을 실행했다. 632년 신라·보통·역사 모드 새 캠페인이다. 자원·장수 능력·생산 지역/기술 주입 없이 다음을 수행했다.

1. 선덕여왕을 금성→금관으로 이동. 제철시설5개월·군기감5개월·도검 연구3개월을 정상 완료.
2. 두 시설의 기존 레시피를10개월 실행해 실제 무기10묶음 생산.
3. 금관→금성으로10묶음 수송, 담당자도 별도 기존 장수 이동으로 금성 복귀.
4. 634.02 금성에서 UI 모집1,000명. `unit:548`의 장비0·훈련50을 확인하고 무기10묶음 지급. 부대 장비1,000명분·훈련50.
5. 실제 선덕여왕(통솔76·무력50, 능률68)을 지휘관/훈련 담당자로 선택. 다음 두 월 금50씩 지불해634.04 훈련70 완료.
6. 부대와 지휘관을 실직으로 이동하고634.05 하슬라에 기존 출정 흐름으로 공격.
7. 실제 전투 결과를 군사 화면에서 확인하고, 저장 후 세 번 복원해 부대/장비/금/도시 상태가 같은지 확인.

실제 전투는 **공격 패배**였다. 준비 부대만 있는 가상 전장이 아니라 현 주둔병을 함께 사용했다.

- 공격: 기존 실직8,800명(훈련50·장비100%) + 준비한1,000명(훈련70·장비100%) =9,800명.
- 부대 합산 기본 전투력 =8,800+1,080=9,880. 통솔76을 한 번 적용해 **17,388.8**.
- 수비:17,053명. 각 실제 부대의 장비/훈련을 합산한16,039.6에 통솔50·성곽73을 한 번 적용해 **29,913.854**.
- 공격 손실4,410, 수비 손실1,960. 준비한 부대는1,000→550명, 장비1,000→550명분, 훈련70 유지. 없던 생존 병력이나 장비를 보충하지 않았다.

GUI 전체 금 수지: `1,000 + 세입47,918 − 건설560 − 연구200 − 생산224 − 수송11 − 모집150 − 훈련100 = 47,673`. 출정은 기존 출발지 군량500이며 금0이다. 생산224는 목표10배치 이후 수송·훈련·전선 이동 중 계속 가동한4배치까지 포함한14×16이다. 수확/소비/창고 손실은 기존 월 처리에 맡겼으며 훈련 군량을 추가 차감하지 않았다.

기존 테스트 수정은 다음 이유다.

개발 중 새 코드의 범위가 넓은 텍스트 치환으로 생긴 파싱 오류를 수정했다. 부대 손실 내부 함수를 직접 호출한 새 fixture의 도시 투영 갱신 누락도 수정했다. 실제 명령 경로는 공통 동기화를 수행한다. 실패 로그를 통과 결과로 세지 않았으며 최종 로그에는 SCRIPT ERROR/FAIL이 없다. 실행 환경 때문에 생략한 핵심 검증은 없다. 기존 Windows 인증서 저장소 경고는 로컬 실행·렌더링과 별개였다.

후속 과제:

- **모집 인구 처리:** 기존 모집은 금/도시 군량을 지불하지만 도시 population을 줄이지 않는다. 이번에도 임의의 인구·징집 가능 인구 공식을 추가하지 않았다.
- 일반 병력 이동은 기존1턴 도착 순서(그달 소비 후 도착)를 유지했다. 이동 중 병력은 원장에서 보존하지만 별도 행군 유지비/식량 행렬 계산을 추가하지 않았다. 훈련 병력은 주둔군 유지비에 한 번 포함된다.
- 기존 모든 시나리오의 초기 병력 총합이 동일한 데이터, 미구현 본토/초원 경제, 삼국의 비대칭 철 조달은 그대로다. 대칭 AI 경제를 위해 실제 지원되는 생산/무역/조달 정책이 필요하다.
- 기존 특수 모집 백엔드는 현재 캠페인 UI에 연결되어 있지 않다. 새 원장에 옛 도시별 구조를 쓰지 못하도록 해당 경로를 거절한다. 현재 일반 모집은 정상 공통 명령으로 유지한다. 특수병 모집·성장 트리는 후속 연결 대상이다.
