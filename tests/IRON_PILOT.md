# 금관 지역 제철 공급 시범 배치 — 2026-09-05

변경 파일: `iron_supply_data.gd`(시범 허용표·초기 기술 설정·근거 안내),
`campaign_main.gd`(새 게임 기술 설정 호출·공급 상태 표시), `production_overlay.gd`(배치 안내),
`production_data.gd`와 `samhan_strategy_systems.gd`(기본 제련 안내 문구만 수정).
검증은 `production_test.gd`, `iron_supply_test.gd`, `geumgwan_ownership_test.gd`를 갱신하고
`iron_pilot_test.gd`를 추가했다. 기록은 이 문서와 `PRODUCTION.md`, `GEUMGWAN_OWNERSHIP.md`에 반영했다.

## 적용과 근거

- `silla_equilibrium_632 / geumgwan`, `goguryeo_coup_642 / geumgwan`만 허용한다.
- 기존 우계리 출처·편년·근거·불확실성을 보존한다. 이는 **지역 제철 공급 시범 배치**이며 광산 확정이 아니다.
  해당 시작 연도의 실제 채굴·가동과 게임 권역 대응은 미확정이다.
- `CANDIDATES.ugye_ri.placement_confirmed/mining_confirmed`는 계속 false다.
  허용표의 `placement_confirmed=true`는 승인된 **게임 설계 배치**를 의미한다.
- 632·642년 새 캠페인의 신라에만 `basic_smelting=1`을 설정한다.
  이번 모델을 위한 설계 결정이며, 다른 국가의 역사적 제련 능력이 없었다는 뜻이 아니다.
- 제철시설·군기감·철·칼·금은 추가 지급하지 않는다. 기존 새 게임 금 1000을 사용한다.
- 다섯 시나리오의 금관 소유권은 이미 신라로 수정되어 있어 도시/시나리오 데이터는 추가 변경하지 않았다.

## 초기화와 저장

기존 `campaign.scenario_id`를 시작 시나리오 식별자로 사용한다.
새 게임 설정 → 초기 상태 작성 → `apply_new_game_technologies()` 순서이며,
시작 기술 처리는 `_init_strategy_state()`나 불러오기 함수 안에 넣지 않았다.
따라서 전략 데이터가 없는 옛 저장의 초기화도 기술을 지급하지 않는다.

저장 버전과 구조는 바꾸지 않는다. 기존 저장의 명시적인 `scenario_id`를 복원하고 현재 연도로 추정하지 않는다.
ID 누락 시 기존 660 기본값을 사용하며 이 시나리오는 공급 미허용이다. 알 수 없는 ID도 공급 미허용이다.
632·642 시작 저장에 기술이 0이면 그대로 0이다. 명시적 시작 ID에 따라 지역은 허용될 수 있지만
불러오기만으로 기술·시설·재고를 얻거나 생산할 수 없다.

달력이 670년으로 진행되어도 시작 ID는 유지된다. 기존 월 처리 순서는
월 경제 → 도시 ID 오름차순의 도시별 공급→제조 → 치안/이동/AI → 계절 전략 처리이며 변경하지 않았다.
완공/연구 완료는 계절 정산에서 일어나므로 다음 월 생산부터 사용한다.
점령 시 지역 허용은 도시에 남고, 시설/재고도 남지만 주문은 중지된다.
국가 기술은 이전되지 않으며 새 소유자의 기술·금·명령 권한을 검사한다.

## 실제 플레이 경로

두 실행 모두 역사적 플레이/보통 난이도에서 새로 시작했다.
MCP로 버튼 신호와 Esc, 정상 턴 종료를 자동화했다.
금·재고·기술·시설·완료 상태·연도·AI 상태를 런타임 대입하지 않았다.
정상 저장 핸들러의 파일 경로만 `.godot/pilot-632-save.json`, `.godot/pilot-642-save.json`으로
지정해 기존 사용자 저장을 덮어쓰지 않았다. 테스트 데이터 주입 사례는 아래의 별도 헤드리스 검증에만 있다.

1. 새 캠페인 → 632년 또는 642년 → 신라 → 역사적 플레이/보통 → 선택한 역사 시작.
2. 금관가야 클릭 → 도시 카드 생산 → 철 공급 → 아래로 스크롤 → 제철시설 건설 (금 240).
3. 닫기/Esc → 턴 종료 6회 → 금관가야 생산 → 철 공급 → 매월 생산 시작.
4. 닫기/Esc → 턴 종료 1회: 철 2 최초 생산.
5. 생산 → 칼 제작 → 도검 제작 연구 (금 200)와 군기감 건설 (금 320).
6. 정상 턴 종료 5회 후 군기감 완공 → 칼 제작 매월 생산 시작 → 턴 종료 1회: 첫 칼.
   철 공급 예약은 공정 선택 변경과 연구/건설 중에도 계속 유지된다.

## 저장 재개와 철 0에서의 연결 — 실제 UI 검증

두 첫 칼 생산 시점의 저장을 다시 불러와 금·재고·시설·기술·주문·월 기록·시작 ID의 보존을 확인했다.
JSON 수치의 정수/실수 차이는 JSON 복원 값으로 비교했다.
632 저장 재개 후 정상 다음 달(633-03): 금 21498→23171, 철 12 유지, 칼 1→2.

642 저장을 복원하고 공급만 UI에서 중지했다. 제조는 계속 예약하여
643-09~644-02 정상 6턴 동안 철 12→10→8→6→4→2→0, 칼 1→7이 되었다.
매월 생산비 금 10, 전체 금은 18542→27212였다.
공급을 다시 예약하고 644-03으로 진행하자 **철 0→0, 칼 7→8**,
금 **27212 + 경제 1455 − 공급 6 − 제조 10 = 28651**이었다.
두 공정 모두 생산 완료였다. 이 사례는 같은 달 공급한 철로 칼이 만들어지는 것을
재고 대입 없이 확인한 결과다.

## 안정 체크포인트 재검증

위 두 헤드리스 명령을 다시 실행해 생산 193/193, 소유권 181/181 통과를 확인했다.
Windows 인증서 저장소 읽기 오류는 환경 메시지로 구분하며, 두 검증의 종료 코드는 0이다.

세력 선택 UI는 실행 중인 `new_game_setup.tscn`에서 다음 순서로 확인한다.

1. 632·642·660·663·670년 탭을 차례로 선택하고 각 연도에서 역사/가상 스타일을 전환한다.
2. 활성 세력이 위쪽에 있으며 각 그룹 내부 순서는 기존 데이터 순서인지 확인한다.
3. 활성 세력을 각각 선택해 목록 강조, 오른쪽 정보와 시작 버튼 상태가 같은 세력을 가리키는지 확인한다.
4. 같은 창 크기에서 왼쪽 패널 너비 220, 항목 높이 82, 지도 위치가 유지되는지 확인한다.
   왼쪽은 국가명과 군주 이름 원문 두 줄이며 나이 없이 표시하고, 툴팁으로 전체 이름을 제공한다.
5. 663년에서 642년 탭을 직접 클릭해 강조·제목·설명과 실제 ID `goguryeo_coup_642`의 일치를 확인한다.

열 가지 연도/스타일 조합에서 위 항목이 통과했다. 두 스타일의 선택 가능 세력은 동일하다.
632·642·660년은 신라·백제·고구려, 663년은 신라·고구려, 670년은 신라다.
