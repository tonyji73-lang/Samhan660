# 외교 기반 통상협정 v1

기반: `feature/trade-system-v1`, HEAD `0b70001a0a1dbe2a708011ed948d434f7c727959`.
이 단계는 구현·검증만 수행하며 commit/push/merge하지 않는다. `_handoff/`는 사용하지 않는다.

## 구조와 규칙

- `campaign_navigation_menu.gd`의 **Menu → 외교** 신호가 캠페인의 외교 오버레이를 연다.
- `diplomacy_overlay.gd`는 대상 세력 ID와 사절 이름을 선택 키로 유지한다.
  대상은 준비된 시나리오 순서와 기존 PLAYER/AI/INACTIVE 정책을 사용한다.
  자기 세력·INACTIVE는 제외하며 전쟁 상대는 표시한다.
- `samhan_strategy_systems.gd`의 기존 `relations`, `value`, `status`, `treaties`를 재사용한다.
  협정을 별도 장부에 복제하지 않는다. 내부 조약명은 계속 `통상 조약`이다.
- 캠페인은 사절 이름만 받는다. 공통 견적/실행 경로에서 실제 `officers`,
  `officers_by_province`, 도시 소유권, 장수 메타데이터를 다시 확인한다.
  이동 중·배치 없음·중복 배치·외국 장수·점령된 도시 소속 장수는 사용할 수 없다.
- `get_diplomatic_action_quote()`는 관계를 만들거나 자원을 변경하지 않는다.
  `perform_diplomatic_action()`도 이 견적 함수를 사용해 실행 직전에 재검증한다.
  정치·지력·권위는 UI가 전달한 능력치 대신 장수 원본에서 읽는다.

성공률은 기존 정수 연산을 유지한다. 나눗셈은 소수부를 0 방향으로 버린다.

```text
clamp(45 + int((정치 + 지력 + 권위) / 12) + int(관계도 / 5), 15, 95)
```

| 행동 | 조건 | 비용 | 결과 | 월 행동 |
|---|---|---:|---|---|
| 친선 사절 (`gift`) | 비전쟁, 금 200 이상 | 금 200 | 성공률 100%, 관계도 +12 | 사용 |
| 통상협의 (`trade_pact`) | 비전쟁, 관계도 10 이상, 협정 없음 | 금 0 | 성공 +5 및 조약 1개, 실패 -3 | 성공·실패 모두 사용 |
| 통상협정 해지 (`cancel_trade_pact`) | 협정 있음, 확인창 승인 | 금 0 | 관계도 -10, 통상 조약만 제거 | 사용 |

관계도는 기존 -100~100 범위다. **해지의 관계도 -10은 임시 게임 밸런스**다.
조건 검증에서 거절한 행동은 금·관계도·월 기록을 변경하지 않는다.
실행 결과의 `executed`가 참일 때만 캠페인이 `gold_cost`를 한 번 차감한다.
다른 불가침·동맹·혼인 동맹은 해지로 바뀌지 않는다. 기존 전쟁 선포는 모든 조약을
제거하는 동작을 유지하므로 통상 조약도 사라진다.

## 월 기록과 저장 호환

기존 저장 버전 4와 전략 상태 버전 4를 유지했다. 전략 상태에 선택적 필드만 추가했다.

```text
strategy_state.diplomacy_last_action_month[세력명] = year * 12 + month
```

이는 기존 계절 단위 `turn_actions`와 별개다. 닫기/다시 열기, 사절 변경, 실패 직후
재클릭, 행동 후 저장/불러오기로 월 제한을 우회할 수 없다. 다음 달에는 다시 가능하다.
다음 해 같은 월은 다른 키다. 구형 저장에 필드가 없으면 빈 Dictionary, 즉 미사용이다.

새 월 인수를 사용하는 판정 키:

```text
diplomacy:v1|교섭세력|대상세력|행동ID|사절이름|현재연도|현재월
```

SHA256 앞 8자리의 16진 정수 `% 100`을 성공률과 비교한다. 고정된 동일 조건을
불러오면 결과도 같다. UI가 판정 값을 지정하거나 강제로 성공시키는 기능은 없다.
기존 6개 인수 호출은 유지되며, 월 인수 기본값 0에서는 기존 연도 기반 판정을 쓴다.
캠페인의 공개 명령 경로는 항상 실제 월·국가 금·활동 세력·장수 배치를 전달한다.

불러오기는 협의나 비용 차감 함수를 호출하지 않는다. 전략 상태 자체가 없는 오래된
저장은 기존 초기 구조를 만들되 `apply_start_relations=false`로 역사적 협정을
다시 지급하지 않는다. 기존 관계·조약이 있는 저장에서는 그대로 복원한다.

## 초기 통상협정 확인

기존 역사 설정은 `year >= 660`이고, 해당 관계 쌍이 이미 존재할 때만 적용한다.
조사에서 원천 시나리오의 `왜(야마토)`와 준비된 캠페인의 `왜(야마토 조정)` 이름 차이로
백제–왜 초기 설정이 누락되는 경로를 확인했다. 관계 키 생성에서 이 두 이름을
같은 세력으로 처리했다. 세력/지도 원천 데이터는 변경하지 않았다.

옛 저장의 `백제|왜(야마토)` 같은 키도 읽기와 쓰기에서 기존 키를 재사용한다.
불러올 때 키를 복제·이행하거나 누락된 협정을 보충하지 않는다.

| 시작 시나리오 | 신라–당 | 백제–왜 |
|---|---|---|
| 632 | 없음 | 없음 |
| 642 | 없음 | 없음 |
| 660 | 동맹 + 통상 조약, 관계도 70 | 동맹 + 통상 조약, 관계도 60 |
| 663 | 동맹 + 통상 조약 | 백제 세력 없음, 새 관계 생성 안 함 |
| 670 | 동맹 + 통상 조약 | 백제 세력 없음, 새 관계 생성 안 함 |

신라–당의 670년 초기 상태를 포함해 기존 연도 정책은 바꾸지 않았다.
초기 설정은 월 행동을 소비하거나 금을 차감하지 않는다.

## 기존 교역로

`open_trade_route()`는 같은 세력을 거절하고 전쟁 여부·통상 조약을 확인한 다음
기존 출발/도착 시장·중복 경로 조건을 검사한다. 관계도만 10 이상이어도 개설할 수 없다.
협정 없을 때의 안내는 `먼저 상대 세력과 통상협정을 체결해야 합니다.`이다.

기존 계절별 `_process_trade()`는 협정 해지·전쟁·비활성 경로의 수익과 관계도 증가를
중지한다. 경로 자료는 삭제하지 않는다. 기존 수익 공식 및 계절 정산 시점은 유지했다.
교역로 개설 UI, 품목·수량·가격 협상, 재고 이동은 이번 단계에 없다.

## 실제 게임 확인 (2026-09-07)

1280×720 그래픽 실행에서 정상 게임 명령과 월 진행만 사용했다. 금·관계도·장수 능력·
결과를 주입하지 않았다. 저장 확인은 기본 사용자 저장을 보호하기 위해 정상 저장/불러오기
함수에 `.godot/` 아래 별도 검증 경로를 전달했다. UI 자동화에는 버튼/목록 신호를 사용했다.

1. **660년 → 신라 → 시작 → Menu → 외교 → 당**:
   관계도 70, 동맹, 통상협정 체결 및 다음 단계 교역로 안내를 확인했다.
   해지 확인창 승인 후 관계도 60, 동맹 유지, 통상 조약만 제거, 금 1,000 유지.
   저장/불러오기 후 해지 상태와 이번 달 사용 상태가 유지됐다.
2. **632년 → 신라 → 시작 → Menu → 외교 → 백제 → 김법민 → 친선 사절**:
   1월 금 1,000→800, 관계도 0→12. 같은 달 통상협의 차단.
3. **닫기 → 턴 종료 → Menu → 외교 → 통상협의**:
   2월 김법민 정치 92·지력 90·권위 95, 성공률 `45+23+2=70%`.
   실제 판정 35로 성공, 관계도 12→17, 통상 조약 1개.
   월 경제를 거쳐 금은 800→2,280이 되었고 협의 비용은 0으로 금 2,280 유지.
   저장/불러오기 뒤 협정과 월 사용 기록(632×12+2=7586)이 유지됐다.
4. 실제 Esc 키로 외교를 닫은 뒤 금관 도시 선택과 턴 진행이 복구됨을 확인했다.
   생산과 외교는 동시에 열리지 않으며 목록·버튼·결과가 화면 안에 표시됐다.

정상 플레이에서 신규 협의는 성공을 확인했다. 실패 시 관계도 -3 및 같은 달 재시도
차단은 별도의 헤드리스 fixture로 검증했으며 실제 플레이 결과를 강제로 실패시키지 않았다.
