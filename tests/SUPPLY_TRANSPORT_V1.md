## 원장과 공통 함수

- 군량은 `provinces[city].food_stock`, 철/칼은 `strategy_state.city_inventory[city].iron/sword`만 사용한다. 조회는 기존 `Production.get_stock/get_inventory_view`, 국가 권한·국고는 `Economy.validate/spend/post/resolve/city_ids`를 재사용한다.
- 국가 표시는 기존 이름, 소유권/명령/비용 부담 참조는 faction_id다. 현재 경제 운영 범위인 삼국 35도시의 유효 국가 도시만 취급한다. 미구현 당/왜/초원 본토 경제를 추가하지 않는다.
- 정규 화물 ID는 `grain/iron/sword`. 기존 `weapons→sword`에 더해 수송 입력의 `food/food_stock→grain`을 정리한다. 동일 ID와 별칭이 함께 있으면 같은 수량은 한 번만 사용하고, 서로 다른 수량은 오류로 거절한다. 별칭 수량을 합산해 재고를 만들지 않는다.
- 출발 시 화물을 도시 원장에서 빼고 `supply_transport.orders[id].cargo`로 옮긴다. 이 사전은 **실제 이동 중 재고**다. 생산/모집은 이를 조회하지 않는다. 종료 시 도시로 옮기고 cargo를 0으로 만든다. original_cargo/delivered_cargo는 불변 이력이며 사용 가능한 재고가 아니다.
- 병력·장수 이동의 pending_transfer_orders와 인물 duties를 재사용하거나 덮어쓰지 않는다. 화물은 장수/병력을 요구하지 않는다. 같은 월 시각과 소유권/자원 검증은 공통 경로를 쓴다.
- 주둔군 군량 필요량은 `Supply.upkeep(province)`의 `floor(troops/100)`으로 기존 계산을 공유한다. 모집 비용과 출정 비용은 기존 값을 유지한다.

## 경로·견적·월 처리

지도 실제 도로 자료인 `Korea.get_roads()`에서 유형 land/mountain만 선택한다. `get_connections()`의 해로를 그대로 쓰지 않는다. 실제 경제 대상 아군 도시만 방문하는 너비 우선 탐색이며, 인접 도시 ID를 정렬하여 최단 구간 수가 같아도 경로가 일정하다. 접수 경로는 저장하며 불러오기 때 다시 계산하지 않는다. 육로/산길 모두 구간당 1개월이다.

| 초기 설정 | 값 |
|---|---|
| 적재량 | 군량 + 철×10 + 칼×10 |
| 명령당 최대 적재량 | 2,000 |
| 기본 운송비 | 구간 수 × (10 + ceil(적재량/100)) |
| logistics 연구 할인 | 단계당 10%, 0~3단계(최대30%) |
| 최종 비용 | max(1, ceil(기본 비용×(1−할인율))) |
| 운송 인력·가축 | 운송비에 포함한 게임용 추상화. 장수/호위 필수 아님 |

견적에 화물, 적재량, 전체 경유 도시, 예상 도착 월, 기본/할인/최종 비용, 출발 후 군량, 현 주둔군 소비와 유지 개월을 표시한다. 가용성 판단과 실행은 같은 quote를 사용한다. ETA는 현재 경로가 계속 유효할 때의 값이고 차단 시 보류로 표시한다. 미래 수확·모집까지 보장하는 유지 기간은 아니다.

월 처리 순서:

1. 월 증가·인물 시각 갱신, 기존 저장/업무 보완.
2. 농업·상업 완료 → 건설·연구 완료 및 생산 담당자 자격 확인.
3. **현재 위치 점령 확인 → 화물 한 구간 이동/도착 하역**.
4. 도시 세입 → 기존 9/10월 수확·풍흉년 → 주둔군 소비 → 창고 손실.
5. 기존 국가별 시설 생산. 그달 도착한 철과 완료한 기술/시설을 사용한다.
6. 기존 치안·장수/병력 이동 → AI 수송 판단 → 기존 AI 모집/공격 → 계절 처리·사건 표시.

접수 시 last_move_month/last_processed_month를 현재 월로 기록하여 접수 당월 이동을 막는다. 월 함수 재호출은 같은 달 이동·도착을 반복하지 않는다. AI가 월말에 접수한 화물도 다음 달부터 이동한다. 재지정은 현재 월을 처리한 것으로 기록하여 같은 월 재호출로 이동을 추가할 수 없다. 월을 건너뛴 직접 호출도 한 번 호출당 최대 한 구간만 이동한다.

## 취소·차단·점령

- 첫 이동 전, 현재 출발지가 아군이면 취소 가능. 화물과 실제 납부 운송비를 최초 국가에 한 번 반환한다. 반복 취소/완료 취소는 거절한다.
- 이동 후 취소는 거절한다. 현재 아군 도시에서 새 목적지의 경로를 견적·결제해 재지정한다. 이전 운송비는 환불하지 않는다. 현지 하역은 그 도시로 화물을 옮기고 종료하며 비용은 환불하지 않는다.
- 남은 경로의 도시/연결과 현재 위치만 검증한다. 다음 경유지나 목적지 상실은 현재 위치에서 대기한다. 지난 출발지나 경유지의 점령으로 멀리 있는 화물을 삭제하지 않는다.
- 현재 위치 도시가 점령되면 그 도시 창고로 cargo를 편입하고 captured(피탈)로 끝낸다. 원래 국가 환불 없음. 실제 두 전투 점령 경로에서 즉시 처리하며, 월 처리도 같은 종료 상태를 확인하므로 중복 지급하지 않는다.
- 불러오기는 이동/피탈/환불을 실행하지 않는다. 소유권이 바뀐 저장도 다음 명시적 월/점령 처리에서 처리한다.

## AI 정책과 실제 연결

`Supply.POLICY`에 국가당 월 신규 명령 1개, 공급 도시 주둔군 6개월 비축, 지원 목표 3개월 비축, 생산 원료 목표 4배치를 분리했다. 적재량/품목별 적재계수도 별도 상수다.

현재 `run_enemy_ai_turns()`에서 경제 대상 AI 국가를 모아 국가별 한 번 호출한다. 초기 군량이 적은 도시(현 군량/월 소비가 작은 순, 동률 도시 ID)를 먼저 검사한다. 이미 유효한 경로로 도착 중인 화물과 예상 도착 기간을 반영한다.

필요량은 대상 도시 소비×(경로 개월+목표3개월) + 계획 모집 군량×(경로 개월+1) + 실제 기존 공격 판단이 고른 출정 수요 − 현재 군량 − 해당 기간 도착 예정 군량이다. 공급원은 도착이 빠른 순, 동률 ID순이며 **접수 시** 자기 주둔군6개월분을 남긴 여유만 제공한다. 접수 후 별도로 시행되는 모집/소비는 기존 경제 규칙을 따른다.

급한 군량 수요가 없으면 가동 명령의 소유권·지역·시설·기술·운영비 조건이 유효하고 재료만 부족한 생산에 원료를 지원한다. 공급 도시의 가동 생산에 필요한 4배치분은 남긴다. 시험에서는 철8이 도착한 뒤 금10·철2를 소비해 칼1을 만들었다. 기술/지역 조건이 충족되지 않은 명령을 지원하기 위해 재료를 생성하지 않는다.

막힌 AI 수송은 원래 목적지까지 대체 경로를 견적·재결제하고, 불가능하면 현재 아군 도시에서 하역한다. 실제 명령은 플레이어와 동일한 start/command 함수다. 부족한 금·물자를 보충하지 않는다. 수요·경로 길이·공급 여유·견적 결과와 실패 이유는 ai_log에, 화물 이동/출납은 history에 남긴다.

## 저장

저장 버전9. 기존 전략 상태 안에 `supply_transport={version,next_id,orders,history,ai_months,ai_log}`를 추가한다. 명령에는 국가 ID, 화물, 원본 화물, 최초/누적 납부 비용, 경로/현재 인덱스/위치, 목표, 생성 월, 마지막 이동/처리 월, 이동 횟수, 상태·대기 이유, 재지정 결제 내역, 종료 월과 하역 내역이 있다.

옛 저장은 빈 수송 상태만 보완한다. 기존 병력·장수 이동, 인물·업무·재정·생산·외교·사건 상태는 그대로 유지한다. 진행/대기/피탈 상태를 실제 저장한 뒤 각각 세 번 복원했다. 불러오기 자체의 금·재고·화물 이동 변화가 없음을 확인했다. 종료 화물은 이력만 남으며 다시 사용할 수 없다.

수송만 단독으로 검사할 때 별도로 월을 증가시키는 테스트가 인물 기준 시각을 갱신하지 않아 저장 비교가 처음 실패했다. 실제 게임 월 경로는 원래 갱신하고 있었다. 테스트에 동일 시각 갱신을 적용했고 게임 저장 코드를 우회 수정하지 않았다.

## 실제 화면과 자원 변화

Windows Godot `4.7.2.stable.official.ed1daf0bf`, D3D12 Forward+ / RTX4060 Laptop GPU에서 `--headless` 없이 실행했다. 632년 신라, 보통, 역사 모드에서 선덕여왕을 금성→금관으로 실제 이동시키고 제철시설·군기감·도검 연구를 완료했다. 공급/제작 2개월로 실제 칼2를 생산했다. 생산 관리자 보너스 없이 기본 생산을 사용했다.

| 실행 | 출발/이동 중/도착 변화 | 실제 운송비 |
|---|---|---:|
| 633.05 금관→금성 칼1 | 금관 칼2→1, 이동 중1, 633.06 금성 칼0→1 | 금27,692→27,681 (11) |
| 633.12 금관→금성 철4 | 금관 철−4, 이동 중4. 634.01 도착 후 같은 달 금성 제작에 철2 소비, 철2 남고 칼+1 | 금39,443→39,432 (11) |
| 634.01 금성→금관 군량1,000 | 금성−1,000, 이동 중1,000. 634.02 도착 후 소비124·저장손실4로 군량872 | 금40,989→40,969 (20) |
| 위 도착 후 1,000명 모집 | 금관 군량872→672, 병력12,400→13,400 | 모집 금42,615→42,465 (150) |

철 도착 전에 금성의 군기감을 실제 담당자로 건설하고 제작을 예약하여 철 부족 보류를 확인했다. 군량 부족은 금관의 현 군량을 유료 화물 명령으로 금성에 반출해 0으로 만들었다. 이동 중 군량이 있어도 모집이 막히고 반대 방향 군량이 도착한 후 실행 가능해짐을 확인했다. 모든 반출 비용은 원장에 포함된다.

AI 화면 검증도 백제 금마저의 현 군량을 백제의 유료 수송 명령으로 사비에 반출해 부족 상황을 만들었다. 이후 **월 버튼의 기존 AI 경로**가 634.03에 주류성→금마저 군량876을 자동 접수(금19), 634.04에 도착시켰다. 금마저는 소비195·창고손실3으로678, 기존 AI 모집 군량100을 지불한 뒤578이 됐다. 이 지원 명령 자체는 테스트가 직접 호출하지 않았다. 별도 headless 검증은 donor/shortage fixture로 같은 결과 조건을 검사한다.

GUI 새 캠페인 전체(632.01~634.04)의 신라 금 수지는 `1,000 + 세입46,256 − 건설880 − 연구200 − 생산118 − 수송131 − 모집150 = 45,777`이다. 같은 실행의 백제는 `1,000+24,946−모집14,100−수송64=11,782`, 고구려는 `1,000+35,522−모집22,665−수송166=13,691`이다. 백제 수송64에는 부족 재현을 위한 유료 반출도 포함한다. 새 AI는 자연 발생 부족에도 지원하므로 다른 두 국가에서도 수송비가 실제 발생했다. 고구려 출정은 기존 군량 비용이며 금 비용0으로 기록된다.

별도 관리 GUI는 이 실행의 최종 저장을 불러와 첫 이동 전 취소로 실제 금/군량을 복구했다. 금관→금성→실직 수송을 한 구간 진행한 뒤 금성→달구벌로 재지정해 금11 추가 지불, 같은 달 추가 이동 차단, 금성 현지 하역으로 군량100 반환(운송비 환불0)을 확인했다.

## 재고 보존과 전체 경제 단계 구분

수송 전용 검사는 생산·수확·소비를 호출하지 않는다. 군량400, 철12, 칼8 각각과 군량400+철12+칼8 혼합에서 `모든 도시 창고 + 이동 중 재고`가 접수/도착/재지정/하역/피탈 후 동일했다. 원래 국가에서 점령국으로 귀속이 바뀌는 피탈도 세계 총재고는 변하지 않고 소유자와 이력만 바뀐다.

한 구간 군량1,000의 연구0/1/2/3단계 비용은20/18/16/14이고 취소 시 해당 실제 비용을 복구했다. 적재량1의 3단계 비용은 ceil(11×0.7)=8로 확인했다.

## 범위·후속 함수

| 공통 함수 | 용도 |
|---|---|
| `Supply.ensure` | 빈 구형 저장 보완. 이동/결제 없음 |
| `Supply.cargo_quote/quote` | 별칭·적재·권한·경로·재고·연구 할인·국고의 공통 견적 |
| `Supply.graph/route/remaining_reason` | 도로 유형 구분, 결정적인 아군 최단 경로, 남은 경로 검증 |
| `Supply.start/command` | 접수, 취소, 재지정, 현지 하역 |
| `Supply.process/capture` | 월 이동/도착과 현재 도시 피탈의 단일 종료 경로 |
| `Supply.incoming/ai` | 유효 도착 예정 재고와 실제 AI 월 지원 정책 |
| `Supply.upkeep` | 기존 주둔군 월 군량 계산 공유 |
| `Supply.move_stock/settle` | 내부 도시↔이동 중 출납/종료. 외부 UI는 직접 호출하지 않고 검증된 명령 사용 |

연구의 행군 소비 절감·새 보급 거리 규칙을 구현한 것으로 표현하지 않는다. 이번 logistics 실제 효과는 화물 운송비 할인이다. 기존 전투 병력 캐시의 전체 개편, 해상 운송·호위·중간 약탈 확률·새 도로·새 군수 품목은 추가하지 않았다. 신규 회귀는 최종 검증에서 발견되지 않았다.

실행 환경으로 생략한 요청 검증은 없다. Godot의 기존 Windows root certificate store 경고는 있었고 스크립트 오류 없이 로컬 실행·렌더링을 완료했다. `git diff --check` 통과. `.godot/supply-baseline-*`는 시작 사본, `.godot/supply-results`의 JSON/PNG와 supply-*.log는 이번 실행 산출물이다. Godot 캐시/셰이더/가져오기 자동 생성물은 직접 수정한 소스와 구분해 `.godot`에 남아 있다.
