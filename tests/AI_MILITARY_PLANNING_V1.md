## 계획과 실제 명령

`ai_military_planning.gd`의 `POLICY`는 국고 일반 예비비 300, 준비 편성 상한 1,000명, 내륙 최소 주둔 3,000명, 월 지원 1회 최대 5,000명, 방어 여유 1.1, 현지 군량 3개월을 사용한다. 기존 모집·생산·훈련 가격, 생산 작업량·환산, 인구 한도, 전투 보정, AI 공격 배율은 변경하지 않았다.

- `fronts`: 현재 공격 가능한 인접 상대의 **공통 Army.power**, 장수·성곽 방어 효과와 실제 지원 이동 중 병력을 사용한다. 방어 부족과 기존 AI 출정 배율까지의 부족을 분리한다. 미장비군도 기존 0.8 장비 보정으로 전투력에 기여한다.
- 일반 모집: 군사 부족분, 100명 단위, 공통 모집·인구·3개월 군량·세입/수확 보존 조건, 현물 장비와 훈련 담당자, 모집+훈련 예비비를 확인한다. 준비 편성 하나를 먼저 처리한다. 기존 병력 전부가 훈련 70이 될 때까지 신규 모집을 막지 않는다.
- 긴급 모집: 실제 인접 상대의 공격력이 현재 방어력의 1.1배를 넘고 부족분이 100명 이상일 때만, 부족분과 기존 난이도별 월 목표 중 작은 수를 요청한다. 국가당 첫 우선 방어 도시만 처리한다. 실제 금·인구·현지 군량 제한은 동일하다. 긴급 상황은 일반 예비비를 이유로 마지막 사용 가능한 금까지 봉쇄하지 않는다. 이미 모집된 병력과 지원군을 다음 판단에 반영한다.
- 기존 가용 예비군도 활용한다. 출신·훈련·장비를 유지한 공통 이동을 사용한다. 지원 도시는 최소 주둔 또는 `인접 공격력 × 1.1 / 현재 1인당 실효 방어력` 중 큰 수를 남긴다. 공격 조건과 전투 판정 자체는 기존 함수를 유지한다.
- 기존 군수 거점·유효 담당자는 유지한다. 건설·연구의 서로 다른 가용 인원을 병렬로 배정하고, 중단된 기결제 업무는 `Industry.assign`으로 이어간다. 생산 관리자는 다른 현지 인원 여유가 있을 때만 배정한다.
- 기존 IronAI의 지역 공급/타 도시 철 수송/공통 정련 선택을 재사용한다. 비용·도착 지연·부족 철을 비교하며, 다른 도시 재고나 미래 철을 완성 무기로 취급하지 않는다. 국가당 화물 신규 1개 제한은 군량 지원·철·무기 지원이 공유한다.
- `Army.equip/train`, `Industry.start/assign`, `Supply.start/ai`, `recruit_for_faction`, `queue_province_transfer`, 기존 `resolve_ai_attack`을 실제 월 행동에서 호출한다. 실패한 명령으로 자원을 늘리거나 새 비용을 재지급하지 않는다.

### 전망·배정·월 순서

전망은 창고 칼, 유효한 도착 예정 칼, 현재 철, **조건부 미래 제작량**을 별도로 반환한다. 시설·연구의 남은 작업량과 미접수 선행 작업을 현재 능력의 월 작업량으로 환산한다. 아직 없는 선행 작업은 직렬 합으로 보수적으로 추정하므로 병렬 수행하면 단축된다. 중단/인력 없음은 미확정 사유로 표시한다. 생산 구간은 1,000명분 10배치에 필요한 현재 시설 작업량, 훈련은 기존 50→70의 담당자 증가량, 이동은 현재 실제 경로 구간 수, 다음 달 시작 1개월을 합산한다. 완성 후 일반 전망 범위는 예를 들어 7개월 생산+2개월 훈련+2개월 이동+1개월=12개월이다. 새 연구·시설의 **미납 예상비**와 접수해 이미 낸 비용은 구분한다.

조건부 생산은 가동 명령·재료 공급·현지 유지 군량·국고를 전제로 양쪽 시설 용량과 전체 레시피 비용으로 제한한다. 생산 중지·입력 경로 중단 시 전망은 0으로 되돌아간다. **미래 생산분을 근거로 현재 장비를 무료 지급하거나 일반 모집을 선결제하지 않는다.** 현물과 담당자를 순차 소비하는 한 국가 한 준비 편성으로 중복 배정을 막는다. 재계산할 가상 예약 원장을 영구 저장하지 않는다.

월 순서는 기존 국내 업무→건설·연구→화물 도착→세입/수확→주둔 소비·손실→훈련→전체 국가 생산→기존 이동 도착→AI 계획·명령→기존 공격→계절/필수 사건→안정된 종료 판정을 유지한다. AI 안에서는 긴급 군량 수송→긴급 방어 동원→군수 기반/조달→준비 편성 장비·훈련·전선 이동→나머지 예비군 지원 순으로 실제 원장을 사용한다. 완료 시설은 그 월 생산에 반영되며 새 접수 이동·훈련은 다음 월부터 진행한다.

고구려/백제 실행은 현재 역사 AI 규칙상 플레이어와 공격 가능한 전선이 없다. 그래서 칼 10묶음 예비 재고 이후 조달을 멈추며 일반 모집을 하지 않는다. 이를 '수지 개선을 위해 모든 모집을 중단'한 사례와 섞지 않는다. 나머지 세 AI 사례에서는 실제 신규 모집→장비→훈련→전선 투입 및 기존 실제 공격이 모두 일어났다. 첫 공격은 기존 무장군을 활용할 수 있으므로 신규군 준비보다 빠를 수 있다. 고구려/신라의 19개월 첫 신규 부대 도착은 긴급 모집 500명이며, 표는 1,000명 누적 도달을 별도로 집계했다.

초기 시설·연구 병렬화와 가용 인원 유지의 결과로 이 대표 실행에서는 첫 생산이 모두 12개월이었다. 국가별 시간을 같게 설정한 상수는 없다. 다른 시나리오·인물 배치까지 같은 기간을 보장하지 않는다. 현재 거점은 신라 금성, 백제 사비, 고구려 평양이며 기본 공급은 기존 공통 조달을 사용했다.

보병 1,000명의 직접 초기 원가는 모집 금150/군량200, 칼10묶음의 공통 철 조달·제작 금280, 훈련50→70의 이번 담당자 2개월 금100이다. 신규 시설·연구가 전혀 없다면 건설560+연구400을 더한 금1,490이다. 이미 지은 시설은 다시 결제하지 않는다. 생산 담당자 보너스에도 추가 배치의 금·철 비용은 생략되지 않는다. 기존 부대 훈련, 다른 신규 부대, 수송, 주둔 유지, 전쟁 비용은 이 한 부대의 직접 원가와 별도이며 위 국가 원장에 실제 합계가 남는다.

60개월 누적 칼은 활동 중인 세 AI가 45~50묶음(백제 47)으로, 4,500~5,000명분이다. 기존 대규모 군은 시작 장비로 싸우지만 새 모집/손실 보충은 이 공급 속도에 제약된다. 무관리 기본 시설 1쌍은 연 12묶음=1,200명분이고, 관리 작업량143이라면 무중단 이론 상한은 연17묶음 안팎이다. 실제치는 원료·재고 목표·담당자·배치 대기 때문에 상한보다 낮다. 계수를 바꾸지 않고 이 차이를 드러냈다.

## 정상 패전과 공급망 상실 후 복구

`ai_military_recovery_test.gd`는 위 정상 초기 신라 저장에서 **실제 당항성→황해 공격**을 했다. 전투력15,900/13,230, 신라 손실3,850/고구려 손실7,000으로 실제 승리했다. 전투 능력·승리 규칙·소유권을 조작해 승리를 만들지 않았다. 이후 신라의 추가 군사 명령 없이 90개월을 진행했다.

고구려의 첫 반격은 1개월째이며 기존 병력으로 수행했다. 신규 준비군 첫 500명은 18개월, 신규 준비 1,000명은 24개월, 준비한 신규군 누적 1,000명 전선 도착은 25개월이다. 새 모집군의 복구를 기존 예비군 반격과 구분했다. [최종 90개월 로그](../.godot/ai-recovery-final.log), [월별 회복 자료](../.godot/ai-planning-results/recovery-months.json), [정상 패전 직후 저장](../.godot/ai-planning-results/normal-ai-defeat.json), [최종 저장](../.godot/ai-planning-results/recovery-final.json).

90개월 고구려: 누적 모집20,800, 전투 손실40,433, 현재157,967명. 시작177,600+20,800−40,433=157,967이다. 지급7,000명분, 현재 신규 완전장비·훈련70 병력5,814명이다. 국고는 1,000+144,171−7,446=137,725. 지출은 건설560/연구400/생산2,184/모집3,120/훈련925/수송257이다. 총 손실 전부를 90개월 내 신규 준비군으로 회복한 것은 아니다. 긴급 방어와 추가 점령이 진행되면서 미장비 수요가 공급보다 빠르게 늘었다. 무료 자원이나 강제 훈련도를 넣어 이를 숨기지 않았다.

### 강화 대기 수정 전후

[수정 전 정상 저장](../.godot/ai-planning-results/island-blocked-before.json)의 `unit:60`은 강화에 422명, 장비0, 훈련50으로 남았다. 창고의 칼은 평양에 있었지만 육상 화물 경로는 없었다. 이 한 편성이 국가 준비 순서를 막았다. `ai_military_island_recovery_test.gd`는 같은 저장을 그대로 불러와 다음 월의 실제 거점 복귀 명령을 확인하고 10개월을 진행했다. [수정 후 저장](../.godot/ai-planning-results/island-recovered-after.json)은 같은 ID 422명, 장비500인원분(5묶음, 여분78 보존), 훈련70, 하슬라 배치다. 병력 이동의 기존 해상 연결을 사용했으며 육상 화물에 바다를 허용하지 않았다. [실행 로그](../.godot/ai-island-recovery.log).

## 저장·종료·검증 범위

계획 상태는 기존 strategy_state 안의 `military_planning` 버전1이다. 국가별 처리 월, 거점, 준비 부대 ID, 목적지, 완료 기록, 판단·행동 로그를 저장한다. 별도 재정·인물·병력 장부를 만들지 않았다. 전망은 다음 판단에서 원장으로 재계산한다. 구 저장에 항목이 없으면 첫 AI 월 실행 때 빈 상태를 만든다. 불러오기 자체는 명령이나 이관 보상을 실행하지 않는다. 저장에 있는 기처리 월을 재호출해도 아무 비용·이동·계획 변경을 만들지 않는다. 종료 확인은 `ensure`보다 먼저 수행하며 이전 IronAI의 직접 진입에도 종료 가드를 추가했다.

- 실제 선택 가능한 12조합의 초기 월 진행, 국가별 재정 항등식, 같은 월 재호출, 부대 출신 합계를 검사했다. [조합별 실제 계획](../.godot/ai-planning-results/initial-combinations.json). 지원되지 않는 연도×국가를 새로 만들지 않았다.
- 계획 없는 구 저장, 진행 중 계획 저장의 3회 반복 복원, 종료 후 새 계획/구 IronAI/월 AI 차단, 새 캠페인 초기화가 통과했다.
- **경계 시험**은 금0·군량0·민간 인구0·담당자 활동 불가 상태를 명시적으로 설정해 실행했다. 모집 비용·결과를 생성하지 않으며 공통 원장이 음수가 되지 않았다. 이 상태들은 정상 수지 표에 사용하지 않았다.
- 생산 중지→조건부 전망0, 실제 경로 단절→배치 불가, 거점 점령→이전 소유 생산 재가동 차단/새 아군 거점 선택, 실제 위협→긴급 모집→위협 제거 후 일반 계획 복귀를 별도 경계 시험으로 확인했다.
- 기존 supply_transport 테스트는 유효 도착량, 같은 달 재호출, 원료·군량 부족, 차단/재지정/하역/점령과 유료 AI 화물을 다시 검증했다. 기존 army 테스트는 분할·합류·이동·전투/장비 손실·실제 유료 AI 훈련과 저장 보존을 다시 검증했다.
- 이 작업에서 Army 테스트 1개가 옛 `army.ai_log`를 읽어 처음 실패했다. 실제 훈련 업무는 존재했고 실행도 성공했다. 기대 동작을 줄이지 않고 **새 국가 계획 로그의 성공한 training 명령**을 검사하도록 두 로그 참조를 수정한 뒤 다시 통과했다.

최종 실제 실행 결과: AI 초기/원장/저장/종료224개, 추가 공급·경로·소유권·긴급 전환10개, 정상 회복3개, 강화 정상 복구4개 모두 실패0. 영향을 받는 기존 Army337, 장수161, 모집·인구417, 수송159, 산업155, 국가 경제247, 내정131, 종료56, 종료·필수 사건25도 실패0이다. 개수는 실행 결과이지 완료 목표가 아니다. 중간 실패/스크립트 오류가 있는 로그는 최종 통과 로그와 구분했다.

## GUI와 재현

`tests/ai_military_planning_gui_test.gd`는 실제 Windows GUI에서 기존 Menu→**국가별 AI 군수 계획**을 마우스와 키 입력으로 열었다. 정상 생산/신규 준비/전선 도착/패전 복구 저장을 불러와 실제 국고 수입·지출, 칼 창고·수송·전망, 준비 부대의 인원·장비·훈련과 판단을 표시한다. 닫기 후 지도 입력 복구, 저장 복원 뒤 실제 턴 종료 버튼의 다음 월 진행도 확인한다. 자동 입력 초안에서는 PopupMenu 포커스 도착 전에 Enter를 보내 메뉴가 열리지 않았다. 포커스를 기다린 실제 입력으로 수정했으며 게임 결과나 자원을 변경하는 우회는 사용하지 않았다.

## 변경 파일과 후속 연결

이번 제품 소스 변경은 `ai_military_planning.gd`(신규), `campaign_main.gd`(월 계획·공통 이동 actor/제외 부대·조회 메뉴), `army_readiness.gd`(기존 take 함수의 선택적 제외 ID), `iron_procurement_ai.gd`(직접 진입 종료 가드)다. 기존 부대 자료를 복제하지 않았다. 신규 검증 스크립트는 ai_military_planning_audit/test/constraints/gui, ai_military_recovery_test, ai_military_island_recovery_test이며, 기존 army_readiness_test의 로그 참조 두 곳을 수정했다.

사본·실행 로그·JSON 저장·캡처는 `.godot/ai-planning-*`, `.godot/ai-*` 아래에 있다. 이 중 보고서/검증 스크립트와 기준 사본·결과 데이터는 이번 작업이 작성했고, 엔진 캐시·셰이더·프로필 메타데이터는 Godot 자동 생성물이다. 기존 자산을 수정한 결과가 아니다. Git으로 추적되지 않는 `.godot` 결과도 이번 로컬 완료 증거로 보존했다.

남은 한계와 다음 작업:

1. **여러 군수 거점과 여러 훈련 편성의 공급 배분**: 현재 한 거점·한 준비 편성 정책은 비용 중복과 인력 경쟁을 억제하지만 큰 전쟁의 손실을 전부 빠르게 복구하지 못한다. 90개월 실제 손실40,433 대비 지급7,000은 이 한계를 보여준다. 다음 확장은 도시별 잉여 담당자·유효 경로·미납 투자비·수요를 비교해 제2 거점의 유료 선행 작업과 편성별 공급을 배정해야 한다. 완료 기준은 무료 보정 없이 공급량/손실/미장비 대기가 지속 가능한 추세가 되는지다.
2. **귀족 권력 제약 연결**: 국가 계획은 `Industry.staff_reason`, 공통 인물 ID·직책·업무, 실제 전투 지휘관 함수를 사용한다. 귀족의 인사·지휘 거부/요구를 이 가용성/명령 결과에 연결하고 실패 이유를 계획 로그로 전달할 수 있다. 이번에는 기존 금100 포상, 충성·권력 상수나 새 반란·처형 규칙을 바꾸지 않았다. 영향력 수치만으로 존재하지 않는 군권 상실을 가정하지 않는다.
3. **정상 캠페인 최종 완주와 사용자 경로**: 자동 종료 경계/복원 회귀는 통과했으나 실제 정상 통일 완주 및 호스트 사용자 기본 저장 위치 확인은 남았다. 현재 정상 장기·패전/회복 저장을 이어서 활용할 수 있다.

역사 AI의 플레이어 전용 공격 범위, 해상 화물 미구현, 전장 정보 공개 범위, 강철·전체 병종 성장·전술 전투 미구현은 이번 계획이 완성한 기능으로 평가하지 않는다.

최종 재실행 확인: release-audit의 자원·모집·병력·손실·도시 수가 위 summary.json과 모두 일치했다. 최종 GUI는 [ai-planning-release-gui.log](../.godot/ai-planning-release-gui.log)에 19개 실패0으로 기록된다. 최종 AI 초기/저장 및 조건 검증은 ai-release-ai_military_planning.log, ai-release-ai_military_planning_constraints.log, 부대 회귀는 ai-release-army_readiness.log를 기준으로 한다.
