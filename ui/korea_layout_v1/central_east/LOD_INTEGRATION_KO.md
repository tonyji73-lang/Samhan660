# 확대 지형 연결 기준

## 한 좌표계와 여러 해상도

전체 지도는 승인된 1254×1254 이미지를 유지한다. 확대 시 필요한 구간을 더 높은 픽셀 밀도의 지역 텍스처로 표시한다. 각 지역 텍스처는 동일한 승인 지도 좌표계의 사각형에 붙이며 별도로 위치·회전·비율을 조정하지 않는다.

이번 후보의 정확한 사각형은 `Rect2(512, 544, 264, 176)`이다. 성·선택 영역·경로는 기존 승인 좌표를 계속 사용한다. `WORLD_CITY_MAP_UV`와 캠페인 이동 계산에 이 사각형을 대입하지 않는다.

화면 사각형이 `map_rect`, 지도 기준 크기가 `Vector2(1254, 1254)`라면 다음과 같이 표시 사각형을 얻는다.

```gdscript
var detail_native := Rect2(512.0, 544.0, 264.0, 176.0)
var base_size := Vector2(1254.0, 1254.0)
var detail_screen := Rect2(
    map_rect.position + detail_native.position / base_size * map_rect.size,
    detail_native.size / base_size * map_rect.size
)
```

렌더 순서는 전체 지형 → 정합된 상세 지형 → 영토/경로 → 성과 이름 → 고정 UI로 유지한다. 전체 렌더러를 예전 패키지 코드로 덮어쓰지 않는다. 현재 게임에서 수정·검증한 코드의 지형 그리기 지점에만 연결한다.

## 화질과 전환

화면의 실제 픽셀 수를 기준으로 기존 지형 1px이 몇 px로 늘어났는지 계산한다. Godot 창 배율과 프로젝트 stretch도 포함한다. 명목상 카메라 줌 숫자 하나로 두 해상도에서 같은 화질이 보장된다고 가정하지 않는다.

- 원본보다 작게 보일 때: 전체 지도와 밉맵.
- 원본 픽셀이 약 1.5~2px 이상으로 늘어날 때: 해당 구간의 정합된 상세 텍스처를 점진적으로 표시하도록 시작점을 조정한다.
- 새 상세 텍스처도 1px당 약 1.25px보다 크게 표시해야 한다면 더 높은 밀도의 자산이 필요하다는 품질 진단을 남긴다. 이는 시작 기준이며 실제 화면 비교로 조정한다.

밉맵과 필터는 축소 및 샘플링 품질을 조절하지만 원본에 없는 확대 디테일을 만들지는 않는다. 샤프닝·보간·해상도 숫자 확대만으로 해결했다고 보고하지 않는다.

상세 이미지를 여러 장으로 잘라 두는 것만으로도 해상도가 늘어나지는 않는다. 각 타일 자체에 새로운 세밀한 지형이 있어야 한다.

## 먼저 해결할 정합

이번 상세 후보는 기존 해안과 일부 강줄기가 다르므로 자동 교체하지 않는다. 정합 전에는 원본/후보 비교 모드에서만 연다.

1. 해안의 각 굴곡, 좌측 강 합류점, 하단 강, 동쪽 해안이 잘리는 위치를 같은 좌표로 겹쳐 본다.
2. 주요 물길·해안이 움직이지 않도록 상세 자산을 수정한다. 성 좌표를 옮겨 지형 차이를 숨기지 않는다.
3. 인접 타일을 만들 때 공통 가장자리와 겹침 영역을 먼저 고정한다. 페더링은 작은 색감 차이를 완화하는 용도로 사용하고, 다른 강줄기 두 개를 겹쳐 가리는 용도로 쓰지 않는다.
4. 이후 1280×720·1920×1080에서 확대 전환, 성 선택, 지원 경로와 저장 복원을 실제 게임으로 확인한다.

Godot의 UI 배치는 [Control 공식 문서](https://docs.godotengine.org/en/stable/classes/class_control.html), 텍스처 그리기는 [CanvasItem 공식 문서](https://docs.godotengine.org/en/stable/classes/class_canvasitem.html)를 참고한다.
