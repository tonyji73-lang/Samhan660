# 남부 v3 — 일반 플레이 연결까지 확인

## 이번 목표

사용자가 F5로 632년 신라를 시작해 금성을 확대했을 때 여전히 승인 원본만 보인다. 기존 남부 v2가 개발 검토 화면 전용이고 남부 자동 LOD가 꺼져 있기 때문이다. 이 작업은 검토 연결로 끝내지 말고, 실제 정합을 통과한 범위를 일반 캠페인의 확대 시 표시하는 것까지 수행한다. 실패 영역을 통과로 바꾸는 뜻은 아니다.

## 적용

1. 현재 미커밋 변경과 v2를 보존하고 v3를 별도 폴더에 추가한다. `south_continuous_v3.json`의 PNG 해시를 확인한다. 기존 보정 ZIP 재적용이나 동일 파일 재검증만으로 작업을 끝내지 않는다.
2. 원화는 1346×1168이며 승인 지도 1254×1254의 `[560,740,300,260]`에 대응한다. 기존 후보용 12점 UV를 재사용하지 않는다. 항등 UV와 동일 지도 카메라로 시작한다.
3. 승인 원본 → v3 지형 → 영토/경로 → 성/이름 → UI 순서를 유지한다. v2와 v3를 같은 위치에 중복으로 그리지 않는다. 성 좌표·크기·피벗을 변경하지 않는다.
4. `integration/south_patch_edge.gdshader`는 원본 위의 **별도 지형 CanvasItem**에만 적용한다. 맵 전체/성/UI에 적용하면 안 된다. UV 0..1의 전체 패치를 그릴 때 사용한다. 가장자리 4개 원본 픽셀에서만 alpha를 연결하며 내부는 원화 그대로다. 이 셰이더는 좌표/물길을 보정하지 않는다. 기존 렌더러가 한 CanvasItem에서 모두 그린다면 지형 전용 항목으로 분리하거나 기존 지형 전용 셰이더에 같은 식을 통합한다. 파일을 복사하는 것만으로 연결 완료가 아니다.
5. `assets/open_sea_keep_mask.png`를 셰이더의 같은 이름 파라미터에 연결하고 `use_open_sea_mask=true`로 설정한다. RGB 원화와 달리 이 마스크는 선형 데이터다. 먼 바다의 새 파도 무늬를 빼서 승인 지도의 바다를 공유한다. 해안 가까이 4원본픽셀은 보존하고 바다 쪽 4~12픽셀에서만 연결한다. 강과 세 성 범위는 마스크 255를 확인했다. 이 자료는 색 기반으로 만든 렌더링 마스크이며 영토/육지/경로 판정에 사용하면 안 된다. 바다 마스크가 새 해안의 불일치를 감추는지 원화 비교도 함께 확인한다.
6. 검토에서는 `lod_weight=1`로 실제 표시를 확인한다. 일반 플레이에서는 기존 승인 검사와 카메라의 화면 픽셀 밀도로 계산한 LOD 가중치를 매번 전달한다. 셰이더 기본값 0을 그대로 둔 채 화면이 흐린 것을 원화 문제로 보고하지 않는다. 밉맵·선형 필터를 사용하고 import 크기 제한으로 새 PNG를 축소하지 않는다.

## 지리와 성 바닥 확인

- 대가야 고정 anchor (654,851), 전체 스프라이트 rect [643,836.26,22,22], pivot (0.5,0.67). 문제 범위 [642,848,12,12]와 지류 범위 [635,832,48,43]를 확인한다. v3는 동쪽 지류를 성 위쪽으로 되돌린 후보이며 승인 원본의 분기 개수·합류 순서·폭과 동일하다고 사전 판정하지 않는다.
- 달구벌 (699,814), 금성 (747,825), 두 폭 24.62와 같은 pivot 유지. 세 성의 불투명한 전체 하부를 본다.
- 외곽 x=560/860, y=740/1000을 먼저 edge 폭 0에 준하는 원화 상태와 비교한 뒤 폭4로 확인한다. alpha로 사각 절단을 완화한 사실을 해안·수로 정합 완료로 처리하지 않는다. 폭을 크게 늘려 차이를 숨기지 않는다.

## 일반 플레이 승인·확인

패키지의 `production_ready`, `registration_verified`, `automatic_lod_enabled`는 제작 측에서 게임 실행을 못 했기 때문에 false다. 사용자가 승인한 작업은 실제 검증 후 일반 플레이로 연결하는 것까지다. 모든 flag를 일괄 true로 바꾸지 말고, 기존 승인 데이터 구조를 사용하여 통과 범위를 PNG+셰이더/메시 해시에 묶는다.

전체 패치가 실패해도 달구벌·금성 내륙 등 독립적으로 정합을 확인할 수 있는 범위를 검토하고, 통과한 범위만 기존 구역별 승인 기능으로 활성화한다. 사각형 임의 잘라내기만으로 승인하거나 실패한 대가야/해안을 함께 켜지 않는다. 모든 영역이 실패하면 변경을 보존하고 구체적 미통과 좌표를 보고한다.

개발 검토 인자 없이 F5 → 새 게임 → **632년 신라와 642년 신라** 각각에서 금성·달구벌·대가야 확대/축소를 확인한다. 1280×720 및 1920×1080의 일반 플레이 캡처에 실제 레이어 ID·PNG SHA·승인 범위·LOD weight를 별도 로그로 기록한다. 임시 진단 문구를 플레이 UI에 남기지 않는다.

성 선택·지원 경로·화면 왕복·줌 왕복·새 프로세스 복원은 이 연결에 필요한 범위만 확인한다. 과거 209개 결과를 이번 검증으로 재사용하지 않는다. 제주 자동 LOD, 게임 규칙·사용자 저장·세력 선택 UI를 보존한다.

보고는 '검토에서만 표시', '일반 플레이 자동 표시', '여전히 원본 표시'를 지역별로 구분하고 실제 일반 플레이 캡처를 제시한다. 전 지역 선명도 해결로 보고하지 않는다.
