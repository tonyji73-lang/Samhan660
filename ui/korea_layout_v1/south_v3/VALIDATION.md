# 제작 측 확인 — Godot 실행 검증과 구분

## 확인

- 사용자가 제공한 v2 SHA256 `7689732ac0034ebf482af41a1682f31e7e4697c7dbf473c977e64ab06adc33d8`는 제작 측 보관본과 일치한다. 이번 v3는 별도 자산이며 v2를 덮어쓰지 않았다.
- 1920×1080 원본/v2 비교 4장을 확인했다. 원본 확대는 저해상도 지형, v2 확대는 다른 위치의 지류, 전체 v2는 네 변의 절단과 바다 무늬 차이가 보인다.
- 632년 일반 플레이 금성 화면은 승인 원본과 같은 지형 표현이다. 사용자 실행 보고의 '남부 자동 LOD 꺼짐'과 일치한다. 현재 화면에서 상세 PNG가 활성화되었다고 주장하지 않는다.
- v3 실제 PNG 1346×1168, 동일 지도 범위 [560,740,300,260], 약4.49 텍셀/원본픽셀. 생성 후 해상도 확대/리사이즈 없이 원화를 제공한다. 이미지 생성 도구로 보정했고 프롬프트는 별도 파일에 기록했다.
- 원래 성 PNG, 좌표, 폭, pivot으로 세 성을 정적 합성해 확인했다. 달구벌·금성 공터 유지, 대가야 동쪽 지류가 성 위쪽을 지나며 성 하부의 물 겹침이 줄었다. 이 그림은 실제 Godot 캡처나 전체 성 바닥 마스크 판정이 아니다.
- 별도 프로그램에서 지형 패치 외곽4픽셀의 smoothstep alpha와 먼 바다 표시 마스크를 계산해 원본 위에 렌더링했다. 외곽 모델 비교판에 원본/v3 raw/v3+alpha+원본바다를 같은 좌표로 표시했다. 제작 원화를 변경한 이미지 파일이 아니라 셰이더 식의 정적 검토 출력이다.
- 바다 마스크는 승인 크롭의 색으로 얻은 물 후보 중 오른쪽/아래 경계 연결 성분만 사용했다. 물 후보의 육지 쪽 경계로부터 4픽셀까지 detail 유지, 12픽셀 이후 승인 원본을 표시한다. 대가야 지류 문제 범위와 세 성 스프라이트 범위의 마스크가 모두255(100%유지)임을 확인했다. 색 분류이므로 실제 지리/영토 근거로 사용하지 않는다.
- 셰이더 구현은 Godot 공식 CanvasItem COLOR/UV/alpha 문서에 근거한다. https://docs.godotengine.org/en/stable/tutorials/shaders/shader_reference/canvas_item_shader.html

## 미완료

- 이 환경에는 실제 Godot 프로젝트/실행기가 없으므로 셰이더 엔진 컴파일, D3D12 렌더링, GUI 입력, 일반 플레이 자동 전환과 저장 복원은 실행하지 않았다.
- 지류의 세부 폭·합류점 위치와 해안/섬 픽셀 정합은 별도 확인이 필요하다. 원본과 물길이 완전히 동일하다고 주장하지 않는다.
- alpha/바다 마스크 적용 후에도 북쪽·서쪽 육지의 산릉·숲 묘사 밀도와 색 차이는 남는다. 마스크로 외곽 사각형을 덜 보이게 한 것을 지리 정합 완료로 판정하지 않는다.
- 제작한 PNG·셰이더·마스크의 해시를 확인한 뒤 검증된 영역만 일반 플레이 승인에 등록해야 한다. 파일 추가와 개발 검토 표시만으로 자동 LOD 완료가 아니다.
- 전 지역 선명도, 35개 성 바닥, 영토 마스크9곳, 세계 지도 접합은 완료되지 않았다. 바다 렌더링 마스크는 미할당 영토 마스크의 대체물이 아니다.
- 최대 줌9/12 및 모든 해상도에서 완전 선명하다는 보장은 없다. 실제 텍셀 밀도에 따른 LOD/줌 품질도 게임에서 확인한다.
