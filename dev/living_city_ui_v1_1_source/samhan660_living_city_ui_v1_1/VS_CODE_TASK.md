# VS Code 작업 요청 — Living City UI V1.1

현재 Godot 프로젝트의 Living City UI V1을 이어서 수정해주세요. 사용자의 최종 선택은 1번 ‘살아 있는 도시’입니다. 아래 작업을 실제 게임에 연결하고, 실행 화면을 승인 시안과 비교해 눈에 띄는 차이까지 정리해주세요.

## 0. 현재 상태와 자료 확인

- 현재 프로젝트의 AGENTS.md, 브랜치, 미커밋 변경, 보호 파일을 확인하고 기존 작업을 보존합니다. 별도 지시 없이 새 worktree를 만들거나 stage·commit·push·merge하지 않습니다.
- 현재 내정·인사 화면, 공통 테마, 장수·임명 검증·비용·월 처리·저장 경로를 실제 코드에서 찾습니다. 이 문서에는 확인되지 않은 파일명이나 함수명을 가정하지 않습니다.
- reference의 시안 두 장과 observed의 실제 화면 두 장을 직접 열어 비교합니다. observed의 첫 화면은 지도이며, 농업·상업 명령이 열린 내정 기본 화면은 아직 제공되지 않았습니다.
- 기존 영지 / 인사 진입점, 도시 65%·업무 35% 구성, 채색 도시 전경을 기반으로 진행합니다. 타이틀·세력 선택·승인된 전략 지도와 거점 위치는 이번 변경 범위 밖입니다.
- 이전 완료 보고서의 통과 수는 이번 실행 결과로 재사용하지 않습니다.

## 1. 현재 태수와 선택 후보를 명확히 구분

관찰된 화면은 큰 초상과 후보 선택이 선덕여왕인데, 아래 태수·세입 설명은 김춘추 기준입니다. 먼저 이 정보의 소유자를 구분합니다.

- ‘현재 태수’ 요약에 실제 현직자와 현재 효과를 표시합니다.
- ‘선택 후보’ 영역에는 선택한 장수의 큰 초상·이름·역할·관련 능력을 표시합니다.
- ‘임명 시 변화’에는 기존 공통 계산이 제공하는 임명 전 / 임명 후 / 차이를 같은 기준과 단위로 보여줍니다. 서로 다른 인물의 정보를 같은 효과 카드에 섞지 않습니다.
- 정확한 예상값은 기존의 읽기 전용 계산 경로를 사용합니다. UI 전용 수식, 시안 예시값, 실제 임명 명령을 미리 호출하는 방식으로 예측값을 만들지 않습니다. 예측이 제공되지 않는 항목은 현재 효과와 구분해 알려진 조건을 설명하고, 미연결 항목을 보고합니다.
- 임명 성공 후에는 새 태수·실제 효과·후보 목록·업무 상태를 다시 읽습니다. 취소하면 원래 상태가 유지되어야 합니다.
- 개인 충성, 집단 협력, 집단 영향력은 구분합니다. 영향력 증가를 일괄적으로 유리한 녹색 결과로 표시하지 않습니다.
- 초상 하단의 ‘내정으로’는 보조 탐색으로 정리하고 인물 핵심 정보의 시선을 방해하지 않게 합니다.

## 2. 설명문 잘림과 스크롤 정리

- 초상 바로 아래 설명문이 일부 잘려 보이는 현상을 1280×720에서 재현합니다. ScrollContainer의 시작 위치, 최소 크기, 여백, 레이아웃 갱신 순서와 고정 영역 간 간격을 확인합니다.
- 화면을 처음 열었을 때와 후보를 바꿀 때 설명이 반 줄부터 노출되지 않도록 합니다. 후보 변경 시 스크롤 이동은 사용자의 맥락을 유지하며 필요한 범위에서만 처리합니다.
- 현재 선택, 핵심 효과·가능 여부, 확정 버튼은 빠르게 확인할 수 있게 둡니다. 긴 설명과 추가 후보는 필요한 경우 스크롤합니다.
- 후보가 많거나 이름·직책·불가 사유가 길어도 확정·취소가 겹치거나 화면 밖으로 밀리지 않게 합니다.
- 720p에서 공간이 부족하면 장식과 부가 설명부터 줄이고 본문 글자를 과도하게 작게 만들지 않습니다.

## 3. 장수와 주 행동의 시각적 강조

- 기존 장수 자산 중 현재 인물·연도에 연결된 고해상도 초상 또는 사용 가능한 오버레이를 확인해 재사용합니다. 새 시안 얼굴로 교체하지 않습니다.
- 오른쪽 패널 위쪽에 상반신과 얼굴이 충분히 크게 보이도록 배치합니다. 현재 작은 정사각형 칸의 인상을 줄이고 이름·대표 능력·소속을 명확한 순서로 보여줍니다.
- 비율을 보존하고 얼굴이나 관모가 잘리지 않게 합니다. 작은 후보용 썸네일을 단순 확대하지 않습니다. 사용 가능한 원본 자산이 부족하면 그 한계를 보고합니다.
- ‘임명 확정’은 오른쪽 아래의 붉은 주 버튼으로 강조합니다. 충분한 높이·글자 크기·금색 테두리와 hover / focus / pressed / disabled 상태를 갖춥니다.
- ‘선택 취소’, ‘닫기’는 보조 행동으로 둡니다. ‘태수 해임’은 임명과 구분해 현재 확인 절차를 유지하고 대상 태수를 명시합니다.
- 후보는 이름과 선택 표시를 유지하며 선택된 카드만 금색으로 강조합니다. 실제 후보가 세 명을 넘으면 모두 접근 가능해야 합니다.
- 상하단과 카드의 테두리·아이콘·여백을 공통 테마로 정리합니다. 기존 자산을 우선 사용하고, 별도 질감·장식 자산이 없어 시안과 차이가 남으면 보고서에 구체적으로 남깁니다.

## 4. 군주 후보 노출은 기존 규칙에 맞춰 확인

- 현재 시나리오의 군주인 선덕여왕이 후보로 표시되고 선택되는 근거를 기존 공통 임명 검증과 대조합니다.
- 기존 규칙상 불가능하다면 UI의 후보 필터·비활성 상태·사유를 그 검증 결과와 맞춥니다.
- 기존 규칙상 허용한다면 군주라는 현재 역할과 실제 임명 효과를 명확히 설명합니다. UI 작업만으로 새 금지 규칙을 만들거나 게임 정책을 바꾸지 않습니다.
- 코드에 역할 규칙이 정의되지 않았다면 별도 설계 이슈로 기록하고 나머지 화면 정리는 계속합니다.

## 5. 내정 기본 화면과 담당자 선택 확인

- 같은 정상 캠페인에서 영지 → 농업 또는 상업 명령을 열어 reference/domestic_default.png와 비교합니다.
- 태수 요약 / 업무 탭 / 담당자 / 비용 / 완료 예상 / 실행 가능 여부 / 개발 지시의 순서가 분명해야 합니다.
- 도시의 농경지·시장·공방과 기존 메뉴의 진입 경로를 유지합니다. 그림 위 클릭 위치는 화면 배율에 따라 맞아야 합니다.
- 담당자 선택은 임명과 공통된 초상·후보 표현을 사용하되 직책과 실제 업무의 차이를 유지합니다.
- 진행 업무가 없는 정상 상태를 그대로 표시합니다. 시안처럼 보이게 하려고 가짜 담당자·진척·생산량을 채우지 않습니다. 빈 업무 영역은 간결하게 정리합니다.
- 실제로 가능한 업무를 접수하고 월 완료 뒤 진행 목록·태수·국고·도시 관련 표시가 갱신되는지 확인합니다.
- 기존 비용·능력·기간·충성·협력·영향력·승패 조건을 시안에 맞춰 조정하지 않습니다.

## 6. 실제 화면 비교와 검증

사용자 캡처와 같은 632년 신라·금성의 정상 상태를 우선 기준으로 합니다. 원본 저장이 없으면 현재 코드의 정상 새 캠페인을 사용하고 상태 차이를 기록합니다. 기준 시안은 642년 예시이므로 연도·장수·금액·능력의 차이를 시각 결함으로 판정하지 않습니다.

1. 수정 전에 내정 기본, 담당자 선택, 태수 후보 선택 화면을 캡처합니다.
2. 수정 후 같은 상태·해상도로 세 화면을 다시 캡처합니다. 태수 임명 성공 후 현재 태수·효과가 바뀐 화면도 남깁니다.
3. 1280×720과 1920×1080에서 실제 렌더링을 확인합니다. Godot 에디터 툴바가 포함된 첨부는 비교할 때 게임 영역과 구분합니다. 게임 화면을 왜곡해 시안에 맞추지 않습니다.
4. 승인 시안과 구현 화면을 같은 표시 크기로 나란히 보고 도시/업무 비중, 초상 크기, 글자 위계, 설명문 잘림, 후보 선택, 버튼과 상하단 장식을 항목별로 확인합니다.
5. 이번 범위 안의 눈에 띄는 차이를 수정한 뒤 해당 화면을 다시 확인합니다. 검사 통과 숫자만으로 시각 검수를 완료했다고 판단하지 않습니다.
6. 기존 기능 중 영향받은 범위의 회귀 검증과 정상 접수·월 완료·임명·저장 복원을 실행합니다. 후보 미리보기와 취소가 상태를 바꾸지 않는지, 반복 확정이 중복 처리되지 않는지 확인합니다.
7. 공석·후보 없음·금 부족·업무 충돌 및 닫기·Esc·지도 복귀 후 입력 복구를 확인합니다. 새 UI 동작에 필요한 검증만 추가하고 기존 검증을 재사용합니다.

## 7. 완료 보고

프로젝트 관례에 따라 tests/LIVING_CITY_UI_V1_1.md 또는 동등한 위치에 아래를 기록합니다.

- 실제 수정 파일과 데이터·명령 연결 위치
- 수정 전후 캡처, 승인 시안과의 비교 결과
- 현재 태수 / 선택 후보 / 임명 후 효과가 구분된 사례
- 농업 또는 상업의 접수 → 월 완료 결과
- 군주 후보 노출의 기존 규칙과 처리 결과
- 이번에 실제 실행한 검증과 통과/실패, 미검증 사항
- 남아 있는 시각 차이와 자산 부족

명확한 기능·배치 문제를 해결하고 세 화면의 비교를 마치면 이번 범위를 종료합니다. 조정·외교·전투 화면 전체 개편은 후속 작업입니다.
