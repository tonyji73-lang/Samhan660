# VS Code 작업 지시 — 삼한660 살아 있는 도시 UI v1

아래 요청을 실제 삼한660 프로젝트를 열어 둔 VS Code의 개발 에이전트에게 전달한다. 함께 제공한 reference, assets와 DESIGN_SPEC.md를 읽고 진행한다.

---

사용자가 내정·인사 디자인의 최종 선택을 첫 번째 ‘살아 있는 도시’ 시안으로 변경했다. 이 패키지의 시각 기준을 사용해 현재 Godot 프로젝트의 내정 기본 화면과 태수 임명 흐름부터 구현하라.

## 목표

넓고 입체적인 채색 도시, 오른쪽의 큰 인물 초상과 밝은 업무 패널, 어두운 목재·금속 장식, 붉은 확정 버튼으로 국정 화면의 존재감을 만든다. 도시를 보면서 담당자를 고르고, 비용과 인사의 결과를 이해한 뒤 명령하는 흐름이 실제 기존 게임 상태와 연결되어야 한다.

## 시작 전 확인

1. 현재 프로젝트의 AGENTS.md 등 적용 지침, 현재 브랜치, 미커밋 변경, 보호 대상을 읽어 확인하라. 현재 작업 위치에서 기존 변경을 보존한다. 별도 지시 없이 새 브랜치·worktree를 만들거나 stage·commit·push·merge하지 않는다.
2. 현재 내정·인사 화면의 진입점과 관련 파일을 찾고, 장수 조회·담당자 검증·비용 접수·임명·월 처리·저장 API를 추적하라. 이 패키지가 현재 코드의 함수명을 확인한 문서라고 가정하지 않는다.
3. reference/approved_personnel.png와 reference/domestic_default.png를 실제로 열어 본다. 시안 PNG 전체를 게임 화면으로 붙여 가짜 버튼을 얹는 방식으로 구현하지 않는다.
4. 기존 장수 초상, 목재·금속·종이·아이콘·폰트 자산과 테마를 확인하고 재사용 가능한 것을 먼저 찾는다. 제공한 도시 전경은 assets/seorabeol_city_panorama_concept_v1.png다.
5. 이전 3번 시안을 일부 구현한 상태라면 업무·인사 연결과 무관한 기존 변경을 보존하고 화면 배치·테마·그림을 새 기준에 맞춘다. 게임 로직을 되돌리지 않는다.

## 구현 순서

### 첫째: 공통 화면과 내정 기본 상태

- 현재 프로젝트 구조에 맞춰 재사용 가능한 테마와 도시 내정 화면을 만든다.
- 상단 국가·도시·날짜·국고·도시 군량, 왼쪽 약 65% 도시 그림·진행 업무·도시 현황, 오른쪽 약 35% 명령 영역, 하단 기능 탐색 구조를 반영한다.
- 도시 전경은 불투명 PNG다. 비율을 보존해 도시 영역에 맞추고 중요한 장소가 잘리지 않게 한다. 장소 표시는 그림과 분리된 실제 조작 요소로 둔다.
- 상하단은 어두운 목재·청동 계열, 오른쪽 본문은 크림색 종이, 선택 강조는 금색, 주요 확정은 붉은 버튼으로 구현한다. 전체 화면을 밝은 종이로 채우는 이전 3번 스타일을 적용하지 않는다.
- 상단과 본문은 선택 도시 및 플레이어 국가의 실제 상태를 읽는다. 시안의 8,400, 12,600, 91, +120, +4 등을 게임 값으로 하드코딩하지 않는다.
- 태수 요약과 농업·상업 등 기존 명령을 연결한다. 범위 밖의 기존 기능은 정상적으로 기존 화면으로 접근할 수 있게 한다.

### 둘째: 담당자 선택과 명령 접수

- 실제 장수 후보의 관련 능력, 위치, 현재 업무, 가능 여부를 보여준다.
- 비용·완료 예상·제한은 기존 검증과 계산을 사용한다. 후보를 클릭하는 동작은 미리보기이며 확정 전에는 게임 상태를 바꾸지 않는다.
- 확정은 기존 접수 함수를 호출하고 결과를 다시 읽는다. 중복 입력, 취소, 담당자 충돌, 금 부족과 이미 진행 중인 업무를 처리한다.
- 월 진행 후 완료·정지·재개가 진행 목록과 실제 원장에 함께 반영되게 한다.

### 셋째: 태수 변경·임명

- 같은 도시 문맥에서 오른쪽을 태수 후보 선택 상태로 바꾼다.
- 세 명보다 많은 후보와 후보 없음 상태도 처리한다. 시나리오에 없는 인물이나 임의의 정치집단을 추가하지 않는다.
- 개인 충성, 집단 협력, 영향력을 구분한다. 현재 계산이 제공하는 인사 효과와 제한을 표시한다. 영향력 증가를 무조건 이익으로 색칠하지 않는다.
- 예측 효과를 위해 기존 계산을 복제하지 않는다. 공통 읽기 전용 견적 경로가 있으면 재사용하고, 정확한 예측을 제공할 수 없는 항목은 알려진 설명을 표시한 뒤 보고서에 미연결로 남긴다.
- 임명 성공 후 태수, 업무, 세입·수확 관련 표시, 정치 상태를 실제 데이터로 갱신한다. 비용이나 효과 계수는 UI 시안에 맞춰 바꾸지 않는다.

## 범위 경계

- 타이틀·세력 선택, 승인된 전략 지도, 거점 좌표를 개편하지 않는다.
- 시안의 새 얼굴로 기존 초상을 덮어쓰지 않는다. 기존 인물·연도별 초상 연결을 재사용한다.
- 새로운 반란·혼인·처벌·성장 트리·경제 규칙을 이번 UI 작업에 추가하지 않는다.
- 웹사이트나 독립 HTML 데모가 아니라 현재 Godot 게임에 연결한다.
- 금·자원·병력·인구·능력·정치 계수·승패 조건을 시안에 맞춰 조정하지 않는다.
- 과거 완료 보고서의 검사 수를 이번 실행 결과로 인용하지 않는다.

## 실제 검증

642년 신라 정상 캠페인에서 도시 선택 → 내정 열기 → 담당자 선택 → 개발 접수 → 월 완료 → 화면 갱신을 실행한다. 태수 후보 비교와 임명도 현재 규칙상 가능한 정상 상태에서 실행한다. 저장·복원 후 UI와 실제 값이 일치하는지 확인한다.

담당자 충돌, 금 부족, 공석, 후보 없음, 취소, 반복 확정, Esc, 도시 전환, 반복 열기·닫기와 입력 잠금 복구를 확인한다. 관련 기존 회귀 검증만 필요한 범위에서 실행한다. 환경상 불가능한 확인은 미검증으로 명시한다.

1280×720과 1920×1080에서 잘림·겹침·읽기 어려운 글자·동시에 둘 이상 켜진 탐색 선택 표시를 확인한다. 구현 전·후 캡처, 실제 비용과 결과, 수정 파일, 남은 시각 차이와 한계를 프로젝트 관례에 맞는 보고서에 남긴다.

## 전달할 결과

실제 변경 파일, 기존 기능과의 연결 위치, 정상 플레이에서 확인한 명령 결과, 화면 캡처, 미검증 사항을 간결하게 보고하라. 이번 범위가 완료되면 다음 화면으로 자동 확장하지 않는다.
