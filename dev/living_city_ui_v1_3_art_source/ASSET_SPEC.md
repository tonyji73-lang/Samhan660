# Living City UI V1.3 — 장식 자산 적용표

기준: 사용자 제공 V1.3 계획서와 V1.2 캡처. 승인된 **1번 ‘살아 있는 도시’**의 칠기·청동·붉은 버튼 분위기를 따른다. 실제 게임 코드는 이 패키지에서 변경하지 않았다.

## PNG와 표시 크기

6종은 각각 하나의 실제 RGBA PNG다. 생성 도구의 출력 크기는 계획서의 1배 규격과 다르며 여백도 포함한다. 아래 원본 영역을 읽고 논리 텍스처 크기로 대응시켜 사용한다. 원본 전체를 TextureRect에 바로 넣으면 장식이 너무 작게 보일 수 있다.

원본 PNG는 수정하지 않고 바이트 그대로 전달한다. 좌표는 `[x, y, width, height]`. 알파 8 초과 영역의 경계에 원본 4px 여유를 더했다. 아주 옅은 바깥 잡음만 표시 영역 밖에 남으며, PNG 자체의 알파를 지우거나 문턱값으로 바꾸지 않았다.

| 파일 | 실제 PNG | 사용할 원본 영역 | 용도 |
|---|---:|---|---|
| `lacquer_bar.png` | 1850×850 | [2, 356, 1847, 135] | 상하단 칠기 프레임 |
| `primary_red.png` | 1974×797 | [40, 260, 1894, 250] | 붉은 확정 버튼 |
| `work_panel_frame.png` | 1075×1463 | [29, 48, 1017, 1367] | 업무 패널 테두리 |
| `candidate_frame.png` | 1410×1115 | [25, 85, 1360, 938] | 후보 카드 테두리 |
| `title_divider.png` | 2193×717 | [48, 318, 2095, 61] | 제목 구분선·메뉴 밑줄 |
| `city_heading_frame.png` | 2111×745 | [28, 285, 2055, 174] | 도시 제목 테두리 |

## 표시 프로필

`asset_manifest.json`의 프로필이 적용 기준이다. 논리 텍스처 크기와 실제 노드 크기는 다르다. 특히 담당자 카드는 **192×152 카드 텍스처의 모서리를 고정한 채 648×182까지 9분할로 늘린다.** 먼저 전체 그림을 648×182로 변형하면 문양이 늘어난다.

| 프로필 | 논리 텍스처 | 표시 예 | 9분할 L/R/T/B |
|---|---:|---:|---|
| `top` | 1920×88 | 1920×78 | 64 / 64 / 12 / 12 |
| `bottom` | 1920×88 | 1920×88 | 64 / 64 / 16 / 16 |
| `primary` | 648×72 | 648×72 | 48 / 48 / 16 / 16 |
| `work_panel` | 672×914 | 672×914 | 24 / 24 / 24 / 24 |
| `candidate` | 192×152 | 185×147 | 16 / 16 / 16 / 16 |
| `officer_card` | 192×152 | 648×182 | 16 / 16 / 16 / 16 |
| `nav_border` | 192×152 | 279×64 | 16 / 16 / 16 / 16 |
| `divider` | 648×12 | 648×12 | 40 / 40 / 0 / 0 |
| `nav_underline` | 648×12 | 279×12 | 40 / 40 / 0 / 0 |
| `city_heading` | 1196×84 | 1196×83 | 32 / 32 / 12 / 12 |

계획서 대비 조정: 후보 카드 모서리는 실제 문양을 보존하기 위해 12→16px, 구분선 양끝은 24→40px로 잡았다. 이는 **텍스처 분할 폭**이며 콘텐츠 여백이나 노드 최소 크기를 늘리라는 뜻이 아니다. 업무 패널·제목·버튼의 현재 패딩과 65:35 배치를 그대로 유지한다.

## 연결 방식

- `ui/living_city_v1/assets/ornaments/v1_3/`의 원본과 제목용 폰트만 게임에 추가한다. 예제 코드는 `integration_examples/ornament_resources.gd`에 있으며 프로젝트 Godot 버전에서 실행 검증 후 사용한다.
- `domestic_assignment_overlay.gd`와 Living City 전용 테마에서 연결한다. 다른 화면의 `atlas_theme.gd` 전역 스타일을 바꾸지 않는다.
- 상하단은 현재 검은 면 위에 프레임을 적용한다. 업무·도시·카드 프레임은 기존 크림 면/한지 질감 위의 투명 장식으로 추가한다. 속이 빈 테두리로 현재 배경 스타일 전체를 대체하지 않는다.
- 장식 Control은 `mouse_filter = MOUSE_FILTER_IGNORE`, `focus_mode = FOCUS_NONE`. 전체 사각형에 앵커를 맞추되 Container의 새 형제 항목으로 높이를 차지하지 않게 한다.
- 담당자 카드는 기존 PanelContainer의 면과 콘텐츠 여백을 보존한다. 인사 후보는 기존 VBox 크기를 유지하고 전체 사각형에 테두리를 겹친다.
- 상단 제목/자원과 도시 제목의 글자가 끝 문양과 겹치는지 720p에서 확인한다. 겹칠 때 글자 패딩을 크게 바꾸기 전에 장식 끝 영역의 표시를 줄인다.
- 제목 장식선은 기존 빈 간격이나 구분선 자리를 사용한다. 이미 꽉 찬 제목 행에 새 12px 행을 끼워 넣지 않는다. 공간이 없으면 그 위치에는 적용하지 않고 보고한다.
- 최종본에서는 원본 영역을 캐시된 논리 텍스처로 만들거나 동일한 결과의 전용 리소스로 준비한다. 프레임마다 PNG를 다시 읽거나 ImageTexture를 다시 만들지 않는다.
- PNG는 Lossless, 2D용 선형 필터, repeat 꺼짐을 기준으로 확인한다. 수평 가운데는 stretch를 우선한다. 반복 타일은 실제 이음새가 보이지 않을 때만 쓴다.

## 상태

normal/hover/pressed/hover_pressed/disabled는 **같은 붉은 PNG와 modulate_color**를 사용한다. 개별 상태 PNG 5장이 있는 패키지가 아니다. 계수는 manifest에 있다. disabled는 어두워지고 투명해지는 상태이며 완전 회색 변환은 아니다. Label 색은 별도 테마로 관리한다.

focus는 기존 Godot 2px 크림색 외곽선으로 유지해 상태와 독립적으로 겹쳐 그린다. 네이티브 focus는 장식 이미지가 없어도 반드시 보여야 한다.

후보: 일반 테두리는 밝기 0.65·alpha 0.55, 선택 테두리는 원본 색상. 기존 선택 문구/표시와 선택 버튼의 의미를 유지한다. 메뉴는 기존 면·아이콘·문구를 유지하고 `nav_underline`을 선택 메뉴의 하단 빈 공간에만 붙인다. 금색 면에 묻히면 밑줄을 어둡게 조정하며, 메뉴 의미나 폭을 바꾸지 않는다.

## 서체

- **기본 적용: NanumMyeongjo ExtraBold.** `city_title` 40px, 업무 `title` 36px에만 우선 적용한다. 동적 도시명/업무명을 그대로 쓴다.
- 본문·능력·비용·연월·후보 이름·확정 버튼은 현재 Samhan UI Sans를 유지한다. 전역 폰트 교체는 하지 않는다.
- NanumBrushScript Regular는 비교용 후보로 포함했다. 기본 적용을 요구하지 않는다. 시안 이미지 속 글씨와 정확히 같은 폰트는 아니다.
- 한글/숫자 표본의 글리프 포함을 확인했다. 폰트가 좁거나 클리핑되면 기존 줄 높이와 실제 폰트 메트릭을 먼저 확인한다. 글자 위치를 이미지에 굽지 않는다.
- 원본 파일명과 각 폴더 `OFL.txt`를 함께 유지한다. 출처/버전/해시는 SOURCES.md에 있다.

## 검증 범위

이 패키지에서는 PNG RGBA·투명 중앙·표시 영역·원본 보존, 폰트 표본, HTML 상대경로와 스크립트 구문을 확인했다. 브라우저 실행기는 확보하지 못해 페이지의 실제 렌더링·조작은 미검증이다. 게임 기능, Godot 스크립트 실행, 저장/복원, 내정 회귀도 이곳에서 수행하지 않았다. 사용자 보고의 기존 통과 건수를 이번 작업 결과로 재사용하지 않는다.

PNG는 분리된 단일 자산 원본이다. PSD 같은 편집 레이어 파일은 포함하지 않는다. `PROMPTS.json`에 최종 생성 프롬프트를 기록했다.
