# VS Code 실행 지시 — Living City UI V1.3 장식 적용

현재 `feature/project-foundation-v1` worktree에서 첨부된 `Samhan660_Living_City_UI_V1_3_Art_20260929.zip`의 자산을 적용해라.

1. 기존 `AGENTS.md`, `tests/LIVING_CITY_UI_V1_3_ASSET_PLAN.md`, V1.2 보고서와 현재 diff/보호 파일을 먼저 확인한다. 기존 미커밋 작업을 보존한다. stage/commit/push/merge/reset/clean은 실행하지 않는다.
2. ZIP을 개발 참고 폴더에 풀고 `ASSET_SPEC.md`, `asset_manifest.json`, `index.html`을 읽는다. 게임 리소스는 ZIP의 `ui/living_city_v1/assets/` 하위에서 필요한 파일만 복사한다. 검토용 HTML·reference·예제 코드를 게임 진입점으로 등록하지 않는다.
3. 승인된 1번 ‘살아 있는 도시’와 현재 65:35 배치를 유지한다. Living City 전용 테마 및 `domestic_assignment_overlay.gd`에 상하단 프레임, 붉은 확정 버튼, 업무 패널, 후보 전체 카드, 도시 제목 테두리, 가능한 위치의 구분선을 연결한다. Atlas 전역 테마는 수정하지 않는다.
4. PNG는 여백을 포함한 고해상도 원본이다. manifest의 source_region과 logical_texture_size를 먼저 대응시킨 후 slice_lrtb로 9분할한다. 전체 PNG를 그대로 늘리거나 담당자 카드 문양까지 넓히지 않는다. 예제 GDScript는 실행 미검증 참고 코드이므로 프로젝트 버전에서 파싱/실행 확인 후 필요한 부분을 사용한다. JSON 등을 동적 로드하면 내보내기 포함 여부도 확인한다.
5. 크림 면·한지 질감과 기존 패딩/최소 높이를 보존한다. 투명 프레임은 입력을 가로채지 않는 오버레이로 붙인다. 장식 노드 때문에 ScrollContainer 높이나 버튼 위치가 변하지 않아야 한다.
6. normal/hover/pressed/hover_pressed/disabled/focus 상태를 연결한다. 상태는 PNG 복제가 아니라 색상 보정과 네이티브 포커스 외곽선으로 만든다. 선택 문구를 유지하며 선택/비선택 구분이 색 하나에만 의존하지 않게 한다.
7. 제목은 NanumMyeongjo-ExtraBold를 도시명 40px·업무명 36px에만 우선 적용한다. 본문·능력치·비용·연월·후보 이름·확정 버튼은 기존 폰트로 유지한다. OFL.txt도 포함한다. 이름·수치·제목을 이미지로 바꾸지 않는다.
8. 실제 Godot에서 632년 신라→금성→내정 기본/담당자 후보/태수 임명을 1280×720과 1920×1080에서 확인한다. 상하단 긴 문자열, 후보 목록 스크롤, 불가 사유, 큰 초상, 확정·취소·닫기·Esc·Tab 포커스, 비활성·호버·눌림을 확인한다. 글자와 문양의 겹침은 장식 범위를 조정해 해결한다.
9. 정상 상태에서 담당자 선택→개발 접수→다음 월 완료, 후보 선택→임명 확정/취소를 실행해 기존 동작과 국고 변화가 유지되는지 확인한다. 변경 영향이 있는 기존 UI/내정 회귀만 실행한다. 장식 작업을 위해 새 기능이나 게임 수치를 변경하지 않는다.
10. `tests/LIVING_CITY_UI_V1_3.md`에 변경 파일, 실제 실행한 검사/결과, 미검증 항목, 같은 조건의 V1.2 대비 캡처를 기록한다. 실제 화면 개선과 장식 적용 여부를 구분해 보고한다. 다음 작업 추천과 바로 실행할 VS Code 지시문을 포함한다. 커밋하지 않은 상태로 마무리한다.

완료 기준: 세 화면의 스타일이 통일되고 720p에서도 글자·선택·확정 동작이 유지되어야 한다. PNG만 복사한 상태는 적용 완료가 아니다. 이 단계 검수 후에는 같은 시각 규칙을 생산·건설·연구 화면으로 확장할 범위를 제안한다.
