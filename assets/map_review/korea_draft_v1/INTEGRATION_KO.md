# 실제 소스에 맞춘 적용 기준

이 문서는 부분 지도 소스를 대조한 결과이며 게임 패치가 아니다. source ZIP의 `map_context` 발췌문을 실제 캠페인 코드로 덮어쓰지 않는다.

## 원인

`settlement_map.gd`는 기존 `map_area.gd`의 표시 사각형을 지형·성 지면·선택·경로에 공통으로 쓴다. 새 UI 여백도 부모 변환으로 처리한다. 첨부한 실행 감사에는 1280×720, 1920×1080과 줌 1·3·5에서 37건 실패 0, 최대 변환 오차 약 0.0001221px가 기록되어 있다. 이 실행 검사는 이번 환경에서 재실행하지 않았다.

불투명한 `terrain_c03_r02_coast_fix_v2_1254.png` 한 장을 전체 지도의 UV (0.5,0.5), 크기 (1/6,1/4)에 얹고 있어 서로 다른 해안·색·산줄기가 사각형에서 끊긴다. 색을 바꾸거나 가장자리를 흐리는 것으로 좌표가 다른 해안을 해결할 수 없다.

## 새 원본의 좌표

| 항목 | 값 |
|---|---|
| 논리 세계 | 6144×4096 |
| 새 그림의 논리 범위 | x=2048, y=1024, 너비=2048, 높이=3072 |
| 새 그림의 전체 세계 UV | 원점 (1/3,1/4), 크기 (1/3,3/4) |
| 실제 원본 픽셀 | 1024×1536 |
| 논리 단위당 원본 픽셀 | 0.5 |
| 기존 성의 지면 접점 | 성 이미지의 (0.5,0.67) |

세계 UV `(u,v)`의 새 그림 내부 좌표는 `((u*6144-2048)/2048, (v*4096-1024)/3072)`다. 새 그림 내부 좌표를 캠페인의 기존 UV에 덮어쓰지 않는다.

현재 세계 표시 사각형을 `rect`라고 할 때 새 원본의 표시 범위는 다음과 같다. 이는 위치 계산 예시이며 두 줄만 바꿔 완성되는 패치는 아니다.

```gdscript
terrain.position = rect.position + Vector2(1.0 / 3.0, 0.25) * rect.size
terrain.size = Vector2(1.0 / 3.0, 0.75) * rect.size
```

원본 전체지도 텍스처를 이 세로 그림으로 바로 바꾸면 `MapArea._get_base_map_rect()`가 텍스처 비율을 기준으로 세계를 다시 계산하므로 기존 위치가 깨진다. 논리 세계 사각형과 그림의 범위를 구별해야 한다.

또한 기존 지도 위에 이 그림을 더 큰 사각형으로 올리기만 하면 바깥 테두리에 다시 접합 문제가 생긴다. 한국 전용 미리보기에서는 명확한 범위 안에서 표시하고, 세계 지도 통합은 같은 지형으로 주변 영역까지 제작한 뒤 처리한다. 이 후보로 전체 캠페인 기본 화면을 강제 교체하지 않는다.

## 마스크

기존 2048×1365 RGBA 마스크의 **알파 바이트가 1..35 지역 ID**다. 일반 그림의 투명도로 변환하거나 흐리게 보간하지 않는다. 0은 영토 표시 없음이며 지형의 바다를 뜻하지 않는다. 이번 패키지에는 새 영토 마스크가 없다.

기존 마스크에는 9개 중심이 미할당이고, 새 그림은 해안·강이 달라졌으므로 기존의 나머지 26개 중심 일치도 전체 경계의 정확성을 보증하지 않는다. 영역 제작 원본이 없는 만큼, 새 육지/해안 기준과 지역별 벡터 경계를 별도로 검토한 뒤 ID 마스크를 생성해야 한다. 점 주변의 원형 영역이나 무제한 최근접 영역으로 빈 곳만 메우지 않는다.

## 확대 지형

`data/detail_tile_plan.json`의 여섯 슬롯은 그림 제작 범위다. 기존 관리 단위 35개를 여섯 영지로 바꾸는 의미가 아니다.

상세 그림은 구역마다 논리 1024×1024, 핵심 원본 목표 2048×2048로 제작한다. 이웃 구역과 32 논리 단위씩 겹쳐 확인하려면 작업 원본은 2176×2176이다. 개관·지역·근접 단계의 해안과 성 지면은 같아야 한다. 현재 PNG의 512×512 조각을 2048로 확대해 상세 지형으로 납품하지 않는다.
